# Vibekits 统一产品需求

版本：0.2

状态：Windows/macOS 统一研发基线

更新日期：2026-08-16

## 1. 产品定义

Vibekits 是面向程序员的本地文件与开发工具融合器。用户把文件、文本或目录交给应用后，应用自动识别真实内容，选择最合适的能力，并允许结果直接进入下一项工具。

首要平台是 Windows 与 macOS。共享领域逻辑、模型、格式路由和测试向量；文件关联、回收站、窗口、系统菜单和平台解码器通过适配层实现。Android 不进入当前主线。

产品成功标准不是“工具数量多”，而是：用户用最少操作完成真实任务，任何输入都有结果或明确下一步，不出现空白、伪成功和静默忽略。

## 2. 最高设计原则

优先级从高到低固定如下：

1. **最少操作**：非破坏性主流程从拖入到结果默认不超过一次主动执行；可安全自动执行时直接给结果。
2. **自动选择最佳工具**：先看文件头和内容，再看扩展名；扩展名错误时按真实内容处理并说明。
3. **一个输入，多种后续**：结果页就地提供最常用的下一步，不要求用户保存、切换模块、重新选择同一文件。
4. **简单胜过暴露参数**：默认只显示一个主操作；高级参数折叠，且默认值必须覆盖多数真实场景。
5. **符合主流习惯**：文件、列表、快捷键、确认框和拖放遵循 Windows、macOS 及对应主流应用习惯。
6. **本地、真实、可验证**：核心处理离线运行；不展示尚不能工作的入口；每项能力都用真实夹具闭环。
7. **安全可恢复**：读取优先；覆盖、删除、批量写入先预览；能进回收站/废纸篓时不直接永久删除。

### 2.1 操作预算

| 场景 | 默认操作预算 |
|---|---:|
| 拖入单文件并得到只读结果 | 0～1 次点击 |
| 选择文件并得到只读结果 | 2 次点击以内 |
| 复制或保存结果 | 1 次点击 |
| 把结果交给下一工具 | 1 次点击 |
| 非破坏性高级配置 | 最多再展开 1 层 |
| 删除、覆盖、批量写入 | 允许 1 次清晰确认，不得省略安全复核 |

任何流程超过预算，开发记录必须说明为什么无法自动化，以及如何避免用户重复输入。

## 3. 统一输入与融合路由

所有入口使用同一个内容路由器：窗口拖入、文件选择器、命令行参数、系统“打开方式”、右键/服务菜单和应用内结果转交。

路由顺序：

1. 校验路径、文件身份、可读性和大小；
2. 读取受限文件头并识别 Magic Number/MIME；
3. 结合扩展名、文件名和轻量内容探测得到候选能力；
4. 自动执行唯一且安全的最佳能力；
5. 有多个合理选择时先打开最常用能力，并在结果页提供切换；
6. 无专用解析器时回退到文本或 Hex；任何文件都不得静默丢弃。

### 3.1 默认融合链

| 输入 | 默认结果 | 就地后续动作 |
|---|---|---|
| 文本/源码/配置 | 只读阅读或结构化视图 | 格式化、Diff、编码、哈希、压缩 |
| Markdown | 可读预览 | 源码、复制、导出、压缩 |
| 图片 | 安全预览；OCR 模型可用时准备识别 | OCR、格式转换、压缩、哈希、查看元数据 |
| PDF | 文档预览 | OCR、提取文本/图片、压缩、哈希 |
| 压缩包 | 内容列表与安全摘要 | 解压、测试、哈希、打开包内文件 |
| `.bin`/未知二进制 | Hex、Magic、字符串摘要 | 哈希、解码、解压候选、提取字符串 |
| 音频 | 元数据/波形 | VAD、ASR、格式转换、哈希 |
| 本地模型 | 校验并导入模型仓库 | 运行兼容性测试、查看元数据 |
| 多文件 | 每项独立识别的批次清单 | 批量执行相同能力或逐项切换 |

新增能力必须接入统一路由和结果动作，不能只在深层菜单增加孤立页面。

## 4. 产品模块

保留五个稳定工作区，用户无需理解底层库：

| 模块 | 职责 |
|---|---|
| 压缩 | 识别、查看、测试、解压和创建压缩包 |
| 清理 | 扫描、复核和安全清理真实可再生成内容 |
| 查看 | 文本、结构化、图片、PDF、Web、电子书和二进制只读查看 |
| 工具 | 编码、格式、生成、网络、文件和自动化小工具 |
| 本地智能 | OCR、VAD/ASR、TTS 和后续小型离线模型 |

首页和导航不因工具数量增加而膨胀。工具通过搜索、最近使用、上下文动作和统一路由到达。

## 5. 格式能力合同

文档中“支持格式”必须分别标记：识别、预览/列表、读取/解压、创建/转换、自动测试、平台实测。仅能识别扩展名不得写成“已支持”。

### 5.1 压缩与容器

P0 必须读取/解压：ZIP/ZIPX、7z、RAR（含常见分卷）、TAR、GZ、BZ2、XZ、ZST、TGZ、TBZ/TBZ2、TXZ、TAR.ZST、CAB、ISO。

P1 扩展读取/解包：LZ4、CPIO、AR/DEB、RPM、WIM/ESD、APK/JAR/WAR/EAR、XPI/CRX、APPX/MSIX；macOS 增加 DMG/PKG 的只读检查与安全提取。

创建目标：ZIP、7z、TAR、TAR.GZ、TAR.BZ2、TAR.XZ、TAR.ZST。RAR 创建不作为目标，不破解密码，不伪装修复损坏包。

所有格式共享路径穿越、符号链接逃逸、条目数、展开大小、压缩比、目标空间、冲突策略、取消和临时文件合同。底层可组合 libarchive、7-Zip、系统框架或许可证允许的独立解码器，但 UI 和错误协议保持一致。

### 5.2 图片与图像模式

P0 预览与 OCR 输入：PNG/APNG、JPEG/JFIF、WebP、GIF、BMP/DIB、TIFF、ICO、PNM（PBM/PGM/PPM）、TGA；SVG/SVGZ 继续使用安全矢量查看器。

P1 通过平台或独立解码器支持 HEIF/HEIC、AVIF、JPEG XL、PSD 预览，以及常见相机 RAW 的嵌入预览和元数据。平台缺少解码器时显示可安装组件或转换建议，并保留 Hex/元数据入口。

图像模式必须正确处理并标明：灰度、灰度+Alpha、RGB、RGBA、索引色/调色板、CMYK、8/16 位通道、动画帧、EXIF 方向和 ICC 色彩配置。OCR 前统一转为受控 RGB，不修改源文件；超大像素图先估算内存并降采样。

### 5.3 二进制与未知文件

`.bin` 是正式能力，不是兜底占位。使用 64 位偏移、固定窗口随机读取和跨块搜索，支持 Magic、Hex/ASCII、大小端数值解释、字符串提取和文件哈希。多 GB 文件不得按文件大小分配内存。

未知文件始终保留“文本/Hex/尝试专用解析器”的覆盖入口，用户覆盖选择可在当前会话记忆。

## 6. 开发工具扩展原则

工具来源优先参考高使用量、维护活跃的开源项目，例如 DevToys、CyberChef、IT-Tools 及各领域标准实现。不是整仓复制，而是移植适合本产品的纯算法、测试向量和交互模式。

准入条件：

1. 解决程序员高频、明确的本地问题；
2. 与现有工具不重复，或能显著减少操作；
3. MIT/BSD/Apache 等许可证明确；GPL/AGPL 需单独评审，不直接嵌入；
4. 固定上游提交，保留版权与修改说明；
5. 默认离线，无遥测、广告、账号或隐式上传；
6. 有标准向量、错误向量和真实文件测试；
7. 接入统一搜索、最近使用、拖放和结果动作。

优先工具族：JWT/证书/密钥查看、代码与数据格式化、二维码、图片转换与取色、文件类型/MIME/字符串检查、压缩与哈希清单、Git/Unix/网络诊断、文本和日志处理。具体批次写入实施计划，不以 Star 数替代产品判断。

## 7. 本地智能

模型不随主程序静默下载。精选项必须固定模型名、版本、大小、URL、许可证和 SHA-256，并由用户主动安装。

首个 OCR 目标采用 PP-OCRv6_tiny 检测+识别模型，Windows/macOS 共享 ONNX 预后处理逻辑。操作流程：拖入图片 → 立即预览 → 模型可用时自动准备 OCR → 一次运行得到带坐标和置信度的文本块 → 一键复制/保存/交给格式或文本工具。

OCR、VAD/ASR、TTS 均在后台任务运行，显示加载、预处理、推理、后处理和释放状态；输入和结果不上传、不写日志。取消、损坏模型、错误哈希、非法输入和内存超限必须受控。

## 8. Windows 与 macOS

| 能力 | Windows | macOS |
|---|---|---|
| 文件打开 | 文件关联、右键菜单、WM_COPYDATA 单实例 | UTI/Document Types、Open With、Services、open-file events |
| 拖放 | HDROP | NSDraggingDestination/Flutter drop bridge |
| 安全删除 | Windows Shell 回收站 | `NSWorkspace.recycle`/废纸篓 |
| Web 隔离 | WebView2 | WKWebView |
| 压缩后端 | 7-Zip/libarchive/系统能力 | libarchive/bsdtar/ditto/hdiutil |
| 模型运行时 | Windows x64 CPU | macOS arm64 优先、x64 兼容 |
| 应用目录 | `%LOCALAPPDATA%\\Vibekits` | `~/Library/Application Support/Vibekits` |

领域层不得直接依赖注册表、盘符、反斜杠、Windows Known Folder 或 macOS 沙箱书签；这些能力必须通过平台接口注入。

## 9. 非功能与隐私

- 冷启动优先展示可交互窗口，模型和大型解码器延迟加载。
- 长任务不冻结 UI，显示真实阶段、进度和取消。
- 默认不记录文件正文、图片像素、模型输入、密码、令牌和 HTTP 敏感内容。
- 文件头探测和缩略图有明确读取上限；模型、压缩和图像解码有内存预算。
- 失败保留输入和上次有效结果，错误同时给用户原因与可展开技术细节。
- Windows/macOS 深浅主题、100%～200% 缩放和键盘流程均可完成主任务。

## 10. 研发与完成定义

每项能力按“需求 ID → 失败夹具 → 最小完整实现 → 自动测试 → 平台 Release → 人工体验 → 文档/版本/备份”闭环。

完成必须同时满足：

1. 接入统一路由、搜索或上下文结果动作；
2. 默认流程符合操作预算，主界面只有一个清晰主操作；
3. 正常、失败、取消、资源释放和大输入均有测试；
4. 不把识别后缀、占位 UI 或模拟输出计为支持；
5. Windows 和目标 macOS 架构分别有构建与实机证据；
6. 第三方来源、固定版本、许可证、修改和哈希可追溯；
7. 更新当前状态、开发日志和验收记录；
8. 使用版本号提交到本地 Git，并同步用户指定的云端仓库。

现有 `ARC-*`、`CLN-*`、`DOC-*`、`DEV-*`、`AI-*` 与 `UI-*` 编号继续有效；新增跨模块需求使用 `FUS-*`，图像使用 `IMG-*`，平台使用 `PLT-*`，开源移植使用 `OSS-*`。
