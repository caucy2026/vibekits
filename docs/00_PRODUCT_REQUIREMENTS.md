# Vibekits 统一产品与研发总纲

版本：1.1
状态：唯一最高研发基线
目标平台：Windows 10/11、macOS arm64/x64、Android arm64
更新日期：2026-08-23

> 本文归并截至 2026-08-16 的全部用户要求。若其他需求、界面、计划或状态文档与本文冲突，以本文为准，并在同一开发批次同步修订冲突文档。

## 1. 产品定义

Vibekits 是程序员的本地文件与开发工具融合器。用户把文件、目录、文本、连接信息或系统任务交给应用，应用识别真实内容和意图，自动选择最佳工具，并让结果直接进入下一步。

产品价值不是“工具数量最多”，而是：

- 任意文件拖入后都有可用结果或清楚的下一步，不出现空白页、伪成功或静默忽略。
- 用户以最少操作完成真实工作，同一输入不重复选择、同一连接不重复填写。
- 高频工具形成完整工作流，低频、重复、不可靠和体验差的入口不进入正式界面。
- 清理、模型、网络、远程连接等能力展示可感知价值，同时真实、安全、可取消、可验证。

Windows、macOS 与 Android 共用领域逻辑、格式路由、模型和测试向量；文件关联、回收站/废纸篓、系统菜单、凭据、截图、远程桌面和平台解码器通过适配层实现。Android 进入正式主线，但不能把桌面控件、桌面运行时或桌面工具入口原样搬到手机。

## 2. 最高设计原则

所有新增、移植和重构能力必须遵循 `22_CAPABILITY_INTEGRATION_STANDARD.md`：单一能力清单、智能体自动发现、手工与 Harness 共用领域服务、至少一个真实上下游、默认后台有界及分模块审计。禁止新增只有界面或只有模型适配器的孤立功能。

以下优先级不可颠倒：

1. **体验完美优先**：设计和实现都围绕真实用户任务，不以“已有按钮”判定完成。
2. **极简易用**：首屏只突出当前任务、一个主操作和结果；高级参数按需展开。
3. **自动选择**：拖入文件、目录或粘贴内容后自动判断最佳工具；安全的只读动作直接执行。
4. **符合主流习惯**：采用 Windows、macOS 和对应主流应用的操作模型；不自创需要学习的新手势。
5. **融合而非堆叠**：相关能力合并在一个工作区，结果就地提供下一步；不建立重复孤岛。
6. **高频优先**：保留程序员常用、价值明确、可靠的工具；低频、重复、不完整能力下架或隐藏到命令搜索。
7. **真实可验证**：不把扩展名识别、占位 UI、模拟输出或未跑通的库写成“支持”。
8. **安全可恢复**：读取优先；删除、覆盖、批量写入先预览；密码进入系统安全凭据，不写普通设置或日志。
9. **效率优先**：后台任务不阻塞界面；磁盘密集型任务独立执行并限速，不能显著拖慢其他应用。
10. **每项闭环**：正常、错误、取消、边界、重启恢复、资源释放、Release 构建和人工体验都有证据。

### 2.1 Android 操作基线

- 一级工作区使用 Material 3 底部导航；不在手机顶部横向挤压五个桌面 Tab。系统返回键/返回手势先回到上一个工作区，导航历史为空时才退出 APP。
- 主操作触控区域不小于 48dp；输入框适配软键盘和粘贴；长列表使用惰性构建；后台只保留当前重型工作区。
- 手机端路径必须位于应用 files/cache 沙箱；不能使用可执行文件同级目录、Windows 环境变量或用户不可写的相对路径。
- 桌面专属 Node/DSH、ADB host、串口、系统清理、QEMU、系统代理等能力必须明确标注为“连接桌面节点”或在 Android 隐藏，禁止展示点开必失败的入口。
- Harness API Key 支持键盘粘贴和同局域网二维码输入。二维码只包含短时一次性地址与随机令牌，不包含 Key；网页确认后立即关闭监听并让令牌失效。Key 在 Android 使用 Keystore 加密保存，不写设置、二维码或日志。

### 2.2 操作预算

| 场景 | 默认操作预算 |
|---|---:|
| 拖入单文件得到只读结果 | 0～1 次点击 |
| 选择文件得到只读结果 | 2 次点击以内 |
| 复制、保存或交给下一工具 | 1 次点击 |
| 再次打开历史文档/数据库/远程会话 | 1 次点击 |
| 非破坏性高级配置 | 最多展开 1 层 |
| 删除、覆盖、批量写入 | 1 次清晰确认，且确认内容与实际计划一致 |

超过预算的流程必须在研发记录中说明无法自动化的原因和降低重复输入的方案。

## 3. 界面与信息架构

### 3.1 视觉

- 简洁科技风：深浅双主题、低装饰、清楚层级、克制的青绿色状态强调。
- 信息密度服务于任务，不使用大面积无效留白、营销卡片、彩色功能宫格或多层抽屉。
- 关键数字使用清楚的标签和对齐；状态不只靠颜色表达。
- 1024×700、1280×800、150% 和 200% 缩放下无溢出，键盘可完成主流程。

### 3.2 稳定的五个工作区

| 一级工作区 | 职责 |
|---|---|
| Harness（智能体） | 项目会话、任务对话、模型、工具调用、计划、审批与截图 OCR |
| 压缩 | 识别、查看、测试、解压和创建压缩包 |
| 清理 | 扫描、复核和安全清理真实无用内容 |
| 查看 | 文本、源码、结构化数据、图片、PDF、Web、电子书和二进制 |
| 工具 | 计算、数据库、远程、网络、Git/API、文件和通用转换 |

不因工具数量增加第六个一级入口。工具通过上下文自动路由、统一搜索、最近使用和工作区内模式到达。

### 3.3 工具准入与下架

一个工具只有同时满足下列条件才进入正式列表：高频需求明确；比系统现有路径更省操作；主路径可靠；错误与取消可控；能接入融合路由；有测试；许可证清晰。

以下能力从正式列表移除或不新增：与其他入口重复；只能展示不能完成任务；依赖长期不可用的网络；没有明确输入/输出；参数多于实际价值；无法安全处理用户数据；仅为凑工具数量。

## 4. 统一输入与融合路由

窗口拖入、文件选择、命令行参数、系统打开方式、Windows 右键、macOS Finder/Open With/Services 和应用内结果转交都进入同一个内容路由器。

路由顺序：校验路径和身份 → 有界读取文件头 → Magic/MIME/内容识别 → 结合扩展名和文件名 → 自动执行唯一且安全的最佳能力 → 提供合理次级动作 → 无专用解析器时回退文本或 Hex。

所有拖入项目都必须处理。多文件逐项分类，当前显示最有价值结果，同时保留批次清单；不能因为第一项可打开而丢弃其余项目。

| 输入 | 默认结果 | 就地后续动作 |
|---|---|---|
| 文本/源码/Shell/配置 | 只读查看；需要时编辑 | 查找、格式化、Diff、编码、哈希、压缩 |
| Markdown | 渲染预览 | 源码、复制、保存、压缩 |
| JSON/XML/CSV/数据库 | 结构化视图 | SQL/查询、格式化、导出、哈希 |
| 图片 | 安全预览；模型已安装时准备 OCR | OCR、截图结果、转换、压缩、哈希、元数据 |
| PDF/电子书/Web 文档 | 安全预览 | OCR、文本/图片提取、哈希 |
| 压缩包 | 内容列表与安全摘要 | 测试、解压、哈希、打开包内文件 |
| `.bin`/未知二进制 | Hex、Magic、字符串摘要 | 哈希、解码候选、提取字符串 |
| 音频 | 元数据 | VAD/ASR、哈希、转换 |
| 模型 | 校验并导入 | 兼容性测试、运行、来源和许可证 |
| 目录 | 根据上下文进入文件搜索、清理、重复文件、Git 或批处理 | 结果直接转交下一工具 |

系统只注册真实支持的类型和动作；解码器不可用时不得抢占默认应用。Windows 任意文件右键提供“用 Vibekits 自动处理”，已知类型增加专用动作；macOS 提供对应 Open With/Services。

## 5. Windows/macOS 清理

清理首页按用户任务而不是内部文件类别组织为五个固定入口：**推荐清理、软件缓存、大文件 / 下载、不常用软件、深度清理**。推荐清理只包含可证明可再生且风险为安全的内容；高风险项不能被类别批量全选。不常用软件必须显示判断证据，证据不足时只称“已安装软件”并调用官方卸载器。完整竞品结论、规则数据库和后续索引架构见 `24_CLEANER_COMPETITIVE_ARCHITECTURE.md`。

### 5.1 扫描范围

扫描用户临时文件、系统临时目录、浏览器缓存、应用缓存、日志/崩溃转储、开发工具和 IDE 缓存、包管理器缓存、插件下载缓存、可证明的旧插件、调试临时文件、未完成下载和陈旧安装包建议。

默认不扫描或删除项目源码、项目依赖目录、个人文档、整个下载目录、当前插件版本和无法证明可再生成的内容。高风险内容默认不选，明确显示来源、原因、大小和修改时间。支持白名单。

Windows 清理范围由版本化规则库驱动。每条规则必须包含稳定 ID、路径模板、适用 Windows build、风险级别、默认选择、最小文件年龄、最大扫描深度、文件名包含/排除模式和用户可读说明。已知软件只扫描明确的缓存/日志子目录；自动清理规则禁止仅凭 `.log`、`.tmp` 等后缀整盘删除。另提供后台、可取消的系统盘 `.log` 全量清单：超过保留期的文件均可见，但未知用途日志一律标为高风险且默认不选，只有位于明确缓存/调试目录的旧日志才可自动选择。Downloads、Windows.old、驱动包、Prefetch 和注册表不得进入直接删除规则库。

扫描发现与清理决策必须分层：规则命中不等于允许删除。统一决策引擎依据可重建性、语义、最近使用、软件归属、容量收益和磁盘压力输出“自动安全、建议清理、人工复核、保护不清理”；系统管理、当前 APP 运行数据、用户文件和未知归属为不可被磁盘压力突破的硬门禁。扫描完成默认勾选与智能选择必须复用同一引擎，回收站永不默认勾选。

规则数据库必须与扫描核心解耦并可独立升级。规则只允许声明有界文件扫描和回收站动作，禁止执行脚本或任意命令；未知环境变量、重复 ID、非法风险/类别和缺失影响说明必须被拒绝，单条错误不得阻断内置规则。未来在线规则更新必须签名、校验、原子替换、可回滚且保留离线最后可用版本。

Harness 调试目录作为一等清理来源：`logs`、`screenshots`、`temp` 分别显示真实来源，24 小时内文件视为当前任务数据不进入候选；超过保留期的日志、PNG/JPEG/WebP/BMP 截图和临时文件可清理。扫描不读取日志正文或图片像素。

macOS 使用独立版本化规则库，覆盖系统诊断报告以及 Xcode、Simulator、SwiftPM、Homebrew、CocoaPods、Gradle、Pub、Cargo、Go、npm/Yarn/pnpm、浏览器和常用开发应用的明确缓存/日志目录；不得把工程、模拟器设备数据或用户文档当作缓存。

清理页必须枚举当前终端的全部可用本地/可移动/网络挂载卷，先显示每个磁盘的总量、已用和剩余，默认勾选系统盘，允许多选、全选并逐盘切换结果。所有选中卷都在独立后台线程中递归审计；Windows 系统盘识别 `Windows`、`Program Files`、`ProgramData`、`Users`、恢复/启动目录、系统管理文件和已知日志缓存（包括系统盘根目录 `estlog`）。数据盘普通项目、媒体和用户目录只统计占用并保持保护，只有明确识别的 `Cache`、`Temp`、`Logs` 等可再生内容才显示可清理操作；不得因“不属于标准目录”或仅凭文件后缀自动删除。报告说明每项是谁在用、是否合理、为什么需要复核以及统计是否完整。

清理页的两个入口职责必须明确：`扫描可清理项` 只按安全规则库查找缓存、日志和临时文件，结果用于勾选与清理；`分析全部占用` 只读遍历所选磁盘，回答系统、软件和用户数据分别占多少、统计合计与物理已用为何存在差异。两个入口都不得在用户确认前删除内容。

### 5.2 性能、取消与总结

- Windows 点击程序后先显示轻量原生启动面和 Flutter 导航骨架；工作区、磁盘发现、WebView、Harness 和模型检查必须在首帧以后异步加载。

- 扫描和删除运行在独立后台任务；扫描最多使用两个有界工作 Isolate，UI 始终可操作。
- 磁盘枚举与删除主动让出 I/O，不持续占满磁盘，避免其他应用明显变慢。
- 扫描和清理都能随时取消；取消保留已完成部分并给出准确报告，不伪装回滚。
- 清理前读取系统盘容量，清理后再次读取。
- 完成页必须同时显示：本次清理量、历史累计清理量、累计次数、系统盘总容量、当前可用、当前已用、成功/跳过/失败数。
- 成功清理后自动运行低优先级空间审计；界面展示主要占用，完整 JSON 报告保存全部系统盘根项目、分类、大小、合理性、判断原因、不可读数量和未归类空间。
- 历史累计跨重启保存；每次清理写入本地审计日志，包含时间、真实路径、来源、大小、修改时间、成功/跳过/失败、失败原因和释放空间。界面可查看明细、逐条删除日志；报告不记录文件正文、图片像素、API Key 或模型输入。
- 回收站/废纸篓操作与永久删除必须准确区分；界面不能把仍占用磁盘的回收站内容描述成永久释放。

## 6. 文档、源码与二进制

- Markdown 默认渲染可读预览，源码为次级切换；渲染失败自动回退源码并说明原因。
- 常用编程语言、Shell、配置、日志、Diff 和结构化格式可查看、查找、编辑并原子保存。
- 最近打开文档跨重启保存，侧栏一键清空；路径失效时给出可理解提示，不阻塞其他记录。
- `.bin` 使用 64 位偏移、窗口化读取和跨块搜索，支持 Hex/ASCII、Magic、大小端解释、字符串提取和文件哈希；多 GB 文件不得整体载入内存。
- 未知文件始终保留文本/Hex/尝试专用解析器入口。

## 7. 压缩与图片

### 7.1 压缩

P0 读取/列表/解压目标：ZIP/ZIPX、7z、RAR 及常见分卷、TAR、GZ、BZ2、XZ、ZST、TGZ、TBZ/TBZ2、TXZ、TAR.ZST、CAB、ISO。

P1：LZ4、CPIO、AR/DEB、RPM、WIM/ESD、APK/JAR/WAR/EAR、XPI/CRX、APPX/MSIX；macOS 增加 DMG/PKG 只读检查与安全提取。

创建目标：ZIP、7z、TAR、TAR.GZ、TAR.BZ2、TAR.XZ、TAR.ZST。所有格式共享路径穿越、链接逃逸、条目数、展开大小、压缩比、空间、冲突、取消和临时文件合同。

### 7.2 图片

P0：PNG/APNG、JPEG/JFIF、WebP、GIF、BMP/DIB、TIFF、ICO、PNM、TGA、SVG/SVGZ。P1：HEIF/HEIC、AVIF、JPEG XL、PSD 和常见 RAW 的嵌入预览/元数据。

正确处理灰度、Alpha、RGB/RGBA、索引色、CMYK、8/16 位通道、动画首帧/帧信息、EXIF 方向和 ICC。OCR 前转成受控 RGB，不修改源文件；超大图先估算内存并降采样。

## 8. 程序员工具工作区

工具页只保留以下高频主工作区；微工具由统一搜索和上下文动作提供。

### 8.1 程序员计算器

操作模型对齐 Windows Calculator 的 Programmer 模式：HEX/DEC/OCT/BIN 实时结果并可切换输入进制；QWORD/DWORD/WORD/BYTE；A～F 和无效数字键随进制启停；有符号/无符号解释；AND/OR/XOR/NOT、移位、循环移位、MOD、括号、退格、CE、等号；键盘输入与按钮输入一致。默认不再使用只有表达式框的自定义界面。

### 8.2 数据库管理器

- 本地：SQLite 文件拖入即打开，浏览表/视图、分页数据和有界只读 SQL。
- 远程：优先 PostgreSQL，随后 MySQL/MariaDB；支持主机、端口、数据库、用户名、TLS、对象浏览、分页和 SQL。
- 成功连接自动进入最近记录；下次一键选择，不重复输入连接信息。
- 密码只存 Windows Credential Manager 或 macOS Keychain；普通设置、日志和历史不含密码。
- 写入默认关闭；启用写入时必须明确会话级开关和事务/确认，不把只读查询误标为管理完成。

### 8.3 串口调试

提供一个通用串口终端，遵循常见嵌入式/硬件调试工具的操作顺序：选择端口和波特率后直接打开，高级帧格式按需展开。

- 支持自动枚举和手工输入端口；波特率可编辑，常用值可直接选择；数据位、校验位、停止位和 RTS/CTS、XON/XOFF 流控完整可设。
- 文本与 HEX 收发可切换，文本支持无行尾、CR、LF、CRLF；`Ctrl+Enter` 发送，输入错误保留原文。
- 收发日志带时间和方向，可清空、保存；最近参数和发送历史跨重启复用，但不静默自动打开硬件。
- 端口枚举、打开、读写和关闭由独立 Isolate 持有原生句柄；接收数据聚合后刷新 UI，关闭工作区立即请求释放，设备占用/权限/断开给出可行动错误。
- Windows 和 macOS 使用同一工作区；macOS 声明串口设备权限，最终完成仍需两平台各接真实 USB/串口回环验证。

### 8.4 远程工作台

将 SSH 终端、SFTP 文件传输、端口转发和会话记录融合成一个类似 Xshell/Xftp/Tabby 的轻量工作台：

- 使用系统 OpenSSH 或安全、维护活跃的协议实现，不自行实现密码学。
- 首次主机密钥验证清楚；密码/密钥口令进入系统安全凭据。
- 会话记录、最近主机和常用目录跨重启保存。
- 终端支持复制粘贴、搜索、清屏、取消和多会话标签；SFTP 支持本地/远程双栏、拖放上传下载、冲突确认和进度取消。
- 端口转发显示本地/远程端点、运行状态和停止按钮。
- 远程桌面通过系统 RDP（Windows）或系统屏幕共享/VNC（macOS）启动，保存脱敏会话资料，不嵌入不可靠的自制协议栈。

### 8.5 网络与 GitHub 加速

一个网络工作台融合 DNS、Ping/TCP、路由、端口占用、代理、TLS/HTTPS、GitHub HTTPS/SSH 22/443 诊断和 Git 网络配置检查。

“GitHub 加速”必须安全、透明、可恢复：优先检测并使用用户已有系统代理、SSH 443、Git 代理和可选择的可信镜像；任何 hosts/代理修改都先展示变更、创建备份、支持一键恢复，不安装中间人根证书，不绕过 TLS，不在后台常驻隐蔽代理。参考 FastGithub 的问题域与交互，不直接复制许可证不兼容代码或不安全做法。

### 8.6 ADB 与 Android 设备调试

ADB 作为开发工具页的独立高频工作区，调用用户已安装的 Android SDK Platform-Tools 官方 `adb`，不复制协议实现、不静默下载替换 SDK，也不扫描无关局域网端口。

- 启动时异步检测 `adb` 路径、版本和 server 状态；支持 USB 设备、`adb mdns services` 发现的无线调试服务，以及用户明确输入地址后的配对码配对和连接。配对码、无线调试口令不持久化、不写日志。
- 设备列表明确区分 device/offline/unauthorized，记住最近设备序列号和显示名称但不自动执行命令；多设备时每个 Shell、文件、日志和截图任务必须绑定唯一序列号，禁止隐式选择第一台。
- 单一工作区内提供交互 Shell、文件推送/拉取、Logcat 实时过滤/暂停/导出、截图预览/复制/保存和 APK 安装。长任务显示阶段与进度，可取消并释放 `adb` 子进程；路径和参数使用参数数组，不通过 shell 拼接。
- DeepSeek 智能体可以提出 ADB 动作，但界面必须展示目标设备、完整参数和副作用，由用户逐项“批准一次”；安装 APK、删除文件、重启、端口转发等写操作不得自动批准。代理与手工入口共用设备选择、执行器、脱敏日志和取消能力。

### 8.7 网络代理与轻量虚拟机

- 开发工具以一个“网络与虚拟化”工作区承载两个关联 Tab，不增加两个孤立一级入口。
- 代理采用 Clash Verge 使用的 Mihomo 内核并兼容其 YAML 配置。Windows Release 必须内置固定版本、哈希与许可证，运行时不得下载内核或依赖用户另装 Clash。
- 启动内核、停止内核、检查版本、读取 PID/日志均须提供 Harness 工具。订阅地址和认证信息必须脱敏；系统代理与 TUN 属于系统变更，必须单独明确批准且可恢复，不能随内核启动静默开启。
- 虚拟机采用 QEMU 的 x86_64 最小发布子集，只打包系统模拟器、磁盘工具、必要 DLL 与固件，不携带无关 CPU 架构。支持 qcow2/vhd/vhdx/vmdk/img/raw 与 ISO。
- 虚拟机运行在独立子进程，界面关闭、停止或异常时必须可回收；Harness 可检查、启动和停止，但不能拼接任意 QEMU 参数。
- Windows 先完成真实打包与进程闭环；macOS 需要独立签名、权限和 Apple Silicon/Intel 运行时验收，Windows 结果不得替代。
- Windows 与 macOS 共用领域模型；最终以官方 Platform-Tools 固定版本、真实 USB 设备和真实局域网无线调试设备验收，模拟进程只用于自动测试。

### 8.7 文件与系统效率

- 文件搜索：选择/拖入目录后按名称、扩展名、大小、时间和可选内容搜索；结果可打开、定位、哈希、压缩或批处理；大目录后台索引并可取消。
- 系统截图：首个高频入口为“截图 OCR”，遵循 Windows 区域截图与 macOS `screencapture` 习惯；框选完成后立即预览并自动 OCR，不要求用户再次点击。完整截图保存/标注后续进入独立截图工作区；macOS 权限被拒时给出系统设置入口。
- 保留文件哈希、重复文件、批量重命名和 Git/API 工作区；结果可互相转交。
- 通用编码/格式/JWT/证书/二维码等微工具进入搜索，不用大量同级卡片挤占主工作区。

### 8.8 Harness（智能体）

“Harness（智能体）”是一级导航第 1 项，默认打开任务会话，截图 OCR 为同页辅助入口。OCR 负责本机图片文字识别；模型管理收进次级对话框，不把模型清单、VAD 和下载卡片铺在首屏。首次启动进入 Harness；正常关闭后，下次启动恢复上次一级工作区和 Harness 子页。页面状态使用稳定 ID 持久化，禁止依赖会因重排失效的数字下标。

一级导航和其他工具保留 Vibekits 简洁桌面壳；Harness 工作台不再由 Flutter 仿制。Windows 必须直接嵌入固定版本的 DeepSeek 官方 Harness Web 生产产物，官方 UI 和 Host 共同作为工作区、会话、对话、模型、权限、工具调用树、目标/计划、后台任务、子智能体、用户问题、插件/技能和设置的唯一数据源。Vibekits 只做桌面容器与工具扩展，不改造官方信息架构。精确对齐见 `19_OFFICIAL_HARNESS_WEB_PARITY.md`。

- 只采用 DeepSeek 官方 `deepseek-ai/deepseek-harness` 与官方 npm 包；当前参考并固定 `@deepseek-ai/dsh@0.1.2-rc.1`，升级必须重新跑接口兼容、许可证和 100 次完整退出重启检查；开发者预览阶段必须明确提示接口可能变化。
- Harness 运行时、Node.js、固定依赖、headless profile、默认 DeepSeek provider/model 配置和 Vibekits 工具桥接必须在编译/打包阶段准备并随 Release 发布。用户电脑不需要 Node/npm/npx；运行时禁止下载包、安装依赖或首次初始化 profile。
- 用户首次使用只执行“输入 API Key → 选择模型 → 发送任务”。Key 保存后立即做有界连通性验证；验证成功才能显示“可运行”。任务发送阶段必须直接启动已打包运行时，离线缺件时明确报告安装包损坏，绝不能回退到 `npx --yes` 在线安装。
- 用户先选择允许代理访问的项目目录，再像 Codex 一样在底部输入任务；输出进入有界缓冲并按固定频率刷新，不能按 stdout 分块重绘完整 Markdown；停止使用独立控制通道并终止完整进程树，不依赖繁忙 UI 线程及时处理。
- 模型和 Key 配置必须使用官方 Settings → Models 流程，保存后无需重启即可使用。旧版已写入 Windows Credential Manager/macOS Keychain 的 Key 可作为官方进程环境初值注入；Key 不得进入命令行、项目、调试日志和安装包。
- 代理可能读写文件和执行命令，界面必须建议先提交 Git，并提供“请求批准 / 帮我批准 / 完全访问权限”三档策略；策略选择必须跨重启真实生效，不能只改变界面文字。完全访问仍限定为 APP 注册工具及其参数/目标安全合同，不得静默下载或越出所选项目。
- 正式交互使用官方 `dsh web` profile 及其生产 Web 产物；headless 仅保留为自动协议测试，不能再作为 Windows 用户界面。不得在 Flutter 内重放文本伪造官方会话、审批或推理状态。
- Harness 必须能调用 Vibekits 已有能力，而不是绕过 APP 自行拼接 shell。ADB、串口、SSH/SFTP、数据库、文件、哈希、搜索、压缩、OCR、清理、Git/API 等均注册到同一个版本化工具目录，包含 JSON 参数合同、风险级别、目标摘要、超时/取消合同和结构化返回值。
- 每个正式工具入口必须至少绑定一个可执行 Harness 适配器，并由目录合同测试阻止“只有界面、智能体不可调用”的回归。工具调用日志默认开启，允许按当前模块关闭和重新开启；关闭一个模块不得影响其他模块。审计只记录目标、参数摘要、状态、耗时和有界结果，不记录 API Key、密码、文件正文或图片像素。
- 手工界面与 Harness 调用共用同一领域服务、设备/连接选择、后台执行器、凭据存储和审计结果；禁止为智能体另写一套行为不一致的实现。查询、设备控制、发送数据和写操作是否询问由当前权限预设统一决定；无论权限档位如何，工具注册表、目标锁定、参数校验、超时/取消和审计均不可绕过。
- Harness 数据关系和持久化完全遵循官方 Workspace/Session 模型：工作区可添加、重命名、排序和移除；工作区持有有序的多会话；会话可重命名、排序、Fork 和 Archive。移除工作区不删目录或会话日志，会话进入 `Ungrouped`。Vibekits 不再维护第二套项目/会话 JSON。
- Harness 设置必须提供可持久化的调试目录。默认值为 Vibekits 可执行文件同级 `tmp`，目录内固定分为 `logs`、`screenshots`、`temp`；打开 Harness 页面时即创建，保存设置时再次验证可写性。Harness stdout/stderr、截图与子进程临时文件必须使用该目录，禁止继续散落到系统临时目录；API Key 不得写入调试日志。
- 系统清理必须把 Harness 调试目录作为独立推荐卡片，分别显示运行日志、调试截图、临时文件及总占用；只将 24 小时前的文件计入可清理容量，始终默认不勾选，低磁盘压力和自动恢复目标也不得代替用户选择。
- Harness 启动、就绪、等待批准、工具执行、成功、失败和停止阶段必须写入持久化、脱敏的结构化工作日志；后端 stdout/stderr 与每个工具的目标、参数摘要、状态、耗时和有界结果必须可从界面和只读诊断接口查询，日志故障不得反向中断任务。
- 工具调用生命周期固定为：Harness 提案 → Vibekits 校验 → 必要时用户批准 → 后台执行 → 可取消进度 → 结构化结果返回 Harness。APP 关闭、会话停止或设备断开时必须释放子进程、端口、串口和远程连接。
- 完成验收需要 Windows 与 macOS 分别完成官方包真实启动、地址识别、打开控制台、停止、断网/端口占用/缺运行时失败和进程释放；模拟句柄只能作为自动测试，不能替代实机证据。

#### 8.8.1 RustDesk 远程状态与网页交互

- Harness 统一发布启动、就绪、等待批准、工具执行、成功、失败和停止状态。远程状态只含阶段、工具名和脱敏目标，不包含提示词、模型输出、文件正文、API Key、Token 或密码。
- RustDesk 官方客户端作为本机主机，经自建 `hbbs/hbbr` 与 RustDesk Web Client 查看并操作 Vibekits。`hbbr` 是 RustDesk 会话中继，禁止将其伪装成任意 JSON/WebSocket 网关。
- App 自动发现已安装 RustDesk、通过官方 `--get-id` 读取本机 ID，并仅从 RustDesk 配置读取 rendezvous 地址推导 `/web`；不读取或保存远程控制密码。
- 远程用户操作真实 Vibekits/Harness 界面，工具写入、设备控制和删除操作不因远程连接而绕过原有审批。
- 所有 Harness 工作区、会话和任务必须有独立状态机。RustDesk 已认证远端可订阅脱敏状态快照；状态通过本机安全 IPC 进入 RustDesk Host，再走现有端到端加密 P2P 会话。状态链路失败不得阻塞 Harness 或远控，具体协议见 `38_HARNESS_RUSTDESK_P2P_STATUS_ARCHITECTURE.md`。

### 8.9 跨工具任务链

工具不是菜单入口集合，而是共享同一任务上下文的能力节点。连接、设备、文件、截图、日志和查询结果必须尽量以安全句柄或结构化结果在能力之间传递，禁止要求用户重复输入已经完成验证的信息。

- Harness 请求新的 SSH 目标时打开远程工作台；用户只输入一次密码。SSH 认证成功后同一客户端直接开启 SFTP channel，不重新连接、不再次索要密码。
- Harness 请求截图分析时切换到截图 OCR；用户框选后由内置 PP-OCRv6 tiny 离线识别，坐标、置信度和文本回到原工具调用。
- ADB 设备、串口和远程连接必须绑定明确目标；后续 Shell、文件、日志、截图和分析沿用该目标，切换目标时清楚显示。
- Harness 必须提供通用 `network.download`：流式写入“工具与模型下载目录”，使用临时文件和原子完成，返回绝对路径、大小、SHA-256、HTTP 状态及最终 URL；APK 额外校验 ZIP/APK 签名。标准安装链为“下载 → 校验 → 内置 ADB 连接/安装 → 设备侧验证”，禁止退回任意 shell 下载或系统 ADB。
- 文件、数据库结果、API 响应、串口日志和 OCR 文本统一提供“交给 Harness / 搜索 / Diff / 保存 / 哈希 / 压缩”等适合该结果的下一步，不让用户回到首页重新选工具。
- Diff 必须支持任意两个本地文本/源码文件，而不局限于 Git：自动识别文本编码、显示左右行号和新增/删除统计、忽略空白/大小写、只看差异、复制统一 Diff、保存 `.diff/.patch`；大文件采用明确上限和有界算法，比较不得阻塞 UI。
- 跨工具动作仍遵循权限和审计：密码不作为结果传递；只读句柄不能升级为写权限；每个真实执行器记录自身日志；任务结束或 App 关闭释放连接和后台进程。

精确任务链、当前闭环和缺口见 `20_INTEGRATED_DEVELOPER_WORKFLOWS.md`。

## 9. 本地智能

- PP-OCRv6 tiny 等经过校验的小模型可随应用提供内置安装资源，必须由用户主动点击安装；VAD 运行时可以保留兼容，但当前模型页不暴露低频入口。
- 在线安装保留固定上游、备用源、版本、许可证、大小和 SHA-256；支持超时、重试、取消、临时文件和原子安装。
- 网络不可用时，已内置的精选模型仍能安装和运行；不让核心演示价值依赖单一站点。
- OCR：拖入图片立即预览并自动识别；也可点击“截图识别”，区域截图完成后自动返回坐标、置信度和文本，可复制/保存/转交。
- VAD/ASR/TTS 在后台运行，显示阶段和取消；输入与结果不上传、不写日志。
- Windows 与 macOS 分别验证 ONNX/原生运行时，不用 Windows 结果替代 macOS 实机证据。

## 10. 开源移植与供应链

优先研究高使用量、维护活跃、许可证清楚的开源项目和官方标准，例如 DevToys、CyberChef、IT-Tools、OpenSSH、7-Zip、PaddleOCR、sherpa-onnx。不是整仓复制：优先系统能力和标准库，其次移植纯算法、测试向量与成熟交互。

每个候选必须记录上游地址、固定版本/提交、许可证、解决的问题、重复度、隐私、平台产物、采用/拒绝原因和测试。GPL/AGPL 默认只做交互研究，未经单独评审不嵌入。不得引入遥测、广告、账号、隐式上传和不可审计后台服务。

## 11. 非功能、安全与隐私

- 冷启动先给可交互窗口，模型和大型解码器延迟加载。
- 长任务独立执行，显示真实阶段、进度、取消和资源释放；取消后界面在有限时间内恢复。
- 不记录文件正文、图片像素、模型输入、密码、令牌、私钥和 HTTP 敏感内容。
- 文件头、缩略图、数据库结果、网络响应、解压和模型有明确大小/时间/内存上限。
- 失败保留输入和上次有效结果，显示用户可行动的原因，可展开技术细节。
- 设置、历史和报告使用原子写入；损坏后安全降级，不导致应用无法启动。

## 12. 研发顺序

按用户价值和依赖顺序重新推进：

1. 极简外壳、统一路由和工具页信息架构收敛。

7. SSH/SFTP/终端/转发/远程桌面融合工作台。
8. ADB USB/无线设备、Shell、文件、Logcat、截图与智能体审批融合。
9. 网络管理与安全可恢复的 GitHub 加速。
10. 文件搜索、截图及高频文件工作流。
11. DeepSeek Harness 可选代理入口与 ACP 演进验证。
12. 内置精选模型、可靠下载回退、OCR/VAD/ASR/TTS。
13. 压缩/图片/BIN 格式矩阵补齐，Windows/macOS 平台验收。
14. 安装、签名、公证、升级、许可证清单和双平台发布。

## 13. 完成定义

清理功能不得以 Windows 算法覆盖其他平台。Windows、macOS、Android 必须使用独立目标库、保护目录、容量口径、软件清单和删除语义；可共用的仅为候选合同、有界扫描、后台任务、决策分级、确认、报告和审计。尚未完成原生适配的平台功能必须禁用并说明原因，禁止回退到另一平台实现。详细基线见 `32_CLEANER_PLATFORM_MIGRATION.md`。

每项能力按“需求编号 → 真实失败夹具 → 最小完整实现 → 窄测试 → 模块回归 → 平台 Release → 人工体验 → 文档/版本/备份”闭环。

完成必须同时满足：

1. 默认流程符合操作预算，界面没有重复或无效入口。
2. 接入统一路由、搜索、最近使用或上下文动作。
3. 正常、失败、取消、重启恢复、资源释放和大输入有测试。
4. 真实文件/服务/模型结果通过，不使用模拟结果替代最终验收。
5. Windows 和目标 macOS 架构分别有构建与实机证据；当前平台无法验证时明确标为未完成。
6. 第三方来源、版本、许可证、修改和哈希可追溯。
7. Analyze、全量测试和目标 Release 构建通过。
8. 更新需求总账、当前状态、开发日志、验收和供应链文档。
9. 更新语义版本和构建号，提交并打标签，备份到本地 Git 和用户指定云端仓库。
10. 在 `tool/release_acceptance_manifest.json` 登记真实任务链、自动测试和实机证据；执行机器门禁并保留逐命令退出码、耗时、版本与产物哈希。页面存在、模拟成功或人工改写报告均不算完成。

发布质量门禁和报告格式见 `21_RELEASE_QUALITY_GATE.md`。

现有 `ARC-*`、`CLN-*`、`DOC-*`、`DEV-*`、`AI-*`、`UI-*` 编号继续有效；新增跨模块使用 `FUS-*`，图像使用 `IMG-*`，平台使用 `PLT-*`，开源使用 `OSS-*`，发布使用 `REL-*`。
