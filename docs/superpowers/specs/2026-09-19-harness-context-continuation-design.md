# Harness 上下文整理与继续会话设计

## 目标

为长时间开发任务提供“整理上下文并继续”能力。用户从现有 Harness 会话创建一个干净的新会话；新会话不复制原聊天时间线，但模型能够取得经过整理的任务交接信息，并在信息不足时按需查阅来源会话。新旧会话保持双向来源关系。F1～F12 独立用于按会话位置直接切换当前焦点。

## 用户流程

1. 用户在会话侧栏右键一个非运行中的会话，选择“整理上下文并继续”。
2. VibeKits 要求该会话对应的 Harness 生成结构化交接摘要。摘要包含目标、约束、已完成工作、关键决定、涉及文件与版本、验证结果、未完成项、已知问题和下一步。
3. 摘要成功后，在同一工作区创建一个新的官方 Harness 会话。新会话聊天记录为空，侧栏标题以原会话标题为基础生成，并显示“继续”标记。
4. 新会话顶部显示非聊天消息的来源卡片：“从《来源会话标题》继续”。点击卡片返回来源会话。
5. 用户首次在新会话发送任务时，VibeKits 通过官方会话接口把交接摘要作为隐藏的会话上下文交给执行端；用户可见的消息只显示自己输入的正文。
6. 模型认为摘要不足时，可以调用受控来源查询接口，按关键词或消息位置读取来源会话的有限片段。界面显示一条“已查阅来源会话”的工具活动记录，但不把原聊天批量复制进新会话。
7. 来源会话显示派生会话入口。点击可进入相应继续会话。

## 键盘切换

- `F1`～`F12`：分别切换到当前侧栏会话顺序中的第 1～12 个会话；例如 F3 对应第三个、F4 对应第四个。
- “对应会话”按用户当前看到的侧栏顺序计算；折叠项目中的隐藏会话不参与编号，搜索过滤后按当前可见结果重新编号。
- 切换动作同时选中目标项目和目标会话、显示该会话聊天，并把键盘焦点放入该会话输入框，用户可以立即输入。
- 目标位置不存在、会话正在加载或输入法正在组合文字时不切换，并显示短提示说明原因。
- macOS 如果系统拦截功能键，用户使用系统当前配置对应的实际 F1～F12 键位；应用不申请全局键盘监听权限。
- 快捷键只在 Harness 工作区窗口获得焦点时生效，不覆盖输入框内系统级组合键，也不影响官方 WebView 自己已经处理的带修饰键快捷键。

## 数据模型

新增独立的 `HarnessContinuationRecord`，由 VibeKits 会话存储管理，不修改官方 DeepSeek Harness 数据结构：

- `id`：关系记录 ID。
- `workspace`：规范化工作区路径。
- `sourceSessionId`：来源会话 ID。
- `continuationSessionId`：继续会话 ID。
- `sourceTitleSnapshot`：创建时的来源标题，仅用于来源被删后的说明。
- `summary`：有界结构化交接摘要。
- `sourceMessageCursor`：生成摘要时来源会话的消息位置。
- `createdAt`、`updatedAt`。
- `schemaVersion`：首版固定为 1。

关系记录与聊天记录分开持久化。删除任一会话时不删除另一会话；关系保留为断链记录，界面明确显示“来源会话已删除”或“继续会话已删除”。删除整个工作区时随工作区元数据一起删除关系记录。

摘要有独立字符上限，不保存模型凭据、审批令牌、隐藏系统提示或完整工具原始输出。旧版本没有关系文件时按空集合加载，不迁移或猜测历史关系。

## 官方 Harness 适配边界

不修改、打补丁或替换官方 Harness 前端与推理行为。VibeKits 只使用官方会话创建、消息发送和会话读取接口，并在外层提供来源菜单、来源卡片、快捷键和关系存储。

交接摘要的生成是一次显式 Harness 请求。只有收到结构化完成结果才创建新会话；生成失败、停止或结果无法解析时保留原会话，不创建半成品。

隐藏交接上下文通过 VibeKits Host 的会话适配层附加到新会话首次用户请求。官方历史接口返回用户消息时，必须仍是用户输入原文；如果当前官方接口无法保证这一点，则改为在工作区创建只读交接文件并通过工具句柄读取，不能把摘要伪装成用户消息。

## 来源查询

新增只读工具 `vibekits.harness.source_context`：

- 只能从当前继续会话解析到其直接来源。
- 接受 `query`、`beforeCursor`、`afterCursor` 和有界 `limit`。
- 返回脱敏且有长度限制的用户/Harness消息片段、消息位置和来源标题。
- 不返回凭据、隐藏系统消息、审批令牌或未授权工作区内容。
- 每次调用进入 Harness 工具活动记录，并标记来源会话和读取范围。
- 来源不存在或当前工作区授权不匹配时失败关闭，不跨项目搜索相似标题。

## 界面

- 会话右键菜单新增“整理上下文并继续”。运行中的来源会话不可执行，菜单说明需先等待完成或停止任务。
- 新会话顶部使用紧凑来源卡片，不作为聊天消息参与计数。
- 来源会话侧栏菜单增加“打开继续会话”；存在多个时显示子菜单。
- 会话条目用轻量图标区分来源和继续关系；当前可见的前十二个会话分别显示 F1～F12 提示。
- 整理过程中显示进度，可取消；取消后不创建关系和新会话。
- 会话切换后焦点回到输入框，草稿仍按现有每会话草稿规则保存。

## 错误处理与一致性

- 创建流程顺序为：生成并验证摘要、创建官方会话、原子写入关系记录、切换新会话。关系写入失败时删除刚创建且仍为空的新会话；删除失败则标记为未关联空会话并提示用户。
- 对相同来源重复操作允许创建多个继续会话，每个关系拥有独立 ID。
- F1～F12 只使用当前可见会话顺序，不根据来源关系或标题推断。
- 来源查询时检测关系与工作区授权；来源内容变化不自动重写旧摘要，用户可以从来源再次创建新的继续会话。
- 并发会话、后台运行状态、审批状态和草稿不能在切换时串到另一个会话。

## 测试与验收

1. 数据模型往返、损坏文件、长度限制、旧版本空数据和断链关系测试。
2. 会话右键菜单、整理成功、失败、取消、运行中禁用和多个继续会话测试。
3. 新会话无继承聊天记录，但首次执行能读取摘要并继续任务。
4. 来源查询只读取直接来源、有界返回、跨工作区拒绝和工具活动可见性测试。
5. F1～F12 分别进入第 1～12 个可见会话，跨项目选择、搜索/折叠后的编号、无目标提示和输入法组合期间不触发测试。
6. 切换后草稿、并发运行、审批和停止状态保持会话隔离。
7. 官方 Harness 运行时文件保持逐字节未修改的现有门禁继续通过。
8. macOS 与 Windows Release 界面实测：鼠标右键创建、来源卡片往返、F1～F12、重启后关系恢复和来源删除后的断链提示。

## 非目标

- 不复制完整聊天记录到继续会话。
- 不自动删除或压缩来源会话。
- 不把来源关系同步到未经授权的远程 Harness。
- 不增加全局键盘监听、系统辅助功能权限或后台按键捕获。
- 不修改官方 Harness 的推理展示、队列、审批或模型行为。
