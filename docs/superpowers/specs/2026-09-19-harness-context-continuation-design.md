# Harness 上下文整理与派生会话设计

## 目标

为长时间开发任务提供“派生会话”能力。用户从现有 Harness 会话创建一个干净的派生会话；派生会话不复制原聊天时间线，但模型能够取得经过整理的任务交接信息，并在信息不足时按需查阅来源会话。两者保持双向来源关系。F1～F12 独立用于按会话位置直接切换当前焦点。

## 用户流程

1. 用户在会话侧栏右键一个非运行中的会话，选择“派生会话”。悬停说明为“压缩当前会话上下文并创建派生会话继续开发”。
2. 先创建同一工作区的空白官方会话并切换到该会话，正文显示旋转动画和当前整理阶段。随后 VibeKits 通过官方会话历史流读取有界的用户/助手消息，在本机脱敏并压缩为结构化交接摘要。摘要包含目标、约束、已完成工作、关键决定、涉及文件与版本、验证结果、未完成项、已知问题和下一步；不依赖额外模型请求，因此没有 API Key、模型繁忙或长时间等待造成的失败。
3. 摘要成功后保存到该派生会话的来源关系中，结束动画并聚焦输入框。派生会话聊天记录为空，侧栏标题按“原名称 2、原名称 3……”生成。
4. 派生会话顶部显示非聊天消息的来源卡片：“派生自《来源会话标题》”。点击卡片返回来源会话。
5. 用户首次在派生会话发送任务时，VibeKits 自有扩展通过官方 systemPrompt.context 注册接口按真实会话 ID 提供交接摘要；用户可见的消息只显示自己输入的正文。
6. 模型认为摘要不足时，可以调用受控来源查询接口，按关键词或消息位置读取来源会话的有限片段。界面显示一条“已查阅来源会话”的工具活动记录，但不把原聊天批量复制进派生会话。
7. 来源会话右键菜单始终只显示一个“派生会话”创建入口，不按历史关系重复堆叠同名入口。来源与派生之间的返回通过会话正文内的来源卡片完成。

## 键盘切换

- `F1`～`F12`：分别切换到当前侧栏会话顺序中的第 1～12 个会话；例如 F3 对应第三个、F4 对应第四个。
- “对应会话”按用户当前看到的侧栏顺序计算；折叠项目中的隐藏会话不参与编号，搜索过滤后按当前可见结果重新编号。
- 切换动作同时选中目标项目和目标会话、显示该会话聊天，并把键盘焦点放入该会话输入框，用户可以立即输入。
- 目标位置不存在、会话正在加载或输入法正在组合文字时不切换，并显示短提示说明原因。
- macOS 如果系统拦截功能键，用户使用系统当前配置对应的实际 F1～F12 键位；应用不申请全局键盘监听权限。
- 快捷键只在 Harness 工作区窗口获得焦点时生效，不覆盖输入框内系统级组合键，也不影响官方 WebView 自己已经处理的带修饰键快捷键。

## 数据模型

新增独立的 `HarnessContinuationRecord`，由 VibeKits 会话存储管理，不修改官方 DeepSeek Harness 数据结构：

- `id`：关系记录 ID。
- `workspace`：规范化工作区路径。
- `sourceSessionId`：来源会话 ID。
- `continuationSessionId`：派生会话 ID。
- `sourceTitleSnapshot`：创建时的来源标题，仅用于来源被删后的说明。
- `summary`：有界结构化交接摘要。
- `sourceMessageCursor`：生成摘要时来源会话的消息位置。
- `createdAt`、`updatedAt`。
- `schemaVersion`：首版固定为 1。

关系记录与聊天记录分开持久化。删除任一会话时不删除另一会话；关系保留为断链记录，界面明确显示“来源会话已删除”或“派生会话已删除”。删除整个工作区时随工作区元数据一起删除关系记录。

摘要有独立字符上限，不保存模型凭据、审批令牌、隐藏系统提示或完整工具原始输出。旧版本没有关系文件时按空集合加载，不迁移或猜测历史关系。

## 官方 Harness 适配边界

不修改、打补丁或替换官方 Harness 前端与推理行为。VibeKits 只使用官方会话创建、消息发送和会话读取接口，并在外层提供来源菜单、来源卡片、快捷键和关系存储。

官方归档能力保持原样：归档入口仍为会话菜单中的“归档会话”；查询与恢复入口为“设置 → 已归档会话”，官方页面提供搜索和“取消归档”。VibeKits 不在“视图选项”或其他位置重复注入归档入口，也不把永久删除伪装成官方归档功能。

交接摘要由官方 Harness 模型根据来源会话快照生成。先创建空白派生会话并展示整理状态；VibeKits 使用一个不加入侧栏的临时官方会话生成九段结构化交接，完成后立即删除临时会话。读取、脱敏、语义整理和结构校验成功后才允许使用交接摘要。来源会话和派生会话都不写入这段整理对话；失败在派生会话内显示原因和重试，重试复用同一个派生会话。

交接上下文通过 VibeKits 自有 provider 进入官方上下文组装器，仅匹配派生会话真实 ID 与所属工作区，重启后仍可读取持久化摘要。官方历史接口返回用户消息时，必须仍是用户输入原文；如果当前官方接口无法保证这一点，则改为在工作区创建只读交接文件并通过工具句柄读取，不能把摘要伪装成用户消息。

## 来源查询

新增只读工具 `vibekits.harness.source_context`：

- 只能从当前派生会话解析到其直接来源。
- 接受 `query`、`beforeCursor`、`afterCursor` 和有界 `limit`。
- 返回脱敏且有长度限制的用户/Harness消息片段、消息位置和来源标题。
- 不返回凭据、隐藏系统消息、审批令牌或未授权工作区内容。
- 每次调用进入 Harness 工具活动记录，并标记来源会话和读取范围。
- 来源不存在或当前工作区授权不匹配时失败关闭，不跨项目搜索相似标题。

## 界面

- 会话右键菜单新增“派生会话”，悬停说明其会压缩上下文并继续开发。运行中的来源会话不可执行，菜单说明需先等待完成或停止任务。
- 官方 Harness 操作保持官方颜色；VibeKits 自己增加的 Harness 操作（“派生会话”、来源入口、来源卡片、进度和重试）复用官方字号、间距、图标与交互，以官方文字色为基础只混入少量暖黄色，不能成为独立按钮样式。
- 点击“派生会话”后必须立即显示旋转进度动画，并随阶段更新“读取来源会话 / 压缩来源上下文 / 创建空白派生会话 / 保存来源关系”；整理期间始终在来源会话和派生会话内展示，完成后聚焦输入框。
- 派生会话顶部使用紧凑来源卡片，不作为聊天消息参与计数。
- 来源会话侧栏菜单只增加一个“派生会话”创建入口；历史派生关系不得生成多个同名菜单项。
- 会话条目用轻量图标区分来源和继续关系；当前可见的前十二个会话分别显示 F1～F12 提示。
- 整理过程中在来源会话和派生会话正文显示进度；失败保留原会话和已创建的空白派生会话，提供重试。
- 会话切换后焦点回到输入框，草稿仍按现有每会话草稿规则保存。

## 错误处理与一致性

- 创建流程顺序为：创建官方空白派生会话、验证已切换到派生会话、生成并验证摘要、原子写入关系记录、结束动画。关系写入失败时在同一派生会话显示错误，重试复用该会话。不得仅凭后台创建成功宣告整个交互成功。
- 对相同来源重复操作允许创建多个派生会话，每个关系拥有独立 ID。
- F1～F12 只使用当前可见会话顺序，不根据来源关系或标题推断。
- 来源查询时检测关系与工作区授权；来源内容变化不自动重写旧摘要，用户可以从来源再次创建新的派生会话。
- 并发会话、后台运行状态、审批状态和草稿不能在切换时串到另一个会话。

## 测试与验收

1. 数据模型往返、损坏文件、长度限制、旧版本空数据和断链关系测试。
2. 会话右键菜单、整理成功、失败、取消、运行中禁用和多个派生会话测试。
3. 派生会话无继承聊天记录，但首次执行能读取摘要并继续任务。
4. 来源查询只读取直接来源、有界返回、跨工作区拒绝和工具活动可见性测试。
5. F1～F12 分别进入第 1～12 个可见会话，跨项目选择、搜索/折叠后的编号、无目标提示和输入法组合期间不触发测试。
6. 切换后草稿、并发运行、审批和停止状态保持会话隔离。
7. 官方 Harness 运行时文件保持逐字节未修改的现有门禁继续通过。
8. macOS 与 Windows Release 界面实测：鼠标右键创建、来源卡片往返、F1～F12、重启后关系恢复和来源删除后的断链提示。

## 非目标

- 不复制完整聊天记录到派生会话。
- 不自动删除或压缩来源会话。
- 不把来源关系同步到未经授权的远程 Harness。
- 不增加全局键盘监听、系统辅助功能权限或后台按键捕获。
- 不修改官方 Harness 的推理展示、队列、审批或模型行为。

## macOS 后台助手身份

中继助手位于 Contents/Helpers/VibeKitsHarnessRelay.app，使用独立 bundle ID 与 LSBackgroundOnly，不占用主程序窗口身份和 Dock 图标。主程序保持单实例；测试工具必须能在助手运行时准确读取主窗口。
# 交互硬约束（2026-09-20）

- 入口和关联菜单统一只显示“派生会话”，禁止使用“新会话”“打开”“继续会话”等名称。
- 派生会话按“原名称 2、原名称 3……”命名，使用官方会话创建与重命名接口持久化。
- 上下文只在创建时整理，并在派生会话首次模型请求中注入一次；首次助手回复成功后标记为已消费，后续不再注入，也不复制原聊天时间线。
- 等待、失败、重试和超时只能出现在来源会话和派生会话正文内。切换到第三个会话必须隐藏；禁止使用 APP 底部黑色 SnackBar 或其他全局等待提示。
- 所有 VibeKits 新增的 Harness 菜单项、来源入口、来源卡片、进度和重试文字复用官方布局，只在官方文字色和悬停背景中混入少量暖黄色；不得使用纯黄、纯蓝或独立突兀的按钮样式。
- 等待必须有总超时和可恢复失败状态，任何异常都不得无限旋转或阻塞其他会话。
