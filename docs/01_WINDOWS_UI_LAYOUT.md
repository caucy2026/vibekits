# Vibekits Windows V1 界面布局与交互规格

> 本文件是 Windows 视觉与控件附件。跨平台信息架构、极简操作预算和融合路由以 [统一产品需求](00_PRODUCT_REQUIREMENTS.md) 为准；Windows 与 macOS 共用七个一级模块，第六项为应用中心、第七项为关于我们。

版本：0.3
状态：Windows V1 UI 开发基线
验收对象：当前 Windows x64 电脑上的 Release 构建

## 1. 设计方向

界面采用简洁的本地科技工具台风格：深浅双主题、青绿色状态强调、低装饰的信息层级。宽窗口使用左侧工作台导航，紧凑窗口自动切换为顶部五模块导航；主体区域始终围绕当前任务展开。

### 1.1 视觉变量

| 用途 | 值 |
|---|---|
| 浅色应用背景 | `#F3F7F9` |
| 浅色主面板 | `#FFFFFF` |
| 深色应用背景 | `#071119` |
| 深色主面板 | `#11212C` |
| 浅色主文字 | `#16232D` |
| 深色主文字 | `#E7F0F3` |
| 主操作 | 浅色 `#0A9F9A` / 深色 `#35D1C8` |
| 信息色 | `#2788E8` |
| 警告色 | `#E09A32` |
| 危险色 | `#D85B57` |
| 圆角 | 面板 `12px`，按钮 `9px` |
| 字体 | `Microsoft YaHei UI`，数字/代码 `Cascadia Mono` |

不使用营销式 Hero、装饰性大卡片或无含义的霓虹效果。轻微阴影和光晕只用于区分主工作区，颜色只表达层级和状态。

每个工作区默认只显示一个主操作。文件拖入后直接进入结果或准备状态；高级参数折叠，常用后续动作紧邻结果。不能为了展示工具数量增加卡片墙、二级首页或重复选择文件步骤。

## 2. 主窗口

默认尺寸 `1280×800`，最小尺寸 `1024×700`，支持最大化。宽度大于等于 `1180px` 时使用侧边工作台：

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Vibekits │ 当前模块与说明                      本地运行   任务 0   设置   │ 76
│          ├───────────────────────────────────────────────────────────────┤
│ 工作台   │                                                               │
│ 解压缩   │                       当前模块内容                            │
│ 清理     │                                                               │
│ 文档     ├───────────────────────────────────────────────────────────────┤
│ 工具/关于│ 系统就绪                                      CPU / 内存      │ 28
└──────────────────────────────────────────────────────────────────────────┘
```

宽度小于 `1180px` 时，品牌与全局操作压缩到 60px 顶栏，七个模块改为 58px 横向导航；较窄宽度只显示图标，避免文字挤压。两种导航共享选择状态、快捷键与页面实例，不会因切换布局中断任务。

### 2.1 顶栏

- 左侧：应用图标、`Vibekits` 名称。
- 中右：后台任务数量、本地/联网状态。
- 右侧：设置图标和标准 Windows 窗口按钮。
- 设置按钮使用齿轮图标，悬停提示“设置”。

### 2.2 Tab 导航

每个 Tab 使用图标加文字，宽度平均分配，不因文字或状态变化移动。选中项使用底部 3px 主色指示线。

快捷键：`Ctrl+1` 到 `Ctrl+7` 切换；`Ctrl+,` 打开设置；`Esc` 取消当前可取消操作或关闭弹层。

### 2.3 全局状态栏

- 左侧：当前提示或最近完成动作。
- 中部：当前进程 CPU 与内存，不显示虚假的“优化分数”。
- 右侧：版本、后台任务简要进度。

```text

│ 打开压缩包                      │ 文件名  原始大小  压缩大小  类型  时间 │

│                                 │                                        │
│ 最近压缩包                      │          压缩包目录虚拟列表            │
│  project.zip                    │                                        │
│  assets.7z                      │                                        │
│                                 ├────────────────────────────────────────┤
│ 格式能力                        │ 12 项 / 84.2 MB      [选择解压] [解压] │
└─────────────────────────────────┴────────────────────────────────────────┘
```

状态：

- 空状态：主区域提供“打开压缩包”和拖放目标。
- 读取状态：列表保留骨架，顶端展示真实文件名和读取进度。
- 已打开：显示目录树、面包屑、排序、选择和安全摘要。
- 解压中：底部操作栏变为当前文件、总进度、速度、取消。
- 失败：保留压缩包上下文，显示具体失败条目和原因。

创建压缩包使用右侧抽屉，不跳离当前 Tab。密码输入带显示/隐藏按钮，不记录密码。

└────────────────────────┴───────────────────────────────────┴────────────┘

- 左栏可折叠，最近文件只保存路径和元数据。

- 大文件加载首先显示首屏，不等待全文索引完成；索引进度位于工具条，不遮挡已显示内容。
- HTML/EPUB/SVG 顶部常驻“隔离只读”状态，外部链接必须弹出确认。

- 左栏显示模型状态：未安装、下载中、可用、校验失败、已加载。

- 工作区按 OCR、ASR、TTS 切换输入控件，但保持相同的运行/取消位置。
- “释放模型”后显示释放前后内存变化，不承诺清理其他进程内存。

## 8. 对话框和通知

- 普通成功使用底部状态或轻量通知，不弹阻塞框。
- 删除、覆盖、永久删除、打开外部链接使用模态确认。
- 错误对话框包含摘要、详细信息折叠区、重试/取消或打开日志操作。
- 所有对话框默认焦点不得落在危险操作上。

## 10. 全局交互规则

### 10.1 页面状态

每个 Tab 必须显式实现以下状态，不允许用同一个无限转圈替代：

| 状态 | 页面行为 | 主操作 |
|---|---|---|
| 初始/空 | 说明当前可执行动作，提供一个清晰主按钮 | 可用 |
| 准备中 | 校验输入、创建任务，不清空已有结果 | 暂时禁用 |
| 运行中 | 保留上下文，显示真实进度或“不确定” | 变为取消 |
| 取消中 | 显示正在停止，不接受重复取消 | 禁用 |
| 成功 | 显示实际结果、耗时和后续动作 | 恢复 |
| 部分成功 | 分开显示成功、跳过、失败 | 恢复，可重试失败项 |
| 失败 | 保留输入，显示原因和下一步 | 恢复，可重试 |

进度已知时显示百分比、已处理量和总量；总量未知时只显示当前项目与已处理量，不伪造百分比。

### 10.2 控件状态

- 主按钮每个工作区最多一个，使用主操作色；危险操作只使用危险色，不与主操作混用。
- 图标按钮必须具有 Tooltip 和可访问名称。
- 禁用控件保留可读标签，并能通过邻近说明解释禁用原因。
- 表格支持单行选择、`Ctrl+A`、`Shift` 连选、方向键移动和列标题排序。
- 列表、树和表格在刷新后尽量保留选择、滚动位置和展开状态。
- 空输入不得启动任务；输入不合法时错误紧邻对应字段，不弹全局错误框。
- 文件路径显示中间省略，悬停显示完整路径；复制时复制完整路径。
- 数值统一使用 IEC 容量单位（KiB、MiB、GiB），速度使用 `/s`，时间同时给出本地时间和相对时间。

### 10.3 焦点与键盘

焦点顺序固定为：主导航 → 当前页左栏 → 当前页工具栏 → 内容 → 右栏 → 底部操作。隐藏或折叠控件不进入焦点链。

| 快捷键 | 动作 |
|---|---|
| `Ctrl+1`～`Ctrl+5` | 切换一级 Tab |
| `Ctrl+O` | 当前模块的“打开文件/压缩包” |
| `Ctrl+F` | 聚焦当前内容搜索 |
| `Ctrl+,` | 打开设置 |
| `F6` / `Shift+F6` | 在页面主要区域间循环焦点 |
| `Enter` | 执行当前默认非危险操作 |
| `Esc` | 先关闭弹层，再取消可取消任务，不直接退出应用 |

危险确认框的默认焦点必须位于“取消”；按 `Enter` 不得因焦点初始化错误直接永久删除或覆盖。

### 10.4 可访问性

- 正文和背景对比度至少 4.5:1，大号文字和非文字控件至少 3:1。
- 状态不能只靠颜色表达，同时使用图标或文字。
- Windows 文本缩放 200% 时主流程仍可完成。
- 屏幕阅读器按“控件名称、类型、状态、值”读出关键控件。
- 动画遵循 Windows“显示动画”设置；关闭动画后不影响进度和状态变化。
- 所有点击目标最小 `32×32` 逻辑像素，主工具栏目标不小于 `40×40`。

## 12. T1 解压缩控件与流程

### 12.1 控件

| 区域 | 控件 | 默认/启用条件 |
|---|---|---|
| 左栏 | 打开压缩包 | 始终可用；支持拖放一个压缩包 |
| 左栏 | 创建压缩包 | 始终可用；打开右侧抽屉 |
| 左栏 | 最近压缩包 | 不超过 10 条；失效路径显示“文件不存在” |
| 顶部 | 路径面包屑 | 压缩包打开后可用；只在包内导航 |
| 顶部 | 搜索与排序 | 条目枚举完成后可用 |
| 内容 | 条目树/表格 | 虚拟滚动；目录可展开；文件可多选 |
| 底部 | 选择摘要 | 显示条目数与预计展开大小 |
| 底部 | 选择解压 | 有已打开压缩包时可用 |
| 底部 | 解压 | 已选择条目且目标有效时可用 |

### 12.2 关键交互

1. 打开压缩包后先校验格式和安全摘要，再显示条目。
2. 拖入多个文件时不自动选择第一个，提示“一次打开一个压缩包”。
3. 加密包先完成能完成的目录读取；真正需要密码时才请求密码。
4. 冲突策略在第一次冲突时出现，可应用到剩余冲突；选择“自动重命名”要实时展示新名称。
5. 创建抽屉依次包含来源、格式、压缩级别、输出路径、可选密码和创建按钮。
6. 取消后结果页明确列出已完成、已回滚和无法回滚的文件。

UI 验收：

- `UI-T1-01`：空状态、拖放状态和非法多文件拖放提示正确。
- `UI-T1-02`：10 万条目下列表滚动时行高、选择和表头不跳动。
- `UI-T1-03`：解压进度、取消中、部分成功和失败状态均可区分。
- `UI-T1-04`：四种冲突策略不会因默认焦点造成意外覆盖。
- `UI-T1-05`：1024×700 下“解压”按钮和选择摘要始终可见。

## 13. T2 Windows 清理控件与流程

### 13.1 控件

| 区域 | 控件 | 默认/启用条件 |
|---|---|---|
| 左栏 | 快速/完整/自定义 | 默认快速扫描；扫描中锁定 |
| 左栏 | 范围说明 | 逐项说明将扫描什么，不使用“深度优化”等模糊文字 |
| 左栏 | 白名单 | 可添加文件夹；规范化后去重 |
| 内容 | 风险筛选 | 全部、安全、需确认、高风险建议 |
| 内容 | 分类树 | 分类复选框支持全选、部分选择、未选择三态 |
| 详情 | 路径/大小/原因/风险 | 选择单项后显示；不读取文件正文 |
| 底部 | 已选择汇总 | 实时按最终可删除项计算 |
| 底部 | 开始扫描/清理 | 扫描前为开始扫描；有选择后为清理 |

### 13.2 关键交互

1. 扫描前显示范围确认，扫描本身绝不删除文件。
2. 下载目录和插件只进入“建议”，不能与安全缓存混在同一默认选择中。
3. 点击清理后显示最终确认页，按“移入回收站”和“永久删除”分组。
4. 永久删除组需要单独复选确认，默认未选中。
5. 完成页的释放空间使用实际成功删除量，不使用扫描估算量。
6. 报告可打开和导出，但默认隐藏完整用户名路径，允许用户展开查看。
7. 扫描范围按类别分组，并提供“推荐范围 / 全部 / 清空”；高风险范围即使参与扫描，候选仍默认不选。
8. 单类超过 100 项时默认折叠并按大小排序，首次只构建 100 项，之后每次加载 200 项，避免万级缓存冻结界面。

UI 验收：

- `UI-T2-01`：首次进入不自动扫描，默认选择符合产品规格。
- `UI-T2-02`：三态复选和底部容量汇总始终一致。
- `UI-T2-03`：下载、插件、高风险项目具有文字风险标识且默认不选。
- `UI-T2-04`：强力清理只允许用于可再生成缓存，并在最终确认页使用独立复选项说明不可恢复性。
- `UI-T2-05`：完成页明确区分成功、跳过、失败和实际释放量。

## 14. T3 文档阅读控件与流程

### 14.1 共通控件

| 区域 | 控件 | 默认/启用条件 |
|---|---|---|
| 左栏 | 打开文件/最近文件 | 最近文件最多 20 条，可逐条移除 |
| 工具栏 | 文件名、格式、编码、大小 | 打开后显示；路径在右侧信息栏 |
| 工具栏 | 搜索、上一个、下一个 | 内容首屏可用后启用 |
| 工具栏 | 格式专用控件 | 仅显示当前格式需要的控件 |
| 内容 | 虚拟查看器 | 首屏优先，索引后台继续 |
| 右栏 | 文件信息/解释器 | 默认折叠，宽 `280px` |

### 14.2 格式专用工具栏

| 格式 | 专用控件 |
|---|---|
| 文本/日志/配置 | 编码、换行、行号、跳转行 |
| Markdown | 预览/源码分段控件、换行 |
| CSV/TSV | 分隔符、表头开关、跳转行列 |
| JSON/XML | 格式化/源码、全部折叠、全部展开 |
| HTML | 隔离只读标识、允许打开外链一次 |
| EPUB | 目录、上一章/下一章、章节进度 |
| SVG/SVGZ | 适应窗口、实际大小、缩小/放大 |
| BIN | 每行字节数、偏移进制、跳转偏移、大小端 |

### 14.3 二进制行布局

```text
0000000000000000  50 4B 03 04 14 00 08 00  08 00 7A 53 2F 5B 00 00  PK........zS/[..
```

- 偏移固定为 64 位，默认十六进制、16 位宽。
- 第 8 字节后有一个额外分组间距，Hex 与 ASCII 保持固定列宽。
- 不可打印 ASCII 显示 `.`；选中范围在 Hex 和 ASCII 两侧同步高亮。
- 到达文件末尾时不补造字节，空位保持对齐但不可选择。

UI 验收：

- `UI-T3-01`：25 个正式后缀进入正确查看模式，未知后缀显示文本/Hex 选择。
- `UI-T3-02`：所有模式共享一致的搜索位置、文件信息和错误表现。
- `UI-T3-03`：1GB 文本和 2GB BIN 先显示真实首屏，再显示后台索引进度。
- `UI-T3-04`：Markdown 源码/预览切换保持搜索词和阅读位置。
- `UI-T3-05`：JSON/XML 折叠、CSV 固定表头和 EPUB 章节导航不改变整体布局。
- `UI-T3-06`：Hex/ASCII 同步选择、偏移跳转和大小端解释值清晰对应。
- `UI-T3-07`：HTML/EPUB/SVG 的隔离状态始终可见，外链先确认。

## 15. T4 开发工具控件与流程

### 15.1 工具选择

左栏固定为搜索框、最近使用、收藏和六个工具组。搜索匹配工具名称、别名和用途；无结果时显示“没有匹配工具”，不进行联网搜索。

### 15.2 通用工作区

| 区域 | 内容 |
|---|---|
| 标题栏 | 工具名、离线/联网标记、帮助、收藏 |
| 参数栏 | 仅放模式、编码、算法等短参数 |
| 输入区 | 文本、文件表或请求编辑器 |
| 命令栏 | 交换、清空、执行；危险文件操作另行确认 |
| 输出区 | 结果、错误位置、复制和保存 |

输入内容切换工具时保留在本次会话内；关闭应用默认不持久化敏感输入。HTTP 工具的授权头、Cookie 和正文不得进入最近历史。

UI 验收：

- `UI-T4-01`：工具搜索、分类、最近使用和收藏指向同一个工作区。
- `UI-T4-02`：纯转换工具的输入、输出、错误、交换、复制、保存位置一致。
- `UI-T4-03`：非法输入错误紧邻输入且不清空内容。
- `UI-T4-04`：HTTP 工具明确标注联网并显示请求/响应分区。
- `UI-T4-05`：批量重命名在确认前显示原名、新名、冲突和跳过原因。

重复文件使用独立工作区：选择文件夹后先按大小预筛，再显示完整 SHA-256 确认的重复组。每组按修改时间标记“建议保留最新”，默认不勾选；“选择每组建议项”只改变选择，不直接删除。底部固定显示已选数量与容量，确认后仅将选中且扫描后未变化的文件移入回收站，并生成不包含私人路径的结果报告。

## 16. T5 本地模型控件与流程

### 16.1 模型列表

模型项显示名称、能力、语言、版本、磁盘大小和状态。只有选中项显示详细许可证、来源 URL、SHA-256、安装路径和删除按钮，避免列表信息过密。

### 16.2 工作区

| 能力 | 输入区 | 结果区 |
|---|---|---|
| OCR | 图片拖放/选择、缩放预览、语言 | 保留布局的文本、纯文本、复制/保存 |
| ASR | 音频选择或麦克风、波形、时长 | 分段文本、时间戳、复制/保存 |
| TTS | 文本、声音、语速 | 播放器、时长、保存 WAV |
| 图像分类 | 图片预览、模型 | 标签、置信度和耗时 |

下载、校验、加载、推理和释放使用独立状态文案。运行按钮只在模型校验通过且输入有效时启用；取消后保留已完成的可用部分，并明确标记任务已取消。

UI 验收：

- `UI-T5-01`：五种模型状态可区分且不只靠颜色。
- `UI-T5-02`：下载、校验、加载、推理和释放不会共用模糊状态。
- `UI-T5-03`：OCR、ASR、TTS 切换后运行/取消位置保持稳定。
- `UI-T5-04`：错误哈希和损坏模型不能进入“可用”状态。
- `UI-T5-05`：释放模型显示前后内存，不宣传清理其他进程。

## 17. UI 验收证据

每个 `UI-*` 检查点至少保存一张包含完整窗口的截图；动态行为另保存短录屏。截图必须包含版本号，文件名遵循 [05_WINDOWS_ACCEPTANCE_PROCESS.md](05_WINDOWS_ACCEPTANCE_PROCESS.md) 的证据规则。

UI 基线截图固定为：

1. 1024×700 / 100%；
2. 1280×800 / 100%；
3. 1920×1080 / 150%；
4. 1920×1080 / 200%；
5. 高对比度或深色系统主题下的可读性检查。

UI 验收全部通过不代表功能验收通过；涉及数据、文件或模型结果时，还必须通过 [04_WINDOWS_ACCEPTANCE_MATRIX.md](04_WINDOWS_ACCEPTANCE_MATRIX.md) 中对应的功能编号。
