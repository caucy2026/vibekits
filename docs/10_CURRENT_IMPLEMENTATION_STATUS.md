# Vibekits 当前实现状态与未完成清单

更新日期：2026-08-15

适用代码：本地 Windows 工程当前工作树

目标平台：Windows 优先，Android 平板后续

## 1. 文档口径

本文按当前代码、测试和可执行入口核对，不按计划表推定完成度。

- **已实现**：当前界面或领域服务已有可执行行为，并有自动测试或构建证据。
- **部分实现**：主路径可用，但产品规格中的格式、错误处理、进度、取消、安全或 UI 验收尚未完整覆盖。
- **未实现**：没有可执行入口、仍显示占位提示，或目标平台工程尚不存在。
- **未验收**：代码可能存在，但没有按 `04_WINDOWS_ACCEPTANCE_MATRIX.md` 和 `07_WINDOWS_UI_ACCEPTANCE_MATRIX.md` 完成 Release 实机证据。

因此，“100 项自动测试通过”不等于“Windows V1 已全部完成”。当前产品定位应视为：**可运行的 Windows 工程预览版，五个模块已有主干能力，但正式发布闭环尚未完成**。

## 3. 应用外壳与通用能力

### 3.1 已实现

- Flutter/Dart 应用入口、浅色主题和五个一级 Tab。
- `Ctrl+1` 至 `Ctrl+5` 切换 Tab，`Ctrl+,` 打开设置对话框。
- Windows 窗口默认 1280×800，最小尺寸 1024×700，标题为 `Vibekits`。
- Tab 页面使用 `IndexedStack` 保留当前会话中的页面状态。
- Windows Debug/Release 构建链已配置，Release EXE 曾完成本机启动验证。

### 3.2 部分实现或未实现

- 设置对话框仍是占位文字；主题、语言、日志级别、缓存上限、模型目录和解压安全限制不可配置、不可持久化。
- 未实现“恢复上次 Tab”、最近文件持久化和用户设置损坏恢复。
- 后台任务面板没有完整任务调度、进度、取消、失败定位和关闭窗口保护闭环。
- 通用快捷键只覆盖 Tab 与设置；`Ctrl+O/S/F/G/W/Tab` 等尚未形成全局一致行为。
- 150%/200% 缩放、1024×700 全流程以及多窗口状态尚未按 UI 矩阵人工验收。

## 4. T1 解压缩

### 4.1 已实现

- 格式路由：ZIP、TAR、TGZ/TAR.GZ、TBZ2/TAR.BZ2、TXZ/TAR.XZ、GZ、BZ2、XZ、7z；RAR/ISO 可识别但会明确提示不支持。
- ZIP/TAR/GZ/BZ2/XZ：列表、条目选择和解压。
- 7z：通过随项目保存的 `native/7za/7za.exe` 完成列表和解压。
- 冲突策略：覆盖、跳过、自动重命名。
- 基础安全：拒绝绝对路径、盘符路径和 `..` 路径穿越；符号链接不写出；限制最大条目数和单文件展开大小。
- 创建服务支持 ZIP、TAR、TAR.GZ；当前 UI 的“新建压缩包”只创建 ZIP。
- 自动测试覆盖常用格式、路径安全、冲突策略以及 7z 创建夹具后的列表/解压闭环。

### 4.2 部分实现或未实现

- RAR、ISO 和 ZST 未实现列表/解压；RAR 需要 unrar 或完整 7-Zip，ISO 需要完整 7-Zip/libarchive 能力。
- UI 未提供创建 TAR、TAR.GZ 或 7z 的格式选择，也未实现目录打包。
- 规格要求四种冲突策略，当前缺少“逐个询问”。
- 普通压缩格式当前整体读入内存，不适合超大压缩包；7z 走外部进程。
- 未按文件头探测真实格式，主要依赖扩展名。
- 没有当前文件、百分比、速度、已写入大小和取消按钮。
- 没有解压前空间检查、总展开大小限制、压缩比检查、不可变解压计划、临时文件和原子改名。
- 加密包、损坏包、压缩炸弹、10 万条目和 500MB 包尚未形成完整自动+实机证据。
- 7z 外部进程的条目安全预检、部分失败报告和取消/清理未达到正式实现合同。

## 5. T2 Windows 清理

### 5.1 已实现

- 扫描 `%TEMP%` 用户临时目录；扫描器不跟随符号链接/联接点，并限制深度和候选数量。
- 按类别展示候选项、大小与原因，支持单项/分类选择和已选容量汇总。
- 支持当前会话内的目录白名单过滤。
- 清理前显示确认对话框，普通清理通过 Windows `SHFileOperationW` 移入回收站。
- 提供永久删除领域方法，但当前清理 UI 不调用它。
- 自动测试覆盖沙箱扫描、空目录、深度/符号链接等基础行为。

### 5.2 部分实现或未实现

- 当前实际扫描入口只有用户临时目录；浏览器缓存、开发缓存、Windows 临时目录、日志/转储、下载建议和回收站容量尚无扫描入口。
- VS Code、Visual Studio、JetBrains 插件清单和跳转卸载入口未实现。
- 扫描过程中没有可用的取消按钮、细粒度进度和当前目录显示。
- 白名单只保存在内存，重启后丢失，也没有规范化、去重和管理列表。
- 未实现高风险项默认策略、下载目录永不默认勾选等完整规则。
- 清理结果没有成功/跳过/失败逐项报告和真实释放空间统计。
- 占用、无权限、文件在扫描后变化等竞态没有完整 UI 反馈。

## 6. T3 文档阅读

### 6.1 已实现

- 文本类：TXT、LOG、INI、CFG、CONF、PROPERTIES、YAML、YML、TOML、DIFF、PATCH、TEX、LATEX。
- Markdown：源码和预览切换。
- 结构化：CSV/TSV 表格、JSON/XML 可折叠树，解析失败时回退源码并提示。
- Web 文档：HTML/HTM、EPUB、SVG/SVGZ；HTML/EPUB 注入 CSP 并清理脚本/iframe，EPUB 有 DRM、路径穿越和解压规模检查。
- 二进制：BIN 的偏移、Hex、ASCII 三栏显示，Magic Number 和整数/浮点解释领域能力已有测试。
- 编码：UTF-8、UTF-16LE/BE、GBK、GB18030、Big5；Windows 代码页转换使用 `MultiByteToWideChar` FFI。
- 普通文本搜索、日志级别着色、自动换行、编码切换、文件信息和会话内最近文件。
- 大于 64MB 的文本使用 `FileLineIndex` 分块建立行索引并按行读取，不整文件载入内存。

### 6.2 部分实现或未实现

- 只支持系统文件选择器；拖放、Windows“打开方式”和文件关联未实现。
- 没有真正的多文档标签页；最近文件只保存在内存。
- 大文本流式模式禁用搜索；流式索引没有取消和关闭页面时的任务取消协议。
- Hex 仍整体读入内存，超过 256MB 直接拒绝；2GB 稀疏 BIN 和跨块搜索未实现。
- Hex 的选择、高亮、跳转偏移、大小端切换等完整 UI 操作未闭环。
- 未知扩展名没有“按文本/Hex 打开”的选择流程。
- 复制、保存导出、外链确认、本地图片、打印等行为尚未完成或未统一验收。
- 1GB 日志内存/首屏性能、25 个后缀实机路由、危险 Web 样本网络隔离仍缺正式人工证据。

| 加密生成 | 7 | MD5、SHA-1、SHA-256、SHA-512、HMAC-SHA256、UUID v4、随机密码 |

| 合计 | 29 | 注册表当前共 29 个工具 |

界面支持工具搜索、分组导航、统一输入/参数/输出、异步执行状态、交换、清空、复制和保存输出。错误结果会保留输入并显示原因，部分工具包含错误位置。

### 7.2 部分实现或未实现

- 批量重命名只生成预览计划，不执行文件改名。
- HTTP 仅提供 GET，未提供方法、请求头、请求体、认证、超时和响应大小等完整工作区。
- TCP 输入按 `host:port` 简单拆分，不支持 IPv6 方括号格式。
- 文件哈希和批量重命名依赖手工输入路径，没有文件/目录选择器。
- 没有收藏、最近使用、执行历史、多个工作区或参数模板。
- 网络状态标识、任务取消、敏感参数日志检查和正式 UI 验收未完成。

> 注：旧开发日志写“22 个离线工具”是 M1 阶段统计；当前注册表实际为 29 个，其中包含后续增加的网络和文件工具。

## 8. T5 本地模型

### 8.1 已实现

- 默认模型目录：`%LOCALAPPDATA%\Vibekits\Models`。
- 导入本地 ONNX/BIN/GGUF/MODEL 等文件、列出模型、按文件名推断 OCR/ASR/TTS 类别、删除模型。
- 导入后计算 SHA-256，并在结果中显示哈希前缀。
- OCR、ASR、TTS 三个工作区入口和切换 UI 已存在。
- 模型存储领域逻辑已有自动测试。

### 8.2 未实现

- OCR、ASR、TTS 均未接入推理运行时；工作区明确显示占位提示。
- 未下载或集成 ONNX Runtime/sherpa-onnx/whisper.cpp/Piper 等 DLL 与模型。
- 没有模型清单、可信下载地址、目标 SHA-256 校验、断点续传、进度、取消和失败恢复。
- 列表阶段不重新计算 SHA-256，无法识别导入后被修改或损坏的模型。
- 没有加载、释放、运行、取消、输入输出、内存限制和 CPU 线程控制。
- 未强制执行单模型 100MB 上限，也没有模型兼容性与输入输出张量校验。

## 10. Windows 发布与 Android

### 10.1 Windows 已有

- Flutter Windows Runner、WebView2/file_selector 插件、窗口标题/尺寸和 Release 构建。
- 7za 第三方二进制及其许可证、说明文件随项目保存在 `native/7za/`。

### 10.2 Windows 未完成

- MSIX/安装器、开始菜单与卸载流程、文件关联、自动升级、代码签名、版本发布说明。
- 固定 Release Build ID 下的 62 项功能验收和 35 项 UI 验收。
- CI、可重复发布脚本、依赖许可证汇总和产物校验值清单。

### 10.3 Android 未完成

- 仓库当前没有 Android 平台工程、Manifest、Gradle 配置或平板适配代码。
- Android SDK cmdline-tools 未配置完成。
- Windows FFI（代码页、回收站）、WebView2、7za 外部进程等能力需要 Android 对应实现或平台抽象。
- 触控布局、存储访问框架、分享/打开方式、权限、前后台任务和 APK 签名发布均未开始验收。

| P0 | 修正现有主路径缺口 | 解压/清理有进度、取消、报告和安全计划；设置可用且持久化 |
| P0 | 接入模型推理 | 至少一个小于 100MB 的 OCR 模型完成导入、校验、加载、推理、释放闭环 |
| P1 | 补齐格式与入口 | RAR/ISO/ZST、拖放、打开方式、文件关联、大 Hex 流式读取 |

| P1 | 正式 Windows 验收 | 同一 Release Build 完成 62 项功能与 35 项 UI 证据，修正验收矩阵状态 |

## 12. 结论

项目不是空骨架：Windows 五个 Tab 均已有代码，其中开发工具和文档阅读具备较多可用能力，压缩、清理和模型模块也已有可验证的基础层。但按产品规格的严格完成定义，**当前尚不能标记 Windows V1 全部完成，更不能标记跨平台完成**。下一阶段应优先补齐真实用户流程中的进度、取消、安全、报告和模型推理，再进入正式验收与 Android 适配。
