# VibeKits 局域网发现与协同

每个打开 Harness 的 VibeKits 实例按照 [LMCP/1](46_LAN_MCP_DISCOVERY_PROTOCOL_V1.md) 在私网组播 `239.255.42.99:47831` 发布不含秘密的在线声明，并监听 VibeKits 或第三方兼容应用。声明限制在 1 KiB，仅包含协议版本、实例/应用身份、设备名、安全 MCP 入口、能力摘要和发送时间；节点离线约 12 秒后从列表移除。

Harness 顶栏显示“协同节点”及当前发现数量，MCP 使用 `vibekits.peers.list` 获取相同列表。发现结果始终为 `authorized=false`，只说明局域网中存在候选节点，不授予读取或控制权限。

协同链路：

1. `peers.list` 发现候选 IP 和 SSH MCP 端口。
2. 用户在目标主机核对 SSH host key，并批准来源设备的独立 Ed25519 公钥。
3. 来源 Harness 通过受限 SSH stdio MCP 获取目标 `tools/list`。
4. 主智能体按能力拆分任务，远端只执行被分派的工具调用。
5. 远端控制、写入和破坏性工具仍由远端 VibeKits APP 审批；主端不能代替远端批准。
6. 主智能体读取结构化结果并汇总，失败、拒绝和离线均作为真实状态，不自动转交未授权节点。

发现包不能携带 Bearer Token、模型 Key、飞书 Secret、工具参数、用户任务或文件路径。组播可以被同网段设备伪造，因此任何发现名称和 IP 都是不可信提示；只有固定 host key 与已授权设备公钥建立的 SSH MCP 才是可信连接。

Windows 首次监听可能触发防火墙提示，只允许“专用网络”。不自动开放公用网络或公网规则。跨设备完成标准为两台真实机器互相发现、分别批准、执行只读工具、拒绝未批准控制调用并在离线后正确移除；同机双实例测试只验证协议实现，不替代真实网络验收。
