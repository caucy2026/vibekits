# 分平台、分系统版本的清理策略

清理顺序：识别平台/版本 → 按规则发现存在的目录 → 保留期与归属/风险评分 → 用户选择 → 删除前再次校验平台边界。系统版本不代表目录可以整棵删除，也不扩大操作权限。

## macOS

沿用用户 Library、浏览器、开发缓存与日志规则。读取 macOS 产品主版本，不把 Darwin 内核版本当成 macOS 产品版本。修复旧逻辑“识别失败返回 99”的问题。

当前策略范围为 macOS 12–26，规则仍逐项检查 minimumMacosMajor 和目录存在性；该范围是代码策略覆盖范围，不代表这些系统都做过真机验收。未知/范围外版本只提供谨慎候选，不默认勾选；不会按“最新版本”放开清理。系统目录不因版本匹配而加入清理。

## Android

通过原生 Build.VERSION.SDK_INT 读取 SDK，传入后台发现任务。SDK 24–28、29、30–36 分别标注旧存储模型、过渡模型和分区存储模型。三个分支都保持本应用私有 cache 的边界；没有其他应用缓存或共享存储清理能力，不为此申请更大权限。

已覆盖 SDK 的本应用缓存保留至少 24 小时；识别失败或范围外 SDK 采用至少 7 天、谨慎风险、不默认选中。SDK 版本不能说明缓存是否正在使用，最终仍需原有候选与删除保护。Harness 调试证据保留人工确认，不等同于普通缓存。

## Windows

保留已有系统 build 号匹配的规则库、文件模式、保留时间与受保护系统目录规则，不套用 macOS/Android 路径。
