# Harness 完整远程工作区开发与验收

## 2026-09-10 dev.167 终端角色与最短操作路径

- Mac 与 Mac 之间是对等节点：任一端打开“允许远程协助”后，另一端只需输入对方 Harness ID 就能将对方项目、会话和工作状态作为远程仿真环境呈现。
- Mac 与 PAD 之间固定为 Mac 执行、PAD 协助：模型推理、工具调用和文件状态留在 Mac，PAD 只显示脱敏的项目/会话/状态，并通过协议发送命令、接收反馈和停止任务。
- PAD 不发布“允许别人协助本机”入口；进入远程协助后，未连接前本地 Harness 命令与工具全部禁用，始终显示醒目的“退出远程协助”按钮。
- 其他执行终端默认只提供本机 ID、密码、允许/拒绝和强制断开。

最短流程是“执行端打开允许协助 → 告知本机 ID → 协助端输入 ID → 连接”。网络通道优先使用内嵌 RustDesk P2P，直连失败才走 HBBS/HBBR 中继。通道只载 Harness 协议事件，不同屏、不传输远程桌面输入。首次连接要求默认密码或用户修改后密码，并由执行端确认最小工作区权限；后续使用端到端证书和已保存历史恢复。

## 2026-09-09 dev.165 架构收敛（历史）

远程协助不是远程桌面。VibeKits 只从 RustDesk 源码中复用以下三项网络能力：HBBS 数字 ID 注册与寻址、可用时的 P2P 打洞直连、直连失败时的 HBBR 原字节中继。

通道上层只运行 VibeKits 自己的证书配对和 Harness 协议，数据范围固定为项目、会话、状态、命令、执行反馈、停止与心跳。不建立桌面采集、视频、鼠标、键盘、剪贴板、文件传输、终端或任意端口代理能力。

运行时必须自包含：Android 使用 VibeKits APK 内的源码构建 `librustdesk.so` 及私有 `:vibekits_harness` 进程；macOS/Windows 使用 VibeKits 应用包内的 `vibekits-harness-relay` helper。禁止搜索、启动或依赖已安装的 RustDesk、KEMI远程办公或第三方插件。

macOS Release 构建前必须执行 `tool/prepare_rustdesk_harness_relay_macos.sh <helper>`。Release 打包阶段会硬校验 Mach-O 类型、`transport_connected`/`transport_connect_timeout` 状态标记和 RustDesk AGPL 许可证，并将 helper 固定复制到 `Contents/MacOS/vibekits-harness-relay`。任一项缺失立即构建失败，不能用开发机上的外部 RustDesk 兜底。

最小数据路径：`VibeKits UI → 包内传输进程 → HBBS/P2P/HBBR → 对端包内传输进程 → 对端 Harness 执行器`。

dev.164 历史证据使用过外部 KEMI Android service，只证明旧网络路径，不是本版交付基线。dev.165 已把 Android service/JNI 收入 VibeKits 自身包名与私有进程，并删除桌面端外部 App 回退。待重新完成首次配对、真实会话命令/反馈/停止、断线及 Mac/Windows 包内 helper 验收后才能发布。

## 交付目标

执行端运行官方 DSH，控制端使用同一工作区 UI。项目、会话、回复、可公开进度、工具参数/结果、审批与文件差异由执行端提供；控制端可以发送、追加、停止并收到执行回执。网络延迟允许，功能缺失、虚假空闲、虚假停止不允许。不传桌面视频；不生成模型未提供的内部推理。

## 架构与阶段

1. 协议基础：版本协商、运行实例 epoch、事件序号、快照恢复、重复投递处理、命令身份。用纯 Dart 实现并测试，与平台传输分离。
2. DSH 适配：盘点当前官方 HTTP/WebSocket 和 Host 桥全部操作，以同一官方数据模型映射项目/会话/工具/审批/文件。本地 Host 操作必须路由到执行端，远端路径不得被控制端直接操作。密钥在执行端保留。完整工具结果按需分页，文件按块传输。
3. 传输：从 RustDesk 注册/打洞/中继与认证流程提取独立组件；Harness 使用独立持久密钥、设备 ID、配置空间。服务端确认产品命名空间与连接类型兼容后启用；不得冒用远程桌面身份。端到端认证加密，按远端授权的项目和操作范围提供访问。
4. 共享 UI：本地与远端使用同一官方页面和增强交互；增加远端设备标识、网络延迟、待确认/离线状态。不能将任意远端网页接入有本机特权的 Host 桥。
5. 双机验收：macOS/Windows 组合、LAN 直连、强制中继、断线恢复、并发查看/控制、生产包回归。

## 协议约束

- 执行端唯一权威。snapshot 包含 epoch 和 sequence；event 必须连续。重复事件忽略，丢序或 epoch 变化必须重新取快照；离线保留最后数据但标为过期。
- commandId 在调用方身份范围内唯一，绑定 sessionId、操作与参数摘要。重试相同命令不得重复执行，不同内容复用 ID 必须拒绝。进程重启依靠持久命令账本恢复，不能仅靠内存去重承诺恰好一次。
- accepted 只表示接收；running、waitingApproval、stopping、completed、failed、cancelled 由执行端报告。停止请求不能直接把 UI 变为 idle。
- 多观看者独立游标与有界队列。状态摘要可合并；聊天、工具结果与审批事件不可丢弃，慢端从持久事件日志补齐。
- 审批绑定具体 task/tool/action，权限在执行端再次验证。断开观看不自动结束工作；撤销授权立即阻止后续命令。
- 产品 ID 不能仅靠显示前缀隔离；登记、握手、密钥和路由都要验证。中继兼容需真实联调，不假定新增枚举被现有服务器接受。

| 场景 | 通过条件 |
| --- | --- |
| 执行端先启动 | 控制端后连仍获取全部授权项目和分页历史 |

| 官方功能回归 | 项目增删改、会话删除/拖动、插件市场、MCP 均可用 |
| 性能 | 记录 RTT、首快照耗时、事件延迟 P95、CPU/内存；慢端队列有界 |
