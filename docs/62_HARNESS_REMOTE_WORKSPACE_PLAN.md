# Harness 完整远程工作区开发与验收

## 交付目标

执行端运行官方 DSH，控制端使用同一工作区 UI。项目、会话、回复、可公开进度、工具参数/结果、审批与文件差异由执行端提供；控制端可以发送、追加、停止并收到执行回执。网络延迟允许，功能缺失、虚假空闲、虚假停止不允许。不传桌面视频；不生成模型未提供的内部推理。

## 架构与阶段

1. 协议基础：版本协商、运行实例 epoch、事件序号、快照恢复、重复投递处理、命令身份。用纯 Dart 实现并测试，与平台传输分离。
2. DSH 适配：盘点当前官方 HTTP/WebSocket 和 Host 桥全部操作，以同一官方数据模型映射项目/会话/工具/审批/文件。本地 Host 操作必须路由到执行端，远端路径不得被控制端直接操作。密钥在执行端保留。完整工具结果按需分页，文件按块传输。
3. 传输：从 RustDesk 注册/打洞/中继与认证流程提取独立组件；Harness 使用独立持久密钥、设备 ID、配置空间。服务端确认产品命名空间与连接类型兼容后启用；不得冒用远程桌面身份。端到端认证加密，按远端授权的项目和操作范围提供访问。
4. 共享 UI：本地与远端使用同一官方页面和增强交互；增加远端设备标识、网络延迟、待确认/离线状态。不能将任意远端网页接入有本机特权的 Host 桥。
5. 双机验收：macOS/Windows 组合、LAN 直连、强制中继、断线恢复、并发查看/控制、生产包回归。

## 协议约束

- 执行端唯一权威。snapshot 包含 epoch 和 sequence；event 必须连续。重复事件忽略，丢序或 epoch 变化必须重新取快照；离线保留最后数据但标为过期。
- commandId 在调用方身份范围内唯一，绑定 sessionId、操作与参数摘要。重试相同命令不得重复执行，不同内容复用 ID 必须拒绝。进程重启依靠持久命令账本恢复，不能仅靠内存去重承诺恰好一次。
- accepted 只表示接收；running、waitingApproval、stopping、completed、failed、cancelled 由执行端报告。停止请求不能直接把 UI 变为 idle。
- 多观看者独立游标与有界队列。状态摘要可合并；聊天、工具结果与审批事件不可丢弃，慢端从持久事件日志补齐。
- 审批绑定具体 task/tool/action，权限在执行端再次验证。断开观看不自动结束工作；撤销授权立即阻止后续命令。
- 产品 ID 不能仅靠显示前缀隔离；登记、握手、密钥和路由都要验证。中继兼容需真实联调，不假定新增枚举被现有服务器接受。

## 验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 执行端先启动 | 控制端后连仍获取全部授权项目和分页历史 |
| 相同任务本地/远程 | 可见消息、进度、工具输入输出、差异、终态一致 |
| 发送及追加 | 远端确认 commandId，真实执行，结果关联同一会话 |
| 重试/网络抖动 | 同一命令只触发一次执行；不同参数复用 ID 被拒绝 |
| 停止 | 工具及子进程停止确认后显示终态；确认前显示 stopping |
| 断线重连/远端重启 | 显示离线，不伪报 idle；补齐或重新加载快照，无重复文本 |
| 两会话同时运行 | 草稿、结果、审批、停止彼此隔离 |
| 多端控制 | 控制冲突明确反馈，审批不重复消费 |
| 授权 | 未授权项目不可见；只读连接不能执行；撤销立即生效 |
| 直连/中继 | 两种路径分别完成发送→工具→结果→停止→重连 |
| 官方功能回归 | 项目增删改、会话删除/拖动、插件市场、MCP 均可用 |
| 性能 | 记录 RTT、首快照耗时、事件延迟 P95、CPU/内存；慢端队列有界 |

每项保留两个端点版本、连接类型、commandId、epoch/sequence、实际结果与截图。未通过项明确列出，协议单测不算双机完成。
