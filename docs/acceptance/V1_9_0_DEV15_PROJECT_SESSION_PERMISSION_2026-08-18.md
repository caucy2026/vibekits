# Vibekits 1.9.0-dev.15 项目会话与权限语义验收

## 本版目标

- 权限设置必须改变实际工具审批行为，并在 Harness 重建后继续生效。
- Harness 项目必须真实绑定多个独立会话，不能只绘制项目/会话侧栏。

## 实现结果

- “完全访问权限”持久化后，注册工具不再逐次弹出批准框；APP 工具注册表、ADB 目标锁定、禁止命令、参数校验、超时和审计仍强制执行。
- 会话数据模型升级为 `Project(workspace) → Session(id) → Messages`，项目保存活动会话 ID。
- 新建会话保存当前会话后创建新实体，旧会话继续显示；点击历史会话先保存当前内容，再恢复目标消息。
- 切换项目先写回当前项目；重新创建 Harness 后恢复该项目的会话列表和上次活动会话。
- v1 单消息列表在读取时自动迁移到一个历史会话；每项目最多保存 40 个会话，每会话最近 80 条消息。
- API Key 仍只写 Windows Credential Manager/macOS Keychain，不进入项目会话 JSON。

## 闭环证据

| 验收项 | 结果 |
|---|---|
| `flutter analyze` | 通过，0 问题 |
| 选择完全访问 → 销毁界面 → 重建 → destructive 工具调用 | 1/1 通过，批准框 0 个 |
| 项目加载两个会话 → 切换 → 新建第三个 → 重建恢复 | 1/1 通过，三个会话均保留且活动会话一致 |
| Windows Debug 构建 | 通过：`build/windows/x64/runner/Debug/vibekits.exe` |

## 边界

- 本验收证明 Flutter 数据/审批状态机在重建后的行为，不把“完全访问”解释为任意系统命令权限。
- Windows Debug 已构建并启动进程；权限菜单和项目会话的 Windows 鼠标实操仍由当前前台版本继续验收。macOS 仍需实机构建验证。
