# v1.9.0-dev.64 清理经验决策引擎验收

日期：2026-08-22  
机器：当前 Windows 开发机，系统盘 80 GiB  
安全边界：所有本机扫描均为只读；没有删除、移动或修改真实文件。

## 1. 闭环方法

1. 使用发布规则和 APP 后台扫描器运行原算法，记录候选数、容量和耗时。
2. 独立按“可重建、语义、最近使用、软件归属、容量收益、磁盘压力”复核，并检查系统目录、当前 APP、用户数据、回收站和重复计数边界。
3. 将结论实现为独立 `CleanupDecisionEngine`，扫描默认勾选和智能选择共用同一结果。
4. 用隔离夹具验证四级决策、当前 APP 保护、系统管理保护、回收站确认和父子去重。
5. 在同一机器再次执行不含任何删除代码的纯只读脚本，输出最终分账。

“人工复核”中主要容量来自约 5.9 GiB 系统回收站。回收站是可释放空间，但清空后不可恢复，因此单独显示且永不默认勾选。`WinSxS`、`WindowsApps`、`Recovery`、安装器缓存、用户下载、会话数据库和模型数据不会因为系统盘空间不足进入自动清理。

## 3. 已闭环

- 扫描发现不再等于允许删除；磁盘压力不能突破硬保护。
- 扫描后默认选择与“智能选择”不再有两套互相矛盾的逻辑。
- 不再为了 10 GiB 验收自动带上回收站或证据不足项目。
- 父目录和同来源子文件不会重复计入计划容量。
- 删除执行前仍校验路径类型、大小和修改时间；用户数据建议保留文件身份复核。
- 扫描在后台 Isolate 执行并可取消；本轮安全、扫描、删除复核和界面定向测试通过。

发布门禁：定向回归 30/30；`flutter analyze --no-pub` 0 问题；Windows Release 构建成功；PE `FileVersion` 与 `ProductVersion` 均为 `1.9.0-dev.64+74`。

## 4. 未伪报项

132 秒仍未达到“快速扫描”目标，且受大量小文件、实时杀毒和磁盘压力影响会波动。后续性能闭环必须实现 Windows MFT/USN 增量索引或等价的快速目录索引；在此之前文档和 UI 不得宣称秒级全盘扫描。实际释放 10 GiB 仍只能由用户在 APP 中确认计划并执行后，以清理前后物理可用空间差验收，本轮只读审计不计为实际释放。
