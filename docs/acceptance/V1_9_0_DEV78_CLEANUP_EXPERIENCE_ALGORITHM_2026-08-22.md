# v1.9.0-dev.78 清理经验算法与性能闭环验收

## 目标

把“大模型人工分析系统盘”的判断方式转成确定、可解释、可测试的 APP 算法，同时保证：不为了 10 GiB 指标删除未知数据，不在 UI 线程扫描磁盘，候选很多时也能结束。

## 已转化为算法的判断

1. **先保护再评分**：系统/安装器管理目录、当前 Vibekits 运行数据、用户文件及未知归属路径是硬门禁，磁盘压力不能降低其风险等级。
2. **证明可重建才推荐**：已知应用缓存、下载缓存、构建索引等必须有明确规则、来源、保留时间和影响说明。安全开发缓存超过 24 小时只进入“建议清理”，不自动删除。
3. **目标不能改变证据**：10 GiB 规划器先纳入自动安全项，再按容量从建议项补足；不足时展示差额和人工复核机会，不把未知目录升级为可清理。
4. **执行前仍复核**：扫描只生成候选，真实删除继续走文件身份校验、取消、成功/跳过/失败报告及磁盘前后可用空间核对。
5. **重叠规则取更安全语义**：同一路径被多个规则识别时，系统保护优先；应用精确规则优先于泛化名称发现；谨慎规则不会被安全规则覆盖。

## 本机只读审计

系统盘当前约 80 GiB。使用 Release 同源规则执行全量默认候选审计，排除显式深度日志盘点；全程只读，未删除真实文件。

| 指标 | 结果 |
|---|---:|
| 扫描耗时 | 77 秒 |
| 唯一候选 | 89,331 项 |
| 候选总潜力 | 6.466 GiB |
| 自动安全 | 579 项 / 0.533 GiB |
| 建议清理 | 19,583 项 / 4.203 GiB |
| 人工复核 | 69,169 项 / 1.731 GiB |
| 保护不清理 | 0 项 / 0 GiB（候选阶段已排除大部分系统内容） |

结论：当前有证据的自动+建议容量约 4.736 GiB，达不到 10 GiB。APP 应如实显示缺口；要继续释放空间，必须由用户在占用分析中决定是否清空回收站、卸载不用的软件/旧版本，或复核会话与用户数据。

## 性能修复

旧去重逻辑会让每个候选遍历已有结果，约 4～9 万项时可能产生十亿级路径比较，表现为扫描结束后长时间不退出。现在按类别/来源维护规范化路径集合，仅逐级检查父目录，复杂度降为 O(n × 路径深度)。

- 50,000 候选性能回归：通过，门槛小于 3 秒。
- 后台扫描：固定 2 个 isolate，避免近满机械盘/系统盘随机 I/O 争用。
- UI：扫描、决策和删除均不占用 UI isolate，取消信号通过独立端口传给工作 isolate。

## 自动验收

- 清理扫描、取消、规则优先级、决策分层、10 GiB 规划器、规则数据库：15/15 通过。
- 定向静态分析：0 问题。
- 实机只读审计：1/1 通过。

## 安全声明

本轮没有执行真实清理。6.466 GiB 是扫描潜力，不等于实际释放；最终释放量只能以用户确认执行后磁盘可用空间的真实增量为准。
