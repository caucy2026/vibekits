# v1.9.0-dev.81 智能体原生协作与演进验收

日期：2026-08-23  
版本：`1.9.0-dev.81+91`

## 本轮目标

1. 用高频能力验证 Harness 工具桥、MCP 和真实模型调用主链。
2. 让音频工具能回答“哪一段谐波明显、哪一段噪声最大”。
3. 用正式简介说明“智能体 + 本地确定性工具”的产品定位。
4. 建立上游 Harness 自动发现、隔离候选验证和人工发布门禁。

## 自动测试证据

- 54 项高频单线程测试通过：Harness Bridge、MCP Server、ADB、串口领域层、SQLite、API、文件 Diff、Git、代理/虚拟机合同与音频。
- 官方固定 Harness 使用本地模型端点完成 `模型 → MCP SHA-256 → APP 执行 → 结果回传 → 最终回复`，单独运行 5 秒通过。
- 音频新增合成夹具：0～1 秒纯音、1～2 秒注入二次谐波、2～3 秒注入噪声；Harness 返回的首个谐波热点位于 1～2 秒，首个噪声热点位于 2 秒以后。
- 并发执行真实 Harness 与大量领域测试曾触发 60 秒假超时；改为单线程资源隔离后稳定通过。正式质量门禁不得把多个原生 Harness 进程无界并发。
- 全量回归发现两个因界面增加有效说明而过时的精确文字数量断言，已改为验证内容存在；生成 PNG 的截图用例改为 `VIBEKITS_UPDATE_SNAPSHOTS=true` 时显式运行，普通回归不再写验收文件或等待 GPU 编码。
- 第一次单线程全量跑次完成 `471 通过 / 5 环境跳过 / 3 失败`。3 个失败分别暴露：虚拟机入口被藏入 Clash 设置、真实 Harness 子进程在长跑中超时、批量拖拽用例未清空延迟计时器。虚拟机已改为独立左栏入口且不依赖代理启动；批量拖拽改用有界帧等待并回收定时器；Harness 保持单进程资源隔离。随后专项回归 `拖拽/OCR 21/21`、`开发工具 10/10`、`真实 Harness 1/1` 通过。
- 修正后第二次全量复跑为 `473 通过 / 5 环境跳过 / 1 失败`，唯一失败是 VAD 冒烟测试仍从已被清理的 Pub 缓存寻找 `onnxruntime.dll`。改为优先使用 APP Debug/Release 自包含 DLL 后，真实 Silero ONNX 中文 WAV 推理 `1/1` 通过（5 秒）。因此当前自动化聚合结果为 `474 通过 / 5 环境跳过 / 0 未修复失败`。
- 点击性能独立复测：Harness 首次 648 ms/再次 190 ms，一级工作区首次 238～746 ms，开发工具首次 47～316 ms/再次 152～308 ms，文件路由 2～17 ms，Harness 调用记录 11 ms。Debug/JIT 长跑会存在宿主负载抖动，因此用例保留计时但与 Release Profile 门禁分开。
- `flutter analyze --no-pub` 通过，0 问题。

## 仍不能宣称完成的范围

- 现有模型自动选择端到端测试主要覆盖 SHA-256；其余多数是直接调用工具 ID。下一阶段必须为每个复杂工作区增加自然语言选择夹具。
- 串口、远程数据库、SSH/SFTP 和真实音频输入仍受对应硬件/服务环境门禁约束。
- ADB 真机、真实 Mihomo Profile、真实系统盘修改和 UI 截图基线需显式环境变量/设备，本轮中按门禁跳过，不计为通过。
- 当前固定 Harness 为 `0.1.0-rc.7`；官方 npm 最新为 `0.1.1-rc.2`。本轮只建立候选检测流程，不直接替换生产运行时。

## 演进边界

`.github/workflows/harness-evolution.yml` 每周检查官方 npm。发现新版后只在 GitHub Runner 隔离目录准备候选、执行兼容补丁和 CLI 冒烟，并创建升级评审工单。客户端继续使用最后验证通过的固定版本；新版必须经过 Web、会话、权限、MCP 全能力、停止、资源释放和 Release 回归后才能灰度发布。
