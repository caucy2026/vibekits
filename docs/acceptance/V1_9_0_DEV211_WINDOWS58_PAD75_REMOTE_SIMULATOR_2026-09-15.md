## 目标

- 被控端一次打开远程仿真后，控制端只输入统一设备 ID；不要求用户手工交换 SSH 地址、账号、密码或密钥。
- 通信只使用 VibeKits 自带的 RustDesk P2P/HBBR 载体、固定回环 MCP 和 SSH/SFTP，不打开或操作 RustDesk 远程桌面界面。
- 能读取应用、进程和日志，上传/下载文件，执行严格主机指纹校验后的 SSH 命令，启动和停止应用并取得单帧诊断截图。
- PAD 只作为控制端，通过同一 ID 查看远端工具和执行进程/文件自检。

## 本轮修复

1. Windows 同名用户目录兼容：不再只相信 `USERPROFILE`，优先读取 `sshd -T`，失败时解析 `C:\ProgramData\ssh\sshd_config` 中精确 `Match User` 的 `AuthorizedKeysFile`，解决公钥写入带机器后缀目录、sshd 却读取原目录的问题。
2. SSH 授权门禁：写入后再次调用状态接口核验；未持久化时立即停止，不再继续建立一个必然失败的隧道。
3. Windows SSH/SFTP：按目标平台创建暂存目录、转换远程路径并用 `certutil` 校验 SHA-256，移除 Unix 专属 `/tmp`、`chmod`、`shasum` 假设。
4. Windows 本地化输出：控制器以允许替换非法字节的 UTF-8 解码子进程输出，避免系统本地化错误文本触发 `FormatException`。
5. Windows 诊断：进程读取与停止改为受控 PowerShell；所有 PowerShell 脚本使用 UTF-16LE `EncodedCommand`，避免参数被拼到管道末尾；日志无匹配项时返回空数组而不是误报调用失败。
6. 非持久化真机门禁也会正确设置进程内授权状态，确保单帧截图与安装工具和目标端开关使用同一授权事实。
7. Android Rust 载体使用当前源码构建；PAD 的仿真监听为后台字节转发，不创建远程桌面窗口。KEMI PAD 的中继资格同时校验硬件身份和精确 APK 签名证书，不能只靠可伪造的机型字符串。
