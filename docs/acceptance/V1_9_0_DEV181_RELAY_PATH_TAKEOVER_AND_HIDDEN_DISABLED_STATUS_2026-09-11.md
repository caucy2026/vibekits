# VibeKits dev.181 中继路径接管与关闭状态隐藏验收

## dev.180 真机复测结论

- 新机器前台已经运行 `dev.180+2180`，认证 LMCP/2 的 197 个工具、仿真状态、
  进程读取均通过。
- routing ID 通道仍超时；远端进程证据显示后台服务仍来自旧安装目录，前台
  则来自新下载目录。
- 旧、新包内中继二进制内容相同，因此只比较 SHA-256 不能识别“旧路径进程”。

## dev.181 修复

1. 同时持久化中继 SHA-256 与绝对可执行路径。
2. App 启动恢复已开启的局域网仿真时，路径或内容任一变化都必须停止旧服务、
   等待退出，再启动当前安装包内服务。
3. 路径和内容均一致时不重启，避免普通启动影响现有连接。
4. 局域网仿真关闭时，官方 Harness 与备用工作区主界面都完全隐藏仿真状态；
   不显示关闭、离线或异常外观。高级设置页仍保留开关。

## 门禁

- 路径变化但 SHA-256 相同仍必须触发一次接管。
- 关闭状态主界面找不到“局域网仿真关闭”。
- 开启后的准备、可连接、连接中和真实错误状态继续可见。
- 全量静态检查无问题；安装真机后必须完成 routing ID 到 32147 的 MCP 初始化、
  工具目录、进程和短日志调用。
