# v1.9.0-dev.52 系统清理安全恢复与交互闭环

## 现场结论

- dev.51 的真实 C 盘清理计划错误地把 96,057 个“需确认”候选纳入智能选择；企业微信小程序运行包及 Pub 开发依赖被误清，QQ/开发环境出现文件缺失。
- 105,948 项逐批送入回收站耗时过长；单软件缓存通过一次 Shell 操作处理聚合目录时会无限转圈，且没有取消入口。
- 本轮释放空间未达到 10 GiB，原 10 GiB 目标仍为 **FAIL**，不得用估算值代替实际磁盘增量。

## dev.52 修复

1. 智能选择只允许高置信类别：旧用户临时文件、已验证浏览器/应用缓存、系统缓存、插件下载缓存、调试临时文件和日志；`cautious/systemManaged` 永不自动选择。
2. 开发依赖、模型、应用运行包、未知目录、回收站、下载和软件本体只展示，由用户逐项决定。
3. 安全且可再生成的候选可采用 8 路有界并发永久删除；其他候选保持回收站策略。先直接删除，失败后才遍历只读属性，避免重复全树 I/O。
4. Microsoft、WindowsApps 等未匹配真实安装项的聚合目录只分析，禁用笼统“清理缓存”。卸载始终调用软件官方卸载器。
5. 单软件缓存清理提供停止按钮；30 秒无结果立即终止工作 Isolate，页面不再无限等待；关闭页面同时终止该工作线程。
6. 软件归属细化到 Microsoft/Google/Tencent 下一级产品及 WindowsApps 具体包，列表显示安装、数据、可清缓存、判断与操作边界。
7. 本次损坏的 Pub 空壳目录已隔离，项目依赖迁移到 D 盘 `.pub-cache` 恢复，避免继续占满 C 盘。

## 发布边界

dev.52 修复版可以用于只读扫描、占用分析和人工复核，不得把 dev.51 的 11.05 GiB 估算计划记作实际释放。下一次真实清理前必须先验证智能计划中不存在需确认项、运行包和活动开发依赖。
