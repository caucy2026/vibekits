# VibeKits 高级设备能力与集群任务中心统一需求

## 1. 目的

本规范统一 VibeKits 的远程协助、远程仿真机和集群任务中心。三项能力共用同一个 VibeKits 设备 ID、统一状态表达和审计基础设施，但拥有独立开关、独立权限和独立运行生命周期。桌面端远程协助默认开启并只进入“等待连接”，远程仿真默认关闭；集群任务开关默认开启，但服务器未配置时只进入安全等待态，不联网、不领取任务。用户明确关闭任一开关后必须持久保持关闭。未使用时不得影响 Harness 的启动速度、官方界面、项目、会话、插件市场、MCP、ADB 或本地推理。

## 2. 设备角色与用户场景

### 2.1 远程协助

- macOS/Windows 可作为被协助端；PAD 只作为协助端。
- 协助端输入统一设备 ID，查看与本地一致的项目、会话、推理、工具时间线和结构化结果，并可发送任务、停止任务。
- 只传输结构化状态与命令，不传输远程桌面画面。
- 打开或冷启动恢复远程协助时，必须强制启动内置通信载体和首次配对通道；“尚未持久化配对范围”是首次等待状态，其他启动错误必须失败关闭。
- 未完成证书校验、范围批准、项目订阅和心跳前，包括正在握手或对端反复重试，主界面统一显示蓝灯“协同等待连接”；只有完成订阅并收到有效心跳才显示绿灯“协同已连接”。
- 本机 Harness 状态 IPC 的订阅、MCP 观察者、本机 KEMI 进程、Relay 已注册或底层字节隧道已建立均不等于远程协同已连接，不得驱动绿灯。状态 IPC 只发布工作快照，协同状态只接受认证远程数据通道的连接、心跳和断开事件。
- 关闭远程协助后主界面不显示协同状态，并撤销配对/执行固定端点；不影响独立的远程仿真和本地 Harness。

### 2.2 远程仿真机

- macOS/Windows 打开“允许作为仿真机”后，其他 VibeKits 或兼容 MCP 智能体只凭统一设备 ID 即可连接。
- macOS 被授权为仿真机时，由系统管理员授权打开 Remote Login（系统 SSH）；通过统一 ID 的 P2P/中继通道只允许转发到回环 `22`（SSH）和 `32147`（受控 MCP），不开放远程桌面或任意端口转发。
- P2P 优先，失败自动走 HBBR 中继；关闭授权后立即拒绝新调用。

### 2.3 集群任务中心

- 所有明确打开“接收集群任务”的电脑向配置的任务服务登记设备 ID、App/协议版本、平台、在线状态和脱敏能力摘要。
- 服务端只下发任务信封：任务 ID、任务描述 URL、版本、创建时间、截止时间、签名及可选能力要求。不得下发 shell、脚本或可直接执行的任意命令。
- 客户端校验签名、可信域名、HTTPS、有效期和去重键后读取任务描述；描述交给本机 Harness 解析和执行，继续复用原有工具 Schema、批准、停止、状态、时间线和证据机制。
- 客户端回传认领、执行中、等待批准、完成、失败、取消等结构化状态与脱敏结果摘要。任务正文、凭据、用户文件和模型上下文不得放进心跳。
- 接收任务默认开启；配置不完整时只显示安全等待配置，不发起网络请求。服务不可达、任务非法或运行失败只能改变集群模块状态，不能阻塞或重启 Harness。

## 3. 统一信息架构

唯一人工管理入口为“设置 → 高级”，页面按以下顺序呈现：

1. 设备身份：统一设备 ID、复制按钮、网络引擎状态。
2. 远程协助：允许接入、协助他人、历史连接、首次配对与撤销。
3. 远程仿真机：独立开关、准备/可连接/已连接/异常状态。
4. 集群任务中心：独立开关、服务地址、可信域与签名状态、当前/历史任务。
5. 诊断与审计：最近连接、最近任务、脱敏错误和重试入口。

Harness 工作区不放设置、密码、设备 ID 输入框或弹窗，只显示紧凑的只读状态：协同等待连接、协同已连接、仿真中、集群任务执行中、断开或异常。状态点击可导航至高级页面，但不得覆盖、重载或拦截官方 Harness WebView。开关关闭时不显示该能力的异常或连接占位。

### 3.1 协同状态判定表

| 条件 | 主界面状态 | 颜色 |
| --- | --- | --- |
| 远程协助关闭，且无控制端会话 | 不显示 | — |
| 远程协助打开，Relay 已注册，但远程连接表为空 | 协同等待连接 | 蓝色 |
| 正在握手、等待首次批准或尚未完成项目订阅 | 协同等待连接 | 蓝色 |
| 认证数据通道已订阅且心跳有效 | 协同已连接 | 绿色 |
| 已打开能力发生协议不兼容、心跳超时或真实运行错误 | 协同异常 | 红色 |

任何仅来自本机状态 IPC 的 handshake、subscription 或 heartbeat 都不得进入此表的绿色状态。

## 4. 自适应布局与可访问性

- 顶层设置对话框受当前窗口约束：最大宽度 720、最大高度 590，较小窗口使用可滚动内容，不得越界。
- 高级页面为纵向滚动视图；长列表单独分页或限制高度，禁止嵌套无界滚动。
- Harness 右侧快捷栏在高度不足时必须纵向滚动；不得用 `Spacer` 把底部按钮推出视口。
- 右栏宽度应随文字缩放保持最小 60 逻辑像素；图标点击区域不小于 44×44。系统文字放大时优先隐藏说明文字、保留图标与 Tooltip/Semantics。
- 在 1024×600、1280×720、常规桌面窗口，以及 100%、125%、150%、200% 文字缩放下，所有按钮均可见或可滚动到达，无 RenderFlex overflow、遮挡或无法点击。
- macOS、Windows 和 PAD 共用同一 Flutter 组件与状态机；平台角色差异只控制可用动作，不复制页面。

## 5. 解耦与生命周期

```text
App Shell
├─ Harness Runtime（核心；独立启动）
├─ Remote Assistance Runtime（可选；首屏后异步）
├─ Simulator Runtime（可选；首屏后异步）
└─ Cluster Device Agent（可选；首屏后异步）
```

- App 启动只等待本地设置和 Harness 必要资源。三项高级运行时均不得进入 Harness readiness 条件。
- 每个运行时拥有独立 generation、超时、重试和取消；迟到回调不得覆盖新状态。
- 任一高级功能异常不得清缓存、删除 Cookie、本地存储或项目数据，不得导航 WebView，不得重启 Harness Node。
- 共用设备 ID 只表示路由身份相同，不表示权限互通。远程、仿真、集群各自授权、各自撤销。

## 6. 集群任务状态机

设备代理：

`disabled → starting → registered → polling/streaming → degraded → registered → disabled`

单个任务：

`discovered → validating → available → claimed → parsing → running ↔ waitingApproval → completed | failed | cancelled | expired | rejected`

- 同一 `taskId + version` 只能认领一次；重试使用新的 attempt ID。
- 任务认领必须是服务端原子操作，避免多设备重复执行；若任务明确允许多播，则每台设备拥有独立 assignment ID。
- App/Harness 停止、用户关闭开关或任务被服务端撤销时，必须取消本地执行并回传最终状态。

## 7. 服务契约（待后端地址与公钥确认后实现联网）

建议版本前缀 `/api/v1/agents`：

- `POST /register`：设备登记，返回短期会话与心跳间隔。
- `POST /heartbeat`：设备/能力/当前 assignment 的精简状态。
- `GET /tasks` 或 SSE/WebSocket：取得签名任务信封。
- `POST /tasks/{id}/claim`：原子认领，返回 assignment ID。
- `POST /assignments/{id}/events`：追加状态事件。
- `POST /assignments/{id}/result`：提交脱敏摘要、证据索引和退出状态。
- `POST /assignments/{id}/cancelled`：确认取消。

所有请求使用 HTTPS、设备级短期凭证、请求 ID、时间戳和重放保护。任务 URL 必须匹配本地可信域白名单；正文大小、重定向次数、解析时间和执行时间均有上限。联网实现不得在未知服务地址、公钥和可信域时猜测默认值。

## 8. MCP 工具契约

高级能力在询问“你有哪些功能/特殊能力”时必须优先呈现：

1. 远程协助；
2. 远程仿真机（macOS 系统 SSH + 受控 MCP）；
3. 集群任务中心；
4. 再列普通业务模块与工具。

首期 MCP 工具：

- `vibekits.advanced.capabilities`：只读返回三项高级能力、平台角色、开关、真实状态与下一步。
- `vibekits.remote_assistance.status` / `set_enabled`：查询或开关被协助端；PAD 返回只作为协助端。
- `vibekits.simulator.status` / `set_enabled`：查询或开关仿真机授权；PAD 明确不可用。
- `vibekits.cluster.status` / `set_enabled`：查询或开关任务接收；配置不完整时返回 `unconfigured`，不得伪报成功。
- 后续联网完成后扩展 `cluster.task_list/claim/stop/result`，不改变已有工具含义。

所有写操作继续走 Harness 的控制设备批准策略；MCP 不得读取或返回密码、Token、私钥和任务正文。

## 9. UI 验收

1. 设置常规/高级切换不丢状态；高级页面所有区块可滚动到达。
2. 最小窗口和 200% 文字缩放下，右侧所有快捷按钮均可滚动点击，底部设置/更多不被遮住。
3. 远程、仿真、集群三个开关互不改变；关闭任一项不停止另外两项。
4. Harness 首屏先完成；高级服务慢、离线、异常时仍可创建会话、输入、推理、停止和使用插件市场。
5. Harness 只显示状态，不弹出远程桌面/连接窗口，不出现高级设置表单。
6. PAD 单屏启动，只能协助或控制远端，不能打开本机被协助/仿真开关。

## 10. 自动测试与真机门禁

- Widget：多尺寸、多文字缩放、浅/深色；快捷栏滚动命中全部 Key；高级页面滚动命中全部区块。
- State：三个独立设置持久化、状态机 generation、取消、超时、恢复、互不停止。
- MCP：工具目录、只读状态、审批、平台角色、未配置集群、错误不污染 Harness 状态。
- Harness 回归：官方插件市场、项目/会话、独立草稿、并行会话、停止、默认折叠时间线、ADB/MCP 均保持工作。
- 故障注入：任务服务断网、坏签名、过期任务、恶意重定向、重复任务、服务端取消；Harness 仍可用。
- 真机：macOS 12+ Intel/Apple Silicon、Windows 10/11、PAD 75；远程和仿真完成 P2P/中继闭环，集群待真实服务契约提供后完成登记→发现→认领→解析→执行→回传闭环。

## 11. 发布判定

代码存在或单元测试通过不等于正式完成。只有对应平台构建、签名要求、真实启动、UI 点击、网络闭环和既有功能回归全部留存证据后，才能发布。集群服务地址、公钥、可信域和后端接口未冻结前，只能交付解耦架构、状态模型、UI/MCP 占位与测试，不得声称集群任务已联网可用。
