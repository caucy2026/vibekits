# Vibekits Windows V1 产品规格

版本：0.1
状态：开发基线
目标平台：Windows 10 22H2、Windows 11，x64
验收环境：当前开发电脑

## 1. 产品目标

Vibekits 是面向程序员的本地工具箱。Windows V1 使用单窗口、五个主 Tab，统一提供压缩解压、系统清理、轻量文档阅读、开发者工具和本地 CPU 模型能力。

产品遵循以下原则：

1. 本地优先：除 GitHub 元数据和用户主动下载外，核心功能离线可用。
2. 只读优先：文档查看器不得修改源文件。
3. 操作可预览：删除、覆盖、解压等破坏性操作必须先展示目标和影响。
4. 能力可验证：每项正式能力都有唯一验收编号和可重复步骤。
5. 资源有边界：大文件、压缩包和模型必须限制内存、线程和展开规模。

## 2. 主导航

应用包含五个一级 Tab：

| 编号 | Tab | 目标 |
|---|---|---|
| T1 | 解压缩 | 查看、解压和创建常用压缩包 |
| T2 | Windows 清理 | 扫描、选择并安全清理可恢复空间 |
| T3 | 文档阅读 | 阅读轻量文本、结构化数据、Web、EPUB、SVG 和二进制文件 |
| T4 | 开发工具 | 提供离线编码、转换、生成、网络和文件工具 |
| T5 | 本地模型 | 管理并运行 ASR、TTS、OCR 等 CPU 模型 |

应用启动后恢复上次 Tab，但不自动恢复模型、不自动删除文件，也不自动执行网络请求。

## 3. T1 解压缩

### 3.1 正式范围

首版读取/解压格式：`.zip`、`.7z`、`.rar`、`.tar`、`.gz`、`.bz2`、`.xz`、`.zst`、`.tgz`、`.tbz2`、`.txz`、`.iso`。
首版创建格式：`.zip`、`.7z`、`.tar`、`.tar.gz`。

底层优先采用 libarchive；若某格式需要独立解码器，必须保持相同的安全检查和进度协议。

### 3.2 功能要求

- `ARC-001`：选择压缩包后展示目录树、文件数、压缩大小和预计展开大小。
- `ARC-002`：支持选择全部或部分条目解压到用户指定目录。
- `ARC-003`：解压过程中展示当前文件、完成比例、已写入大小、速度和取消按钮。
- `ARC-004`：目标文件冲突时支持逐个询问、全部覆盖、全部跳过和自动重命名。
- `ARC-005`：支持将文件/目录创建为首版声明的压缩格式。
- `ARC-006`：检测并拒绝路径穿越、绝对路径写入、符号链接逃逸和异常展开比例。
- `ARC-007`：损坏、加密或不支持的压缩包必须明确提示，不留下伪成功结果。
- `ARC-008`：取消操作后关闭文件句柄，删除本次未完成的临时文件。

### 3.3 非目标

首版不编辑压缩包内部文件，不承诺修复损坏压缩包，不破解密码。

## 4. T2 Windows 清理

### 4.1 扫描类别

| 类别 | 默认行为 | 说明 |
|---|---|---|
| 用户临时目录 | 默认勾选 | `%TEMP%` 中未被占用且超过 24 小时的内容 |
| Windows 临时目录 | 默认不勾选 | 无权限项目只报告，不提升权限绕过 |
| 回收站 | 默认不勾选 | 单独显示大小并二次确认 |
| 浏览器缓存 | 默认勾选 | Edge、Chrome、Firefox 的纯缓存目录，不删除账号和 Cookie |
| 开发缓存 | 默认不勾选 | NuGet、npm、pnpm、Yarn、Gradle、Maven、pip 等可再生成缓存 |
| 下载目录 | 永不默认勾选 | 只做大文件、重复文件和长期未使用文件建议 |
| 日志/崩溃转储 | 默认勾选 | 用户级日志和系统允许访问的转储文件 |
| 空目录 | 默认不勾选 | 只扫描用户选定范围 |

“插件”不作为可直接删除类别。VS Code、Visual Studio、JetBrains 等插件必须列出名称、版本、路径和最后使用线索，由用户显式卸载或打开对应管理器。

### 4.2 功能要求

- `CLN-001`：扫描前展示范围，扫描时可取消，扫描不得删除任何内容。
- `CLN-002`：结果按类别和目录分组，展示项目数、大小、风险和删除原因。
- `CLN-003`：支持展开到单个文件并取消勾选。
- `CLN-004`：高风险类别默认不勾选，下载目录永不自动删除。
- `CLN-005`：清理前展示最终文件数、大小和不可恢复提示。
- `CLN-006`：默认优先移入回收站；无法进入回收站的项目必须单独确认永久删除。
- `CLN-007`：被占用、无权限或删除失败的文件记录原因，成功和失败数量必须真实。
- `CLN-008`：支持路径白名单，白名单内容不扫描、不建议、不删除。
- `CLN-009`：清理结束生成本地报告，不记录文件内容和隐私数据。

### 4.3 禁止行为

不得删除注册表“垃圾”、驱动、系统组件、用户文档、浏览器账号数据、项目依赖目录或无法证明可再生成的文件。

## 5. T3 文档阅读

### 5.1 正式格式

首版明确支持 25 个后缀：

- 文本/日志：`.txt`、`.log`
- Markdown：`.md`、`.markdown`
- 配置：`.ini`、`.cfg`、`.conf`、`.properties`、`.yaml`、`.yml`、`.toml`
- 开发文档：`.diff`、`.patch`、`.tex`、`.latex`
- 表格数据：`.csv`、`.tsv`
- 结构化数据：`.json`、`.xml`
- Web/电子书/矢量：`.html`、`.htm`、`.epub`、`.svg`、`.svgz`
- 二进制：`.bin`

未知后缀允许用户手动选择“文本查看”或“十六进制查看”，但不计入正式格式数量。

### 5.2 共通要求

- `DOC-001`：支持文件选择、拖放和 Windows“打开方式”。
- `DOC-002`：查看器只读，不修改时间戳之外的源文件内容，不占用文件阻止其他程序使用。
- `DOC-003`：显示文件名、路径、大小、修改时间、识别格式和字符编码。
- `DOC-004`：支持查找、上一个、下一个、匹配数量和复制选中内容。
- `DOC-005`：解析在后台执行，支持取消；关闭文档后释放缓存和文件句柄。
- `DOC-006`：损坏、超限、加密和编码失败必须受控提示，不崩溃、不显示伪内容。

### 5.3 文本和结构化格式

- `DOC-101`：文本支持 UTF-8、UTF-16 LE/BE、GB18030/GBK、Big5，并允许手动切换。
- `DOC-102`：大文本和日志采用分块索引，不把整个文件读入内存。
- `DOC-103`：日志对 ERROR、WARN、DEBUG 等级着色，支持自动换行开关。
- `DOC-104`：Markdown 支持源码/预览、GFM 表格、代码块和受控本地图片。
- `DOC-105`：CSV/TSV 使用虚拟表格，支持引号、转义、内嵌换行和固定表头。
- `DOC-106`：JSON/XML 格式化并支持节点折叠；解析失败回退到索引源码并标明原因。

### 5.4 Web、EPUB 和 SVG

- `DOC-201`：HTML、EPUB、SVG 禁用脚本、网络请求、文件访问、表单提交和自动跳转。
- `DOC-202`：HTML 使用白名单清洗后离线渲染，外部链接只能经用户确认交给默认浏览器。
- `DOC-203`：EPUB 支持章节导航、搜索和本地图片；拒绝 DRM、路径穿越和压缩炸弹。
- `DOC-204`：SVG/SVGZ 支持适应窗口、放大和缩小；不执行脚本和外部资源。

### 5.5 二进制

- `DOC-301`：`.bin` 和手动二进制模式显示偏移、Hex 字节和 ASCII 三栏。
- `DOC-302`：支持跳转偏移、Hex/文本搜索、每行 8/16/32 字节切换。
- `DOC-303`：支持以大小端解释选中数据为整数和浮点数。
- `DOC-304`：二进制查看采用随机读取，打开多 GB 文件不得按文件大小分配内存。
- `DOC-305`：根据 Magic Number 提示常见真实类型，但未经用户操作不切换解析器。

## 6. T4 开发工具

### 6.1 首版工具组

编码转换：Base64、URL、HTML、Unicode、Hex、进制转换。
格式处理：JSON/XML/YAML 格式化与校验、文本 Diff、行排序去重。
加密生成：MD5、SHA-1、SHA-256、SHA-512、HMAC、UUID、ULID、随机密码。
时间文本：Unix 时间戳、时区、正则测试、Cron 解析。
网络开发：HTTP 请求、URL 分解、IP/CIDR、DNS 查询、TCP 端口测试。
文件工具：文件哈希、批量重命名预览、重复文件扫描。

### 6.2 功能要求

- `DEV-001`：所有纯转换工具离线可用，输入不会自动上传。
- `DEV-002`：输入、输出和错误区域边界明确，支持交换、清空、复制和保存。
- `DEV-003`：转换失败显示位置和原因，不清除用户输入。
- `DEV-004`：批量重命名必须先生成完整预览并检测重名，确认后才写入。
- `DEV-005`：HTTP 请求明确显示方法、URL、请求头、正文、状态、响应头、耗时和响应体。
- `DEV-006`：网络功能必须由用户主动执行，并提供超时和取消。
- `DEV-007`：工具内置帮助只说明输入约束和结果含义，不依赖外部网页。

## 7. T5 本地模型

### 7.1 首版能力

| 能力 | 首选运行时 | 首版目标 |
|---|---|---|
| OCR | ONNX Runtime / RapidOCR | 中英文图片文字识别 |
| ASR | sherpa-onnx 或 whisper.cpp | WAV/麦克风转文字 |
| TTS | Piper / sherpa-onnx | 中文文本转 WAV/播放 |
| 图像分类 | ONNX Runtime | 示例小模型验证统一推理链路 |

模型不随主程序强制打包，采用清单管理和用户主动下载/导入。

### 7.2 功能要求

- `AI-001`：模型列表显示能力、语言、版本、文件大小、来源、许可证和校验值。
- `AI-002`：下载支持进度、取消、断点或失败重试，完成后校验 SHA-256。
- `AI-003`：模型按需加载，同一时间默认只驻留一个大型模型。
- `AI-004`：支持释放模型，释放后界面显示内存状态变化。
- `AI-005`：OCR 支持图片选择、预览、识别、复制和保存文本。
- `AI-006`：ASR 支持音频文件和麦克风，显示时长、进度和识别文本。
- `AI-007`：TTS 支持文本、声音选择、生成、播放和保存 WAV。
- `AI-008`：推理失败显示模型、输入和运行时错误，不导致主进程退出。
- `AI-009`：所有模型推理离线完成，未经许可不上传输入和结果。

## 8. 全局要求

- `APP-001`：冷启动后 3 秒内出现可交互主窗口，耗时模块延迟初始化。
- `APP-002`：窗口最小尺寸 1024×700，默认 1280×800；缩放 100%～200% 不遮挡关键操作。
- `APP-003`：五个 Tab 可通过点击和 `Ctrl+1`～`Ctrl+5` 切换。
- `APP-004`：所有长操作展示进度、当前状态和取消入口，UI 线程不得冻结。
- `APP-005`：错误提示包含发生位置、可理解原因和下一步，不只显示“失败”。
- `APP-006`：设置、缓存、日志和模型目录可查看，允许打开目录和清理本应用缓存。
- `APP-007`：日志默认不记录文件正文、HTTP 密钥、模型输入和其他敏感内容。
- `APP-008`：应用卸载不删除用户创建或下载到外部目录的文件。

## 9. 发布门槛

Windows V1 只有同时满足以下条件才能标记完成：

1. 所有实现项在验收矩阵中有对应测试，结果可追溯。
2. `flutter analyze` 无错误。
3. 自动测试全部通过。
4. Windows Release 构建成功，能在当前电脑启动。
5. 五个 Tab 的主流程完成一次人工验收。
6. 清理、解压、文档和模型使用专用测试数据，不以真实重要文件做首次验证。
