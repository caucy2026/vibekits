# Harness 远程协助：交互与实现契约

## 远程协助开关、ID、密码与历史

应用每次启动时远程协助必须为关闭状态，但注册后的独立 Harness ID 始终可见、可复制。关闭态只允许读取本机身份状态，不开放配对端口、正式项目/会话端口，也不自动恢复历史连接。用户明确打开后，才可接受连接或输入对方 ID 主动协助。

首次配对的默认密码为 `12345678`，本机可修改为 8～64 字符。密码不得写入连接历史、普通配置、日志、遥测或协议帧；请求只携带用密码作为密钥、同时绑定随机 nonce、调用方 routingId/deviceId/证书摘要、工作区集合和操作集合的 HMAC-SHA256 证明。证明错误必须在弹出授权前返回 `PAIRING_BAD_PASSWORD`。密码通过后仍必须执行原生连接授权、证书核对和最小权限确认，不能用密码替代证书固定或用户授权。

连接历史最多保留 100 个已明确记住的设备，展示 routingId、直连/中继、授权工作区数量和最近连接时间；选择历史仅填入目标并允许使用已固定证书重连，删除历史必须删除本机证书与授权记录。默认路径先尝试 RustDesk P2P/打洞，失败自动使用 HBBR，强制中继只用于诊断和验收。

状态：实现与验收共同基线，2026-09-08。已实现项仍须以开发日志和验收记录中的证据为准，本文件本身不是发布声明。

## 1. 产品边界

执行端保存项目、文件、会话、模型凭据并运行任务；控制端显示同一官方工作区，提交操作、接收执行端事实。不发送桌面画面，不在控制端把远端文件路径当本地路径运行。Mac/Windows 共用 Flutter 控制逻辑与官方 Web UI。Android 不启动桌面 Node 运行时，但既可作为控制端，也可通过同进程 adapter 把本机 Harness 的权威项目、会话、模型凭据、运行与停止状态作为执行端发布；不得另建影子会话库或伪造桌面 DSH。

本地工作不依赖远程服务。关闭远程协助不能破坏本地会话、插件、MCP、系统凭据与工作区。

RustDesk 只是网络运输源码供应方，不是外部运行时。VibeKits 自行编译并携带寻址、P2P 打洞和 HBBR 中继组件；上层只传输 Harness 结构化消息。不得包含或暴露桌面图像、远程输入、剪贴板、文件传输、终端或任意端口转发接口。正式包不得依赖已安装的 RustDesk/KEMI App 或插件。

## 2. 页面与入口

Harness 顶部增加“远程协助”，不替换官方侧栏、插件市场或项目菜单。打开管理面板：

| 区域 | 内容及动作 |
|---|---|
| 本机身份 | HBBS 确认的数字 Harness ID、VH 证书核对码、复制、服务状态；未注册不显示可连接 ID |
| 连接设备 | 输入对方数字 Harness ID、连接；局域网发现列表属于候选信息，不等于已授权 |
| 授权请求 | 对方名称与 ID、证书核对信息、请求项目、查看/控制范围、允许/拒绝、是否记住授权 |
| 已授权设备 | 最近连接、项目权限、撤销授权；不显示私钥或模型凭据 |
| 活动连接 | 调用方、直连/中继、连接时长、延迟、活动任务、断开与终止任务入口 |

首次配对必须有执行端明确同意。已保存且未撤销的相同身份/范围不重复弹授权；新增项目或扩大权限需重新同意。

连接后在同一工作区顶部显示“远程 · 设备名称/ID · 直连或中继 · 延迟”。左侧仍为官方项目/会话，中间为官方消息/工具轨迹，底部保留原输入方式。非选中运行会话显示转圈，只有选中项显示操作菜单；草稿按设备 ID + workspaceId + sessionId 隔离。任务状态和连接状态分开显示，断线不把任务改为空闲。

授权面板必须适配紧凑窗口、Windows 缩放和 Android 旋转/副屏安全区：正文使用有最大高度的单一滚动区域；有时限的首次证书“确认/拒绝”必须排在连接历史和已配对设备之前，不能仅在 framebuffer 可见却落在应用可触控区域之外。已配对连接出现时展示调用方、connectionId 和“强制断开”；没有协议握手/心跳时不得因为发现了中继就显示已连接。

## 3. 两套状态机，不能混用

连接状态：断开 → 寻址 → 连接中 → 等待授权（首次）→ 校验身份 → 同步中 → 已连接。

- 只有证书固定校验和授权均通过，且当前连接的快照/历史应用成功，才能“已连接”。
- 桌面原生 helper 的进程已启动、内部 sender 已建立或本地端口转发已登记都不是成功证据。只有 RustDesk 权威连接状态进入 `Connected` 后才允许开放 `127.0.0.1` 应用协议端口，并以单行 JSON 输出 `state=transport_connected`；超时/拒绝必须非零退出并提供结构化错误。Flutter 在收到该状态前不得创建可用 tunnel lease。
- 连接失效进入“重连中”，保留内容但标记过期；不能继续提交新命令。恢复后重新校验、补齐状态。
- 用户主动断开或撤权后，旧网络回调不得重新把 UI 改为已连接。
- 未注册、ID 不存在、超时、证书变化、权限拒绝分别显示原因；不得静默改用远程桌面 ID。

任务状态：待提交 → 已送达/已接受 → 运行/工具运行/等待审批 → 完成/失败；停止操作进入“停止请求中”，执行端确认终态后才“已停止”。发送超时为“结果待确认”，不是失败重发许可。客户端本地取消 HTTP 请求不算停止远端任务。

“断开连接”只关闭观察与控制通道，不隐式杀死执行端本地任务；按钮旁明确说明任务继续。用户选择“停止我的远程任务并断开”时，逐项提交停止、核验终态后断开；未确认的任务标记未知，不影响其他调用方或本地任务。撤权立即拒绝新请求；是否终止此前任务用独立明确动作处理。

## 4. 身份、寻址、配对

用户输入的 ID 是独立 Harness 网络引擎向 HBBS 注册、由 RegisterPkResponse=OK 确认的十位数字 routingId；候选 ID 在服务器确认前不可复制、不可显示在线。ID_EXISTS 时生成新候选重试，UUID_MISMATCH/INVALID_ID_FORMAT/NOT_SUPPORT 等分别显示原因，不降级冒用远程办公 ID。

VibeKits 包内网络引擎必须提供三个无 shell 拼接的本地控制命令：

- `--vibekits-harness-service`：在独立 `VibekitsHarness` 配置/IPC 命名空间启动注册、打洞和中继服务，不打开桌面共享窗口；
- `--vibekits-harness-get-id`：读取该命名空间的候选数字 ID，仅供诊断，不能单独证明可呼叫；
- `--vibekits-harness-status`：通过独立服务 IPC 同时读取 `OnlineStatus`、`keyConfirmed` 和服务端实际 ID，输出单个 JSON 对象。

状态响应固定字段为 `routingId:string|null`、`callable:boolean`、`rendezvousOnline:boolean`、`registrationKeyConfirmed:boolean`、`state:string`。`callable=true` 的充分必要条件是：ID 为 6～16 位纯数字、至少一个 HBBS 在线且注册密钥已确认。`state` 至少支持 `registered`、`registration_pending`、`offline`、`invalid_routing_id`；未知状态必须按不可呼叫处理。UI 只有在 `callable=true` 时启用复制本机 ID 和接受连接，绝不根据进程存在、候选 ID 或旧缓存猜测在线。

建立数据通道前必须完成 `hello` 协商：固定协议名、双方支持版本区间、服务器选择版本、connectionId 与能力表；不兼容立即关闭。连接后以 connectionId 绑定心跳，心跳或读状态超时只把连接标为过期，不把远端任务伪报为空闲。重新连接必须重新协商并重新取得官方项目/会话快照，旧 generation 的迟到回调全部丢弃。

执行端网络引擎必须运行无桌面的授权管理器，并通过同用户 IPC 向 VibeKits 提供等待授权的 connectionId、调用方 ID 和调用方名称。首次连接只允许用户在 VibeKits 明确“允许本次连接”或“拒绝”；不得使用产品默认固定密码。网络身份仅接受目标为远端 Harness 本机回环监听端口的 PORT_FORWARD，禁止桌面画面、文件、终端和任意 LAN 地址转发。

现有 VH 标识由独立证书派生，仅用于首次配对的端到端身份核对，不是服务器路由 ID。持久关系是 routingId ↔ RustDesk 注册公钥 ↔ Harness TLS 证书指纹；显示 ID、服务器寻址 ID、TLS 证书指纹不得互相冒充。Harness 网络引擎使用独立 app-name/config 路径、ID、keypair、密码和历史库，绝不读写 KEMI 远程办公配置。

当前 RustDesk rendezvous.proto 没有 Harness ConnType。第一兼容阶段用独立身份的加密 PORT_FORWARD 作为原始字节承载，再在隧道内执行 Harness 双向证书认证、授权及协议协商；不能依赖已经建立的桌面会话。后续如新增 HARNESS_REMOTE ConnType，必须同时升级客户端、hbbs/hbbr并完成旧服务端拒绝/回退验证，不直接变更线上远程办公服务。

远程协助没有全产品默认密码。首次连接以执行端确认与双端证书核对码授权；可选无人值守密码属于用户单独设置的设备凭据，只保存慢哈希及随机盐，限速/锁定并可撤销。RustDesk 配置中的桌面密码不能继承到 Harness。

发现包只含产品标识、协议版本、候选 ID、可达性等非敏感元数据。未知候选不能直接得到项目、会话或调用能力。配对握手使用有过期时间的一次性挑战，绑定双方身份、会话随机数和授权范围，抵抗重放；校验码须覆盖完整握手摘要。已配对连接严格固定证书，身份变更需用户重新确认。

当前实现固定两个执行端回环端口：`32145` 只承载首次公开证书交换，`32146` 只承载配对后的 mTLS Harness 协议。两者都只能由独立 RustDesk Harness 身份的回环 PORT_FORWARD 到达。配对请求必须写明精确 workspaceId 和 operation 集合；执行端批准前再次核对原生授权连接的 routingId，批准范围不得超过请求范围。双方只持久化公开证书及 SHA-256，私钥始终留在平台凭据存储。关闭窗口、连接失败或主动断开必须关闭本次受管 tunnel lease。

## 5. 官方 UI 兼容接入

新增远程 transport adapter，保留官方 client-request/server-response/server-request/client-response 数据模型。不要针对 DOM 改写聊天或裁剪插件市场。

控制端加载受信任的匹配版本官方静态 UI，通过受限桥接发送远端操作。不得加载任意远端网页后授予本机文件、进程、凭据桥能力。官方 UI/协议版本不兼容时阻止控制，显示需要升级，不能带病转发。

每项官方操作建立映射表：方法、参数 schema、执行位置、授权范围、是否有副作用、回执含义、恢复方式、测试。当前 session 白名单并非完整操作集合。必须盘点 workspace/session 管理、审批回复、文件差异/附件、插件管理、模型选择与设置等调用。

凭据保持执行端安全存储；远程客户端不读取明文 key。插件安装与主机级设置属于单独高权限范围，不能由普通项目控制授权顺带获得。文件选择框明确操作的是哪台设备，上传/下载另有显式权限与进度。

## 6. 同步与命令可靠性

命令使用 peerId + commandId 去重，内容摘要绑定项目/会话/操作。执行前持久化 claim，回执持久化后返回。重启 pending/unknown 不自动重发，由任务/历史查询核实。每次取缓存回执也要重新授权。

事件使用 epoch + sequence，丢序/重连触发快照与所选会话历史重载。先订阅并记录游标，再加载快照，重放期间事件；UI 应用成功才推进游标。快照和授权变更发生竞争时重新检查范围。全量恢复不能只加载项目列表而漏掉聊天历史。

大结果分页/按需展开；设帧大小、队列、并发、磁盘账本上限。达到上限显式报错，不丢记录后继续假装可靠。日志脱敏，证据导出不包含模型密钥、配对秘密或不在范围内的项目。

## 7. 实现顺序与门禁

1. 启动迁移故障修复：重复启动与旧配置回归，保留用户内容。
2. 连接状态机与身份存储：身份不漂移，旧回调无效，断线不显示空闲。
3. 配对/权限存储与面板：拒绝、超时、撤权、多调用方隔离。
4. 官方 API 操作盘点及远程 UI transport：先只读项目/历史，再发送/继续/停止/审批，最后文件与插件。
5. LAN 真双机闭环：本机执行、63 控制；不以模拟 HTTP 服务代替真实 Harness。
6. 独立 ID 直连/中继：完成注册绑定与强制中继验收。
7. Mac ARM/Intel macOS 12+ 与 Windows 回归、签名打包、操作手册、发布。

## 8. 必留验收证据

每项记录端点版本/源码、连接方式、项目/会话脱敏标识、commandId、epoch/sequence、两端结果与截图。至少覆盖：首次拒绝/允许、记住授权、越权拒绝、晚启动发现、同名项目、并行会话、独立草稿、工具后继续分析、三阶段停止、断线时提交、重启去重、撤权、强制中继、插件原交互及本地 MCP 回归。

交付条件：用户按文档从打开页面开始，独立完成“输入 ID → 授权 → 选项目 → 发送 → 查看过程/结果 → 停止/断开”。任何一步依赖开发者后台手工接线，就不能宣称远程协助已完成。
