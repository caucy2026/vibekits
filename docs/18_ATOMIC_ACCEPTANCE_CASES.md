## 1. 动作书写规则

每个用例只能覆盖一个场景和一个二值结论。需要状态切换时把动作写成编号序列，执行人不得自行补步骤、重试、修改输入或解释结果。`${参数}` 用例必须为参数表中的每个值生成独立记录，例如 `ARC-102-A[zip]`；一个参数失败时只记录该参数失败，不得写“部分通过”。

| 字段 | 强制写法 |
|---|---|
| 前置条件 | 固定 Build ID、平台、账号/设备、初始文件树、网络和设置；任何一项不同即记“阻塞”，不得继续 |
| 动作 | 写明页面、控件可见文字和完整编号序列；禁止省略中间步骤，也禁止“尝试、检查一下、正常操作、按需”等词 |
| 唯一预期 | 使用精确值、文件哈希、进程数、时间上限或明确 UI 文字；禁止“正常、友好、流畅、完整、基本可用” |
| 失败判定 | 只要唯一预期不满足、出现范围外副作用或需要执行人补救，即为失败 |
| 证据 | 固定截图/录屏/日志/目录树/哈希/系统进程或网络快照；没有证据不得改为通过 |

通用数值口径：

- “界面未阻塞”：测试任务运行时，应用内 100ms 计时器连续 20 次的最大延迟不超过 300ms；窗口拖动和切页在 1 秒内出现视觉响应。
- “取消完成”：点击取消后 3 秒内进入“已取消”，5 秒后相关子进程数为 0、测试输出目录无 `.part`/临时文件、设备/文件句柄可由第二个进程重新打开。
- “不保存敏感值”：使用唯一金丝雀 `VK_SECRET_20260817_7f3a`；在设置 JSON、应用日志、验收报告和 Git 工作树全文搜索结果必须为 0。
- “一键复用”：远程工作区出现会话列表和可点击主按钮后，只允许点击目标记录一次，再点击“连接”一次；中间不得聚焦或修改任何输入框。
- “无范围外修改”：测试前后对允许目录之外做文件树、注册表/Git 配置或网络配置 Diff，差异必须为 0。

## 7. 状态更新规则

1. 首次执行前状态固定为“未执行”；没有设备/账号/证书时写“阻塞 + 缺少的唯一条件”，不得写“基本通过”。
2. 一个表格行只允许“通过、失败、阻塞、不适用”四个终态；“部分通过”必须拆行。
3. 同一用例不得同时验证修复前和修复后；修复后生成新 Build ID 并创建复测记录。
4. 任一 P0/P1 缺陷使所属发布批次不能关闭；不得用其他用例的通过数抵消。
5. `17_RELEASE_COMPLETION_CHECKLIST.md` 中某功能只有在其全部原子用例通过后才能从 `🔴/🟡` 改为 `✅`。
