# MCP 全局信誉、长期记忆与 Harness 路由验收规范

状态：编码完成，自动化与 macOS Release 门禁通过；等待生产环境首次真实调用后补充带分数徽标的实机截图。本文是 MCP 工具排序、长期评分、UI 标识和 Harness 调用策略的唯一验收口径。

## 1. 目标

VibeKits 必须长期记住 MCP 工具是否好用。评分跨项目、跨会话、跨 App 重启保留，并同时提供给 Harness 规划器和 MCP 列表 UI。它不是临时调用日志，也不能只记录“调用过”；必须能让错误多、超时多、任务完成度低或被用户标记为垃圾的工具自动降权。

评分用于候选排序和解释，不替代在线状态、证书校验、工具目录校验、参数 Schema、风险审批或人工明确选择。

## 2. 固定路由顺序

Harness 查找同类能力时必须使用以下不可被评分跨越的层级顺序：

1. 本机 VibeKits MCP（`app`，进程内执行）；
2. 本地其他进程 MCP（`local`）；
3. 局域网 MCP（`lan`）。

只有同一层内的同类候选工具才按全局信誉分从高到低排序。低分或 `garbage` 工具不得从目录消失；人工仍可查看并明确指定。局域网工具即使高分，也不能越过存在且适用的本机或本地候选。

## 3. 全局评分主键

评分主键是规范化工具类型 `toolName.toLowerCase()`，不是设备实例 ID。

例如多台 KEMI 设备都提供 `kemi.files.send`，所有实例必须显示并使用同一个全局分数。任一实例调用的成功、失败、超时和完成质量都会加权更新 `kemi.files.send` 的全局长期记忆。

以下数据仍按设备实例独立判断，不能混入工具类型分数：

- 在线/离线；
- TLS 证书和实例指纹；
- LMCP 目录版本与能力摘要；
- 当前端点和网络可达性；
- 单次调用延迟与当前会话审批。

因此路由决策是“层级 → 工具类型全局分 → 当前实例健康状态”，而不是把一台离线设备的高分当成可调用证据。

## 4. 长期记忆字段

每个工具类型至少持久化：

- 自动完成质量 EWMA（0–1）；
- 总调用次数、成功次数、失败次数；
- 连续失败次数；
- 平均耗时；
- 可选人工评分 0–5；
- 最后更新时间；
- 计算后的 0–100 全局分与等级。

新工具初始分为 60，但在没有调用历史和人工评分时 UI 不显示任何评分标识，保持现有界面。

等级：

- 85–100：`excellent`；
- 70–84：`good`；
- 50–69：`neutral`；
- 30–49：`poor`；
- 0–29：`garbage`。

## 5. 自动加权与降权

自动质量使用近期调用占 25% 的 EWMA；首次真实调用直接采用该次质量。连续失败每次额外扣 7 分，成功后清零连续失败。

调用质量建议值：

- 明确成功且任务完成：1.0；
- 返回部分结果、`final=false`、`completed=false` 或 `verified=false`：0.45；
- `isError=true`、`ok=false`、`success=false`、结构化 error、异常或超时：0；
- 用户拒绝审批：不评价工具质量，不得因用户拒绝而降分。

人工评分为 0–5。最终分数按人工 65%、自动 35% 合成，再扣连续失败惩罚。人工 0 分等价于“垃圾/强降权”，但不删除工具。人工评分后仍继续收集自动历史。

## 6. Harness 可见能力

`vibekits.mcp.catalog_list` 必须返回：

- 固定 `tierOrder = [app, local, lan]`；
- 每个工具的 `reputation.score/grade`；
- 有无人工评分、调用数、成功/失败、连续失败和平均耗时；
- 明确文字规则：评分不得绕过风险审批。

Harness 还必须有只读“查看全局评分”和写入“人工评分”的正式 MCP 工具，禁止靠猜 JSON 文件。人工评分工具属于本地设置写入，必须经过现有写操作审批。

## 7. MCP 列表 UI

- 从未调用且从未人工评分：不显示徽标，保持当前样式；
- 有调用历史：显示 `分数 + 等级`；
- 有人工评分：同时显示人工 0–5 分；
- 人工 0 分或最终分小于 30：显示“垃圾/已降权”警示；
- 同名工具出现在多台设备时显示相同全局分；
- UI 标识不能替代“可调用/仅发现”、在线状态或权限状态。

## 8. 安全与隐私

- 信誉文件只记录工具名、计数、质量、耗时和评分；不得记录参数、文件内容、Token、密码、证书私钥或远端返回正文；
- 写入采用临时文件后原子替换；损坏或超大文件必须安全回退为空记忆；
- 评分不能使未通过 LMCP/2、TLS pinning、catalog digest 或权限校验的节点变成可调用；
- 文件发送、写入、设备控制等副作用仍逐次走原有风险审批。

## 9. 验收用例

1. 新工具目录不出现评分徽标，Harness 得到中性初始分 60。
2. 同名工具由三台设备提供；其中任一实例成功后，三台 UI 和目录显示相同分数。
3. 同类工具连续失败三次后分数和排序下降，成功后连续失败计数清零但历史不丢失。
4. 远端返回 HTTP 成功但 MCP `isError=true`，必须按失败计分。
5. `final=false` 或 `verified=false` 按部分完成降权，不能算满分成功。
6. 用户拒绝权限审批不降工具分。
7. 人工评分 0 后显示“垃圾/已降权”，但仍能从目录查看并人工指定。
8. 重启 App、切换项目和新建会话后评分保持。
9. 同类工具同时存在 app/local/lan 时，即使 lan 分更高，Harness 仍按 app → local → lan。
10. 评分文件中不得出现调用参数、路径内容、Token、密码或返回正文。
11. 无效评分、空工具名、损坏评分文件和并发写入均不能破坏现有目录或调用。
12. Flutter analyze、领域测试、Harness 目录/调用测试和 macOS Release 构建全部通过。

## 10. 完成定义

只有领域存储、自动采样、目录排序、Harness 查看/评分工具、UI 徽标、持久化回归和 Release 实机验证全部完成，才能把本文状态改为“已验收”。仅写文档、仅显示分数或仅记录调用日志均不算完成。
