本文件是从 v1.8.0 开始唯一的当前执行与验收清单。`04_WINDOWS_ACCEPTANCE_MATRIX.md`、`07_WINDOWS_UI_ACCEPTANCE_MATRIX.md` 保留为早期详细用例库，其中未更新的“未实现”不再代表当前进度；产品范围仍以 `00_PRODUCT_REQUIREMENTS.md` 为准。

## 1. 状态和关闭规则

- `✅ 已闭环`：代码、错误/取消/释放、自动测试、Windows Release、文档、版本和双远端备份均有证据。
- `🔵 软件基线`：固定版本的代码、自动测试和 Release 已验证；若表中指向 E 用例，仍必须补真实设备/服务证据才能升级为 `✅`。
- `🟡 待实证`：主路径代码存在，但缺真实设备、真实服务或目标平台证据，不能算最终完成。
- `🔴 待研发`：用户要求的完整流程仍缺实现。
- `⏸ 后续增强`：不阻塞当前极简主产品发布，完成 P0 后再排期。

每个 `🔴` 项必须按同一顺序关闭：失败夹具 → 实现 → 单元/Widget → 错误/取消/资源释放 → 模块回归 → 全量 Analyze/Test → 目标平台 Release → 人工体验与性能 → 文档/版本 → 本地 `backup` 与 GitHub `cloud`。

## 7. 明确不做或不以错误方式实现

- 不复制完整 Zed/Geany/数据库客户端；只建设轻量高频流程。
- 不复制 FastGithub 的中间人证书或不透明代理；只做安全、可审计、可恢复的网络配置。
- 不自研 SSH/RDP/VNC 密码学和协议栈；调用系统成熟实现或经过许可证/安全评审的库。
- 不因扩展名可路由就宣称格式已支持；必须有真解码/解压夹具。
- 不把 ASR/TTS/VAD、模型清单和低频微工具重新放回首页。
