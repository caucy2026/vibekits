# Vibekits 智能清理产品与架构准则

日期：2026-08-20  
状态：生效，后续清理研发必须遵守

## 1. 产品目标

清理模块不是“按后缀删文件”，而是回答四个用户问题：谁占用了空间、这些占用是否合理、哪些内容可以安全释放、释放后是否可恢复。目标是在不牺牲透明度和可恢复性的前提下，达到主流安全软件的一键效率，并在开发缓存解释、跨工具联动和 Harness 调用方面超过传统清理工具。

## 2. 竞品结论

360 的有效工作模型不是单个扫描器，而是“一键清理 + 软件清理规则 + 大文件/下载 + 不常用软件 + 插件/痕迹/注册表 + 卸载残留 + C 盘搬家 + 启动优化”的任务组合。Windows Storage Sense 的优势是系统认可、计划执行和低风险；BleachBit/CleanerML 的优势是数据驱动规则；dua-cli 的优势是快速定位大目录。

Vibekits 已有的差异化基础是：多磁盘、开发工具缓存、真实占用分析、回收站优先、后台取消、清理审计和 Harness 工具调用。当前主要差距是规则覆盖与更新机制、软件身份归属、增量索引、不常用软件的可靠证据、卸载残留、锁定进程解释，以及用户入口仍偏技术分类。

## 3. 唯一用户入口模型

扫描结果固定重组为五个任务入口，底层类别仍保留用于规则和审计：

| 入口 | 用户任务 | 首版数据来源 | 删除规则 |
|---|---|---|---|
| 推荐清理 | 最少操作释放可再生内容 | 安全级规则且默认可选 | 可批量选择，回收站优先 |
| 软件缓存 | 看清每个软件的缓存/日志 | 浏览器、应用、开发、插件规则 | 按软件/类别复核；高风险逐项选择 |
| 大文件 / 下载 | 定位最值得处理的文件 | 下载建议、重复文件；后续接快速大文件索引 | 默认不选，不因“大”自动删除 |
| 不常用软件 | 卸载确实长期不用的软件 | 已安装应用清单；后续增加可靠使用证据 | 只调用官方卸载器，不直接删安装目录 |
| 深度清理 | 专家复核系统和未知项 | 系统管理、未知日志、残留和高风险规则 | 默认不选，显示影响和证据 |

在使用证据尚不可靠时，界面必须写“已安装软件”，不得把所有应用伪称为“不常用”。在大文件索引未完成前，也不得宣称已经完成全盘极速大文件扫描。

## 4. 版本化规则数据库

规则库使用随包 JSON 数据，核心扫描器不再为每个软件修改代码。数据库包含 `schemaVersion`、`catalogVersion` 和规则数组。每条规则必须包含：稳定 ID、平台、路径模板、类别、风险、默认启用、年龄、扫描深度、条目上限、清理动作、影响说明和来源。

安全合同：

- 规则只描述数据，不允许命令、脚本、注册表写入或任意可执行文件。
- 当前唯一删除动作是 `recycle`；路径不存在时跳过；畸形规则单条拒绝，不能使内置安全规则失效。
- `safe` 才能进入批量推荐；`cautious` 和 `systemManaged` 必须默认不选并逐项确认。
- 所有规则有最大深度和条目上限；未知环境变量、重复 ID、未知类别或无影响说明均拒绝。
- 在线更新是后续能力，启用前必须增加签名、哈希、原子回滚和离线最后可用版本；当前版本只读取随包规则，不联网阻塞启动。

## 5. 下一阶段技术路线

1. 软件身份层：将安装清单、Program Files、ProgramData、AppData、服务和发布者证据合并为同一软件实体。
2. 快速索引层：Windows 优先使用 MFT/USN 增量索引，失败时回退有界目录扫描；macOS 使用平台文件元数据能力并保留回退。
3. 占用进程层：用 Restart Manager 解释“为什么删不掉”，只在用户确认后请求关闭相关应用。
4. 安全删除层：Windows 统一 IFileOperation/回收站语义；永久删除只对明确可再生缓存开放。
5. 使用证据层：结合卸载信息、应用启动记录和文件最近活动，给出“可能不常用”及证据，不做无依据判断。
6. 趋势层：本地记录软件缓存增长速度，优先提示异常增长的大日志；不上传文件名或内容。
7. Harness 层：先生成清理计划和解释，删除仍走同一审批、规则、日志和回收站服务。

## 6. 验收指标

- 首屏入口点击到可见反馈不超过 100 ms；规则发现和磁盘 I/O 不在 UI Isolate。
- 规则解析错误不会导致页面不可用；同一候选不因内置/外部规则重复出现。
- 高风险项不被“一键全选”；每项显示风险、原因、影响、路径、大小和来源。
- 扫描、分析、删除均可取消；取消后保留准确的已完成结果。
- 每次删除都能由工具真实日志反查，并能删除日志；日志不含凭据或文件内容。
- 清理完成显示本次/累计释放量、磁盘总量/已用/剩余及成功/跳过/失败。

## 7. 参考实现与边界

- 360 安全卫士功能模型用于产品对标，不复制其专有代码或视觉资产。
- BleachBit/CleanerML、dua-cli 等仅用于理解数据规则和磁盘分析模式；引入代码前必须单独核对许可证、版本和供应链。
- Windows 系统目录、组件存储、驱动、注册表和安装缓存不允许因规则命中直接永久删除，优先调用系统官方维护或卸载入口。
