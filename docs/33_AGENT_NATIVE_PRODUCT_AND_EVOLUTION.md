# Vibekits 智能体原生产品与持续演进规范

版本：1.0  
生效日期：2026-08-23

## 1. 产品简介

Vibekits 是一个智能体原生的开发者工具工作台。智能体负责理解目标、规划步骤和解释结果，本地工具负责读取文件、连接设备、执行协议、计算指标和留下真实证据。两者共享同一个任务上下文，不再是聊天窗口与工具箱之间的人工复制粘贴。

用户只需要描述任务或拖入对象。Vibekits 负责选择能力、补齐必要参数、请求合适权限、在后台执行、记录脱敏日志，并把结构化结果交给智能体继续处理。产品默认本地优先、无广告、隐私优先，面向 Windows、macOS 和 Android 持续发布。

## 2. 每项能力的智能体验收

每个工具必须逐项通过以下六层，缺少任何一层只能标记“部分可用”：

1. **发现**：MCP `tools/list` 能看到稳定名称、用途、禁用场景和输入 Schema。
2. **选择**：自然语言评测中，智能体选择正确工具；缺参数时询问，不猜路径、设备或凭据。
3. **执行**：调用 UI 共用的真实领域服务，耗时工作不占 UI 线程，支持超时和取消。
4. **证据**：工具自身记录目标、脱敏参数、耗时、状态和有界结果，不由聊天层伪造成功。
5. **协作**：结果形成结构化对象，能继续进入最多三个高价值下一步。
6. **环境**：硬件、远程服务和系统修改能力必须补真实环境证据，模拟测试不能冒充实证。

固定评测语句至少覆盖：正常请求、缺参数、错误参数、拒绝授权、执行失败、取消和连续工具协作。发布报告分别统计领域测试、Harness 直接调用、模型自动选择和真实环境四种通过率，不得合并成一个模糊的“已测试”。

## 3. 音频协作范例

“分析这段声音哪个地方引入了谐波，哪个地方噪声最大”必须形成：

```text
文件/拖入对象
  → 音频格式识别
  → 有界时间窗 DSP 分析
  → 谐波与噪声热点时间段
  → Harness 结合波形、频谱和上下文解释
  → 点击时间段试听 / 导出报告 / 与另一文件 Diff
```

工具必须返回时间范围、THD、THD+N、SNR、噪声底、基频、可信度和测量限制。复杂语音与音乐不能把稳态单音估算伪装为实验室结论。

## 4. Harness 持续演进机制

Vibekits 客户端禁止直接安装 npm `latest`。Harness 处于开发预览期，上游明确可能发生破坏性变更，而且 Vibekits 还包含 MCP、审批、中文体验和生命周期适配。正确演进流程为：

1. GitHub 后台每周查询官方 npm registry，比较当前固定版本。
2. 发现新版后，在隔离目录安装精确版本，校验包名、版本、许可证、CLI 入口和依赖。
3. 应用 Vibekits 兼容补丁并执行 CLI 冒烟；失败只生成报告，不影响用户版本。
4. 自动创建升级评审工单，补跑 Web 启动、模型、会话、权限、MCP 全能力、停止和资源释放测试。
5. 通过后生成固定版本、依赖锁、资产哈希和 SBOM，进入 Windows、macOS、Android 候选 Release。
6. 小比例灰度，监控启动失败、工具错误和回滚率；超过阈值停止发布。
7. 客户端只升级到 Vibekits 签名发布版本，并保留上一套运行时以便一键回滚。

后台自动完成“发现、隔离准备、兼容冒烟和工单”，但不得自动越过发布门禁。模型、工具协议或官方 UI 发生变化时，必须同步更新自然语言能力评测，避免只升级界面而工具失联。

## 5. 当前版本审计结论

- 当前固定 `@deepseek-ai/dsh@0.1.0-rc.7`，官方 npm 在 2026-08-23 已发布 `0.1.1-rc.2`。
- 当前高频测试中，Harness 工具桥、MCP Server、ADB 语义工具、SQLite、SSH/SFTP、OCR、文件、API、Git、代理/虚拟机合同和音频算法均有自动证据。
- 真正模型发起 MCP 并拿到最终回复的端到端测试已通过，但目前覆盖的模型自动选择场景仍少，不能代表全部工具。
- 音频已增加时间轴谐波和噪声热点结果；仍需在可控扬声器、声卡和真实录音夹具上补硬件实证。

## 6. 发布门禁

- 新增能力没有模型选择评测，不得写“智能体可自动使用”。
- 新 Harness 候选没有全能力回归，不得替换客户端固定版本。
- 自动更新不得携带 API Key、会话、工作区或普通日志。
- 无网络时继续使用最后验证通过的内置运行时，其他 APP 功能不受更新检查影响。
- 更新失败必须原子回滚，不能留下半套 Node/npm 目录或后台进程。

## 7. APP 自身迭代接口

Harness 通过 `vibekits.project.iteration_inspect` 读取工作区、版本、Git 状态和目标平台，再通过 `vibekits.project.build` 执行固定参数的 Analyze、能力目录/桥接合同测试和目标平台 Release 构建。新增工具仍以 `ToolSpec + VibekitsHarnessToolBridge handler` 为唯一注册源，能力目录和 MCP `tools/list` 自动同步，不维护第二份手工接口表。

自迭代只允许修改用户明确选择的工作区并生成候选产物。它不得自行覆盖正在运行的 APP、安装 APK、签名、推送远端或发布渠道；这些操作必须经过独立门禁与用户确认。构建失败返回具体阶段、退出码和有界输出，不能把“代码已生成”报告为升级成功。
