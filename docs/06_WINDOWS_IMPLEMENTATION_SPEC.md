# Vibekits Windows V1 模块实现规格

> 本文件保留 Windows 实现合同。新增领域代码必须同时符合 [统一产品需求](00_PRODUCT_REQUIREMENTS.md)、[macOS 平台实现附件](11_MACOS_PLATFORM_SPEC.md)和[统一验收矩阵](12_UNIFIED_ACCEPTANCE_MATRIX.md)，通过平台接口隔离系统差异。

版本：0.1
状态：交付给开发者的实现合同
平台：Windows 10 22H2、Windows 11，x64
技术路线：Flutter UI + Windows 原生能力 + C/C++ 通用原生层

## 1. 文档用途

本文规定 Windows V1 五个模块的实现边界、处理阶段、输入输出、状态、限制和交付物。开发者可以调整内部类名和文件拆分，但不得改变 [00_WINDOWS_PRODUCT_SPEC.md](00_WINDOWS_PRODUCT_SPEC.md) 中的产品行为，也不得绕过 [05_WINDOWS_ACCEPTANCE_PROCESS.md](05_WINDOWS_ACCEPTANCE_PROCESS.md) 的验收规则。

界面以 [01_WINDOWS_UI_LAYOUT.md](01_WINDOWS_UI_LAYOUT.md) 为准，底层分层以 [02_TECHNICAL_ARCHITECTURE.md](02_TECHNICAL_ARCHITECTURE.md) 为准。

## 2. 全模块共通合同

### 2.1 模块边界

每个模块至少包含以下职责，具体文件名由实现者决定：

| 职责 | 输入 | 输出 | 禁止行为 |
|---|---|---|---|
| Presentation | 用户动作、只读状态 | 页面、对话框、通知 | 直接读写文件、调用 FFI 或 HTTP |
| Application | 用例请求、取消令牌 | 进度、结果、领域错误 | 依赖具体 UI 控件 |
| Domain | 领域值和规则 | 计划、判定、纯计算结果 | 访问系统 API |
| Infrastructure | 抽象接口请求 | 文件、数据库、网络实现 | 把平台错误原样显示给用户 |
| Native/Platform | 版本化请求 | 进度事件、结果、错误码 | 持有 Dart/Flutter 对象 |

### 2.2 任务状态

所有预计超过 200ms 的动作必须遵循：

```text
idle -> preparing -> running -> succeeded
                         |-> failed
                         |-> cancelling -> cancelled
```

规则：

1. 一个任务只进入一次终态；终态为 `succeeded`、`failed` 或 `cancelled`。
2. `cancelled` 不是 `failed`，但必须报告已产生的输出和回滚结果。
3. 进度事件最多每 100ms 推送一次，最终事件不节流。
4. 页面关闭不等于忽略任务；只读任务停止，写入任务按产品规则确认后停止或转入任务面板。
5. 取消后必须关闭句柄、停止回调并清理本任务临时目录。

### 2.3 进度合同

| 字段 | 必需 | 说明 |
|---|---|---|
| `taskId` | 是 | 本次运行唯一 ID |
| `stage` | 是 | `prepare/scan/process/finalize` 等稳定阶段 |
| `currentItem` | 否 | 脱敏后的当前文件名或步骤 |
| `completedUnits` | 是 | 已处理单位，不得倒退 |
| `totalUnits` | 否 | 未知时为空，不填假值 |
| `processedBytes` | 否 | 已处理字节数 |
| `totalBytes` | 否 | 可确定时提供 |
| `speedBytesPerSecond` | 否 | 至少 1 秒窗口的平滑值 |
| `messageKey` | 是 | 可本地化状态键，不传完整隐私文本 |

### 2.4 结果与错误

每个用例结果包含：任务 ID、开始/结束时间、成功数、跳过数、失败数、实际字节数、输出位置、警告和可导出报告路径。

错误分为：

| 类别 | 示例 | UI 动作 |
|---|---|---|
| 输入错误 | 路径不存在、格式不匹配 | 指向输入，可立即修正 |
| 权限错误 | 访问被拒绝、文件占用 | 显示路径和建议，不自动提权 |
| 安全拒绝 | 路径穿越、脚本、压缩炸弹 | 明确说明已阻止，不提供忽略安全检查 |
| 资源错误 | 内存不足、磁盘不足 | 显示所需/可用量和释放建议 |
| 运行时错误 | 解码器、模型、系统 API 错误 | 用户摘要 + 可展开技术详情 |
| 取消 | 用户取消、窗口关闭 | 显示取消和已完成范围 |

技术错误要映射为稳定错误码。日志记录错误码、阶段、耗时和脱敏路径，不记录文件正文、密码、令牌、请求正文或模型输入。

### 2.5 设置合同

| 设置 | 默认值 | 范围/行为 |
|---|---|---|
| 主题 | 跟随系统 | 浅色/深色/跟随系统 |
| 语言 | 简体中文 | 首版至少简体中文，键名可本地化 |
| 最近文件 | 开启 | 只存路径和元数据，可清空 |
| 日志级别 | 信息 | 调试日志需用户显式开启 |
| 缓存上限 | 1GiB | 达上限优先清理已完成临时任务 |
| 模型目录 | `%LOCALAPPDATA%\Vibekits\Models` | 可迁移，迁移前校验空间 |
| 解压安全限制 | 开启 | 不提供全局关闭入口 |
| 清理白名单 | 空 | 路径规范化、去重、持久化 |

设置文件损坏时备份原文件、恢复默认并提示；不得因设置损坏阻止应用启动。

## 3. T1 解压缩实现合同

### 3.1 格式能力

| 格式 | 识别 | 列表 | 解压 | 创建 | 备注 |
|---|---:|---:|---:|---:|---|
| ZIP | 是 | 是 | 是 | 是 | 支持加密提示，不破解密码 |
| 7z | 是 | 是 | 是 | 是 | 创建能力以实际库能力验证 |
| RAR | 是 | 是 | 是 | 否 | 只读/解压 |
| TAR | 是 | 是 | 是 | 是 | 保留相对路径 |
| GZ/BZ2/XZ/ZST | 是 | 是 | 是 | 仅 TAR.GZ | 单流格式显示实际文件名 |
| TGZ/TBZ2/TXZ | 是 | 是 | 是 | 仅 TAR.GZ | 按组合格式处理 |
| ISO | 是 | 是 | 是 | 否 | 只读/提取 |

格式先看文件头，再结合后缀；后缀与内容不一致时显示实际识别格式。

### 3.2 打开阶段

1. 获取只读文件句柄并记录初始文件身份、大小和修改时间。
2. 探测格式，失败时返回“不是受支持压缩包”。
3. 枚举条目并生成规范化相对路径。
4. 计算文件数、目录数、已知展开大小和未知大小条目数。
5. 执行安全预检，危险条目标记并禁止选择。
6. 生成虚拟树索引，先返回首批条目，后台继续枚举。

条目数据至少包含：原始路径、规范化路径、类型、原始大小、压缩大小、修改时间、加密标志、链接目标和安全状态。

### 3.3 解压计划

执行前生成不可变计划，包含：源文件身份、已选条目、目标根目录、冲突策略、安全限制和预估空间。开始写入前重新检查源身份及目标可用空间。

安全限制默认值：

| 限制 | 默认值 | 行为 |
|---|---:|---|
| 最大条目数 | 100,000 | 超过时拒绝自动展开，允许仅查看摘要 |
| 单文件展开大小 | 20GiB | 超过时单项拒绝 |
| 总展开大小 | 可用空间的 80% | 超过时阻止开始 |
| 异常压缩比 | 1,000:1 | 警告并要求再次确认；测试样本可直接拒绝 |
| 路径长度 | Windows 可安全创建范围 | 不静默截断 |

所有输出先写入同目录临时文件，单个文件完成并校验写入字节后原子改名。任何规范化后逃出目标根目录的路径必须拒绝。

### 3.4 创建阶段

1. 收集来源并构建相对路径计划；
2. 检测循环链接、不可读文件和重复目标路径；
3. 展示总文件数、已知大小和输出位置；
4. 写入 `.part` 文件；
5. 完成后重新打开并枚举；
6. 校验条目数量、路径和未压缩大小后原子改名。

创建报告记录成功、跳过和失败来源，不记录密码。输出失败不得覆盖已有有效压缩包。

### 3.5 交付物与完成定义

- 格式探测器、条目枚举器、解压计划器、创建计划器；
- 路径安全和空间检查；
- 四种冲突策略；
- 取消、部分成功和报告；
- 正常/损坏/加密/穿越/压缩炸弹夹具；
- `ARC-001`～`ARC-008` 与 `UI-T1-01`～`UI-T1-05` 全部具备证据。

## 4. T2 Windows 清理实现合同

### 4.1 扫描器清单

扫描器只生成候选项，不删除文件。目录不存在时返回“未安装/无数据”，不算错误。

| 扫描器 | 典型位置 | 默认选择 | 删除策略 |
|---|---|---:|---|
| 用户临时文件 | `%TEMP%` | 超过 24 小时且未占用 | 回收站优先 |
| Windows 临时文件 | `%WINDIR%\Temp` | 否 | 仅当前权限可访问项 |
| 回收站 | Windows Shell API | 否 | 系统清空动作，二次确认 |
| Edge 缓存 | `%LOCALAPPDATA%\Microsoft\Edge\User Data\*\Cache*` | 是 | 仅缓存，不碰 Cookie/登录数据 |
| Chrome 缓存 | `%LOCALAPPDATA%\Google\Chrome\User Data\*\Cache*` | 是 | 同上 |
| Firefox 缓存 | `%LOCALAPPDATA%\Mozilla\Firefox\Profiles\*\cache2` | 是 | 同上 |
| 崩溃转储 | `%LOCALAPPDATA%\CrashDumps` 等用户可访问目录 | 是 | 回收站优先 |
| NuGet | `%USERPROFILE%\.nuget\packages` | 否 | 标明将触发重新下载 |
| npm/pnpm/Yarn | 各工具实际配置返回的缓存目录 | 否 | 不凭猜测删除目录 |
| Gradle/Maven | 用户缓存目录 | 否 | 仅可再生成缓存，不碰配置 |
| pip | `pip cache dir` 可验证目录 | 否 | 不碰虚拟环境和 site-packages |
| 下载建议 | 用户 Downloads Known Folder | 永不选择 | 只建议，不自动删除 |
| 插件盘点 | VS Code、Visual Studio、JetBrains 已登记插件 | 永不选择 | 打开对应管理器或显式卸载 |
| 空目录 | 用户选定根目录 | 否 | 只删除确认后仍为空的目录 |

开发缓存路径优先调用工具自身查询命令或配置 API；工具不存在、命令失败或路径不可信时只报告，不扫描推测路径。

### 4.2 候选项

每项包含：规范化路径、文件身份、类别、字节数、最后修改时间、风险等级、发现依据、建议动作、默认选择、白名单命中和占用状态。

不得读取文件正文来判断是否可删除。目录大小可在后台增量计算；未知时显示“计算中”，不得先显示 0B。

### 4.3 清理阶段

1. 根据用户最终选择生成计划；
2. 再次应用白名单并重取文件身份；
3. 发现路径被替换、大小变化或类型变化时跳过；
4. 普通项调用 Windows Shell 回收站能力；
5. 不能进入回收站的项进入永久删除待确认组；
6. 逐项执行并记录实际成功字节数；
7. 最终重新扫描所选范围，生成报告。

符号链接/联接点只处理链接本身，不沿链接遍历到其他目录。任何扫描器都不得请求静默管理员提权。

### 4.4 插件与下载

- 插件盘点显示产品、插件 ID、版本、安装位置和可得的最后使用线索。
- 卸载优先调用产品官方 CLI 或打开产品管理器；不得直接删除插件目录冒充卸载。
- 下载建议按大文件、重复候选和长期未使用分组；用户必须逐项选择。
- 重复文件需先比较大小，再计算哈希；只把哈希相同文件列为重复。

### 4.5 交付物与完成定义

- 扫描器注册表、候选聚合器、白名单、风险策略；
- 回收站删除器、永久删除确认、报告；
- 插件盘点和下载建议，不做隐式删除；
- 只操作沙箱的自动测试；
- `CLN-001`～`CLN-009` 与 `UI-T2-01`～`UI-T2-05` 全部具备证据。

## 5. T3 文档阅读实现合同

### 5.1 格式路由

| 查看器 | 后缀 | 识别依据 |
|---|---|---|
| 文本 | `txt log ini cfg conf properties yaml yml toml diff patch tex latex` | 后缀 + 文本编码探测 |
| Markdown | `md markdown` | 后缀 + Markdown MIME |
| 分隔表格 | `csv tsv` | 后缀 + MIME；允许手动分隔符 |
| 结构化 | `json xml` | 后缀 + 文件头/根结构 |
| 安全 Web | `html htm` | 后缀 + HTML 内容特征 |
| EPUB | `epub` | ZIP + mimetype/container/OPF |
| SVG | `svg svgz` | XML/SVG 根元素；SVGZ 先受限解压 |
| Binary | `bin` | 明确后缀；未知格式可手动选择 |

路由优先读取文件名和受控 MIME，再做轻量文件头确认。未知 `application/octet-stream` 不自动当文本；由用户选择文本或 Hex。

### 5.2 文件会话

打开会话保存：文件身份、路径、大小、修改时间、识别格式、编码、索引状态、阅读位置、搜索状态和临时资源。会话关闭后释放句柄；最近文件只保存路径和最后打开元数据。

当源文件在阅读期间变化时：

- 未索引区域停止继续读取；
- 页面显示“文件已变化”；
- 提供重新加载，不混合新旧内容；
- 不自动覆盖当前选择和搜索结果。

### 5.3 文本与编码

编码探测顺序：BOM → 严格 UTF-8 → GB18030/GBK → Big5 → 用户选择。自动结果低置信度时显示编码选择，不用替换字符伪装成功。

行索引使用 64 位偏移。初始只扫描首个窗口并显示，后台以固定块继续建立索引。超长行按显示片段处理，但复制和搜索必须基于原始字节范围。

日志着色只改变显示，不改变文本；至少识别 `ERROR`、`WARN`、`INFO`、`DEBUG`、`TRACE`，无法识别时使用普通文本色。

### 5.4 Markdown、CSV、JSON、XML

- Markdown 使用 CommonMark/GFM 解析器；原始 HTML 默认转义或白名单清洗。
- 本地图片仅允许文档所在目录及其子目录，禁止 `..` 逃逸、UNC、网络和 `file:` 任意访问。
- CSV/TSV 解析逻辑记录，支持引号、双引号转义、CRLF/LF 和字段内换行。
- CSV 默认首行作为表头，可关闭；超大单元格显示截断标记并允许复制完整值。
- JSON 使用流式严格解析，最大深度 128；64MiB 内提供格式化树，超限进入索引源码。
- XML 禁用 DTD、外部实体和 XInclude，最大深度 128；遵守 XML 声明编码。
- JSON/XML 解析失败显示行列/字节位置并进入只读源码，不丢失原始内容。

### 5.5 HTML、EPUB、SVG

安全渲染统一要求：JavaScript 关闭、网络拦截、下载关闭、新窗口关闭、文件访问关闭、表单提交关闭、导航拦截。

HTML 先经 DOM 白名单清洗。允许基础文本、表格、图片和样式子集；删除脚本、事件属性、iframe、object、embed、base、刷新跳转和危险 URL scheme。

EPUB 限制：

| 项目 | 限制 |
|---|---:|
| EPUB 文件 | 128MiB |
| 条目数量 | 5,000 |
| 单条目展开 | 32MiB |
| 总展开 | 256MiB |
| 单章文本 | 8MiB |

EPUB 规范化所有 ZIP 路径，拒绝根目录逃逸、未知条目大小、DRM/encryption 和超限。资源通过虚拟本地域提供，不能访问公网。

SVG/SVGZ 解压后最大 8MiB。仅允许安全 SVG 元素和属性；脚本、外部图像、外部字体、动画事件和链接跳转受阻。

### 5.6 二进制查看器

- 使用 64 位偏移和固定窗口缓存，默认窗口 1MiB，可按内存压力回收。
- 每行支持 8/16/32 字节；偏移支持十六/十进制显示。
- 搜索支持 Hex 字节序列、ASCII 和 UTF-8 文本，跨窗口保留 `patternLength - 1` 重叠。
- 空搜索、奇数位 Hex、非法字符和超长模式在输入区阻止。
- 选择解释支持有/无符号 8/16/32/64 位整数、float32、float64 和大小端。
- Magic Number 只提示，不自动转入其他解析器。

### 5.7 容量与性能

| 类型 | 正常模式 | 超限行为 |
|---|---:|---|
| 文本/日志 | 无文件硬上限 | 分块索引 |
| CSV/TSV | 64MiB 结构模式 | 询问进入源码/分块预览 |
| JSON/XML | 64MiB 结构模式 | 索引源码 |
| HTML | 16MiB | 拒绝渲染，可选文本查看 |
| SVG/SVGZ | 8MiB 展开后 | 拒绝渲染，可选 Hex |
| EPUB | 见 EPUB 限制 | 受控拒绝 |
| BIN | 无文件硬上限 | 固定窗口随机读取 |

### 5.8 交付物与完成定义

- 25 后缀路由、未知格式选择器、编码探测和手动切换；
- 大文本索引、虚拟表格、结构树、安全 Web、EPUB、SVG、Hex 查看器；
- 查找、复制、取消、源变化和资源释放；
- 正常/损坏/攻击/大文件夹具；
- `DOC-001`～`DOC-305` 与 `UI-T3-01`～`UI-T3-07` 全部具备证据。

| 网络开发 | HTTP | 方法、URL、头、正文、超时、响应 |
| 网络开发 | URL 分解 | scheme/host/port/path/query/fragment |
| 网络开发 | IP/CIDR | 网络、广播、范围、掩码 |
| 网络开发 | DNS | A/AAAA/CNAME/MX/TXT 等查询 |
| 网络开发 | TCP 端口 | 主机、端口、超时、耗时 |
| 文件工具 | 文件哈希 | 多文件、进度、复制哈希 |
| 文件工具 | 批量重命名 | 查找替换、前后缀、序号、大小写、预览 |
| 文件工具 | 重复文件 | 大小预筛、SHA-256 确认、只建议 |

### 6.2 通用转换合同

- 输入变化不自动联网；纯转换可选择自动执行，但大输入使用显式执行。
- 每次运行产生结果或结构化错误，错误不清空输入和上次有效结果。
- 文本编码默认 UTF-8；涉及字节时明确显示编码。
- “交换”只有在输入输出类型兼容时启用。
- 保存前显示目标路径和编码，不静默覆盖。

### 6.3 网络合同

- HTTP、DNS 和端口工具只有点击执行后联网。
- 默认连接超时 10 秒、总超时 30 秒，可在 1～300 秒内调整。
- HTTP 重定向最多 10 次；跨主机重定向不自动携带 `Authorization`、Cookie 等敏感头。
- 响应正文默认最多预览 10MiB，超限流式保存或截断并明确标记。
- TLS 错误不得提供“全局忽略证书”设置。
- 历史记录默认排除授权头、Cookie、请求正文和带敏感查询参数的完整 URL。

### 6.4 文件工具合同

批量重命名先生成计划，检查目标重名、非法名称、保留名、路径长度和大小写冲突。执行过程中失败时停止后续相关操作并保留可恢复映射报告。

重复文件只根据完整文件哈希确认；默认不提供一键删除，用户选择后仍走清理模块的安全删除器。

### 6.5 交付物与完成定义

- 表中所有工具、离线帮助、输入校验和错误定位；
- HTTP 安全重定向、超时、取消；
- 批量重命名计划和重复文件确认；
- 标准测试向量和非法输入向量；
- `DEV-001`～`DEV-007` 与 `UI-T4-01`～`UI-T4-05` 全部具备证据。

## 7. T5 本地模型实现合同

### 7.1 模型清单

每个模型项必须包含：稳定 ID、能力、名称、语言、版本、运行时、精度/量化、下载大小、展开大小、来源 URL、项目主页、许可证、SHA-256、最低内存、推荐线程数和输入约束。

Windows V1 的单个可下载模型包目标不超过 100MiB；超过时不得进入默认精选列表。模型不随应用静默下载。

### 7.2 生命周期

```text
notInstalled -> downloading -> verifying -> installed -> loading -> loaded
                       |             |           |           |-> failed
                       |-> cancelled |-> invalid |-> failed
loaded -> running -> loaded -> unloading -> installed
```

- 下载使用 `.part`，支持取消和重试；校验成功后原子改名。
- 导入模型同样执行清单、许可证和哈希检查；未知模型标记为“用户导入”。
- 默认同一时间只加载一个大型模型；切换前释放当前会话。
- 推理线程数默认不超过逻辑核心数减一，UI 始终保留响应能力。
- 释放模型后销毁运行时会话、输入缓存和输出缓存，但不删除模型文件。

### 7.3 OCR

输入支持 PNG/JPEG/BMP，先校验像素数和内存预算。预处理、检测、方向分类和识别阶段分别报告进度。输出包含文本块、置信度和坐标；低置信度不隐去，只标注。

### 7.4 ASR

文件输入至少支持 PCM WAV；其他格式可通过受控音频解码层转换。麦克风必须显示录音状态和时长。长音频分块推理，输出分段时间戳；取消后保留已确认分段并标记未完成。

### 7.5 TTS

输入限制和支持字符在运行前校验。输出固定为有效 WAV，播放器和保存使用同一生成文件。声音模型、语速和采样率写入导出元数据或报告，不写入用户文本日志。

### 7.6 资源预算

| 项目 | 默认策略 |
|---|---|
| 并行模型会话 | 1 |
| 推理线程 | `max(1, logicalCores - 1)`，可设置上限 |
| 单次输入内存 | 预估后确认，超过预算拒绝 |
| 结果缓存 | 当前会话；用户保存后才持久化 |
| 下载临时文件 | 失败可重试，用户取消可选择删除 |
| 网络 | 仅模型下载，推理全离线 |

### 7.7 交付物与完成定义

- 版本化模型清单、下载/导入/校验/删除；
- 单会话资源管理和内存可见性；
- OCR、ASR、TTS 完整工作区及测试小模型；
- 损坏、错误哈希、超内存和非法输入测试；
- `AI-001`～`AI-009` 与 `UI-T5-01`～`UI-T5-05` 全部具备证据。

## 8. 数据库与持久化

数据库至少包含逻辑数据集：设置版本、最近文件、最近压缩包、任务摘要、清理报告、工具收藏/最近使用、模型清单和已安装模型。

要求：

1. 数据库迁移必须有版本号和回滚备份；
2. 不保存文档正文、开发工具敏感输入、HTTP 密钥或模型输入；
3. 最近路径失效时保留可移除提示，不反复弹错；
4. 用户清除历史后对应记录不可继续出现在 UI；
5. 卸载不删除外部用户输出，应用数据由卸载策略明确说明。

## 9. 第三方组件准入

引入组件前记录：项目地址、固定版本、许可证、是否修改、发布产物包含方式、已知 CVE 和升级负责人。

MIT、BSD、Apache 组件按许可证保留通知。GPL/AGPL 组件不得仅因“开源”直接嵌入；如确需使用，必须先完成许可证影响评审。模型许可证与代码许可证分开记录。
