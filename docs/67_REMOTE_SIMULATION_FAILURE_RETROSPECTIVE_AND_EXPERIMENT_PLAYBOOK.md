# VibeKits 远程仿真失败复盘与唯一实验手册

> 更新时间：2026-09-16  
> 当前实验候选：`1.9.0-dev.216+2216`  
> 目的：把 dev.164～dev.216 的反复失败固化为可执行规则，后续禁止靠猜测、重复点击或更换路线碰运气。

## 1. 不再变化的目标

远程仿真与 Harness、远程桌面是三个彼此独立的功能。目标设备只需安装 VibeKits、主动打开远程仿真并完成一次授权；之后控制端只凭 6～16 位统一设备 ID，即可通过内置 P2P/中继静默建立工具通道，查询系统与 App 状态、读取日志、传输文件、安装、启动、停止、卸载和验证 App。跨局域网时走中继，不能打开或依赖 RustDesk 远程桌面界面，也不能阻塞 Harness 首屏。

## 2. 为什么几十次实验会反复失败

问题不是一个“网络偶发错误”，而是多类错误被混在一起，并且每次只修当前表象：

- 把桌面控制、协同、远程仿真和 Harness 生命周期耦合，改一处影响多处。
- 本机模拟、固定端口通、100 次启动等替代了真正的异机 ID→P2P/中继→SSH/MCP 业务验收。
- 状态文字基于开关或历史缓存，而不是当前传输和工具探针，形成“显示可连接但实际不可用”。
- 失败后更换端口、换机器、重启、重复配对，却没有先保存首个失败证据并归类。
- 构建、签名、安装目录和运行进程的版本没有冻结，验证过旧 App 或错目录。
- 修复没有立即变成能击穿旧实现的回归测试，后续重构又把旧错误带回来。

## 3. 逐项失败台账

### F01 错把 RustDesk 桌面 UI 当传输入口

- 现象：Windows/Mac 前台反复出现黑屏和“正在连接”对话框，妨碍用户工作。
- 错误判断：认为复用 RustDesk 就必须启动它的远程桌面客户端。
- 根因：产品只需要其 ID、打洞、中继和字节转发技术，不需要桌面会话 UI。
- 修复：VibeKits 内嵌无界面的 tunnel/relay helper；远程仿真只允许后台字节通道。
- 防回归：实验期间若出现任何第三方远程桌面窗口，立即判失败，不再继续用该结果。

### F02 新功能与 Harness 启动耦合

- 现象：Harness 白屏、启动慢、控制台提前退出；远程功能关闭时仍影响主界面。
- 根因：远程状态探测、P2P 初始化和 Harness WebView/进程使用了同一启动链。
- 修复：远程仿真放到高级设置和独立控制器；默认按需初始化；Harness 只订阅已生成的状态摘要。
- 防回归：远程功能关闭、网络断开、helper 缺失三种条件下，Harness 冷启动和工作流必须与基线一致。

### F03 设置页面不可滚动、底部按钮被挡

- 现象：高级设置内容超出窗口，开关与保存按钮无法点击。
- 根因：固定高度对话框叠加非滚动 Column，未考虑小窗口、PAD 和字体缩放。
- 修复：主体滚动、底部操作栏固定、安全区与最小尺寸约束；本机 ID 前置，说明改为悬停提示。
- 防回归：最小支持窗口、PAD 单屏、125%/150% 缩放均需完成滚动与每个按钮点击。

### F04 固定端口被通用隧道权限拒绝

- 现象：连接刚发起即失败，或远端端口没有监听。
- 根因：将远程仿真的受管端口套入通用用户自定义端口校验，内部固定端口被拒绝。
- 修复：为已签名、已授权的 simulator scope 建立专用受管端口白名单；其他端口仍走原安全策略。
- 防回归：正向允许专用回环端口；负向拒绝越界端口。

### F05 等待不存在的桌面 Connection Manager

- 现象：目标已打开仿真，但控制端一直等连接管理器或报端点未就绪。
- 根因：残留了远程桌面会话依赖，目标端工具服务本应可独立接受隧道。
- 修复：远程仿真开关直接管理工具端点和授权，不依赖桌面会话。
- 防回归：不启动 RustDesk UI，也必须完成 ID→工具调用。

### F06 helper 提前报告“监听完成”

- 现象：UI 显示可连接，实际本地端口尚未 bind，首个请求失败。
- 根因：状态事件发在 socket 真正监听之前。
- 修复：仅在 bind/listen 成功且健康探针通过后发布 ready。
- 防回归：ready 事件出现后立即连接必须成功；端口占用时不得发 ready。

### F07 按需隧道形成确定性死锁（本次核心根因）

- 现象：`5298938227` 明明在线，dev.212/215 每次约 45 秒超时；重试也一样。
- 错误顺序：`start tunnel → await tunnel ready → 发 HTTP/MCP/SSH 请求`。
- 根因：原生 RustDesk 字节转发是 demand-driven，只有真实本地客户端连接后才会建立远端传输；在发请求前等待 ready，触发条件永远不会发生。
- 修复：`start tunnel → 先启动真实 HTTP/MCP/SSH 请求 → 再等待 ready 与请求共同完成`。控制隧道、MCP 隧道和移动端路径统一。
- 回归：新增 demand-driven 假进程；没有真实请求时永不 ready，旧顺序稳定超时，新顺序必须通过。
- 结果：dev.216 对 `5298938227` 3.8 秒完成 P2P/relay、SSH、MCP，发现 207 个工具。

### F08 更新后旧 relay/旧进程仍占 IPC

- 现象：安装新包后行为仍像旧版，或报 IPC/端口被占。
- 根因：旧 helper、旧 tunnel 或旧 App 进程未退出，验证命中了旧运行实例。
- 修复：升级前确认进程路径与版本；按受管生命周期退出旧 helper；启动后再次核验 PID、路径、版本和 hash。
- 防回归：候选身份冻结表必须包含安装路径、运行路径、PID、版本、构建号和摘要。

### F09 “仿真可连接”是假阳性

- 现象：主界面显示可连接，但远端工具不可调用；关闭开关仍显示异常。
- 根因：文案由配置开关、缓存或中继注册状态驱动，不代表工具链可用。
- 修复：关闭时不显示；打开但无人连接显示“等待连接”；只有传输握手和端点探针都通过才显示“仿真中”。
- 防回归：状态必须带时间戳、peer ID、transport、SSH/MCP 探针结果；过期自动降级。

### F10 协同与仿真状态互相污染

- 现象：关闭协同仍显示“协同连接中”，仿真状态覆盖 Harness 状态。
- 根因：两个功能共享过于粗糙的全局布尔状态。
- 修复：使用独立状态机和独立 scope；主界面只合并展示，不共享生命周期。
- 防回归：协同开/关 × 仿真开/关四象限逐一验证。

### F11 首次配对授权生命周期死锁

- 现象：“确认并记住”后不消失，控制端持续等待；或每次重复授权。
- 根因：授权确认、端点启动、连接完成互相等待，授权记录又没有绑定已验证 peer。
- 修复：授权先形成原子决定，再异步启动端点；记住的是验证后的设备身份和权限 scope，不是临时连接对象。
- 防回归：首次允许、记住后重连、拒绝、撤销、peer 变化五条路径都必须有明确终态。

### F12 短 tunnel 身份未进入连接管理

- 现象：短生命周期命令通道被当成未知连接清理，偶发掉线。
- 根因：受管隧道没有稳定 lease/heartbeat 标识。
- 修复：每条隧道携带 session ID、用途、peer、lease 与心跳；连接管理按 scope 回收。
- 防回归：并发控制/MCP/文件隧道互不误杀，断开后无残留。

### F13 只读工具也被强制走敏感授权查询

- 现象：查询系统或 App 列表也超时，导致误判整机不可仿真。
- 根因：所有工具统一串到高风险授权路径，授权 UI 或状态查询阻塞只读请求。
- 修复：只读诊断使用已建立会话的最小权限路径；安装、卸载、写文件等写操作单独授权和审计。
- 防回归：只读调用不弹窗且有界完成；写操作未授权必须被拒绝。

### F14 SSH known_hosts 路径含空格解析错误

- 现象：隧道已通但 SSH 报参数或主机密钥文件错误。
- 根因：把 SSH 参数拼成字符串，含空格路径被错误拆分。
- 修复：所有进程调用采用参数数组，不使用插值 shell 字符串。
- 防回归：临时目录和用户名包含空格时仍能连接。

### F15 SSH 权限、端口未就绪、磁盘满被混成一个错误

- 现象：统一显示“SSH 失败”，随后盲目重启或重新配对。
- 根因：环境前置条件没有分别探测，错误分类丢失。
- 修复：分别报告系统授权、22 端口、登录凭据、磁盘空间、SFTP 和命令权限。
- 防回归：每个故障注入都必须得到稳定错误码和可执行建议，不得自动换路线掩盖。

### F16 PAD 协议帧前缀不一致

- 现象：PAD 返回 `PAIRING_BAD_REQUEST_FRAME` 或写小游戏时卡死。
- 根因：移动端和桌面端使用了不同的帧边界/前缀与过大的主线程处理。
- 修复：统一协议版本和帧解析；网络、解析和长任务放后台 isolate/线程，UI 只接收节流后的状态。
- 防回归：分片、粘包、空帧、大响应和取消任务均做协议测试与 PAD 真机压力测试。

### F17 隐藏 WebView 拦截左侧按钮

- 现象：侧栏、应用中心等按钮看得见但点击无效。
- 根因：不可见或透明的 WKWebView/平台视图仍占据命中区域。
- 修复：非活动页面真正移出命中树或禁用 pointer；不靠透明度隐藏平台视图。
- 防回归：对每个侧栏按钮做真实命中测试，并检查顶层平台视图 bounds。

### F18 同版本号不代表同一份安装包

- 现象：本机正常、另一台异常；口头确认版本一致仍无法复现。
- 根因：`/Applications` 与 `~/Downloads` 同时存在不同构建；运行进程可能来自非预期目录；版本号相同但字节不同。
- 修复：每次记录实际进程路径、bundle 版本/构建、签名、SHA-256，不再只看 UI 版本。
- 防回归：候选与目标实际运行二进制摘要不一致即停止实验。

### F19 本机 100 次启动不能替代跨机链路

- 现象：Harness 100/100 正常，远程 ID 仿真仍失败。
- 根因：验证维度不同；本机启动覆盖进程生命周期，不覆盖 ID 注册、NAT、中继、隧道触发、远端端点和授权。
- 修复：保留启动压力测试，但远程发布必须另跑至少一台异机真实 ID 的 P2P 和强制中继业务。
- 防回归：不再用本机或 mock 结果宣称“远程仿真通过”。

### F20 通用 timeout 导致死循环重试

- 现象：多次等待 45 秒、切机器、重启、重新授权，没有新增证据。
- 根因：所有阶段共用一个 timeout，未记录最后完成的状态和触发条件。
- 修复：连接阶段拆为 identity、relay registration、local bind、demand trigger、transport、endpoint、SSH/MCP probe，并保留首个失败日志。
- 防回归：相同错误码第二次出现时禁止原样重试；必须先改变一个明确变量或修复代码。

## 5. 后续唯一实验流程

任何人不得跳步，也不得用后一步成功反推前一步成功。

1. **冻结候选**：记录 commit、dirty files、版本/构建、包路径、SHA-256、签名、公证状态、架构、最低系统。
2. **确认目标**：记录设备 ID、目标开关、实际运行 App 路径/PID/版本/摘要；清理同名旧进程和过期隧道。
3. **本机正负控制**：正向验证工具端点；负向关闭端点，确认测试确实会失败。
4. **只连接一次**：静默使用 ID 建立通道；记录各阶段耗时和 transport。禁止打开桌面 UI。
5. **固定验收顺序**：状态探针 → 工具目录 → 只读系统/App/进程 → SSH 命令 → SFTP 上传下载校验 → 经授权安装/启动/停止/卸载 → 断开清理。
6. **传输矩阵**：同局域网 P2P 与跨网/强制 relay 分开跑；二者证据不得互相替代。
7. **失败立即归类**：保存首个失败包、阶段、错误码和日志。相同输入不得无变化重试超过一次。
8. **先写回归再修复**：测试必须能在旧实现上失败、在修复后通过。
9. **重建即新候选**：任何代码、签名、重打包变化都生成新 hash，并重跑受影响门禁。
10. **只报 PASS/BLOCK**：PASS 只对应精确 hash 和已跑矩阵；未跑项必须列为 BLOCK/未覆盖，不说“应该可以”。

## 6. 实验停止条件

出现以下任一情况必须停止原样重试并回到定位：

- 弹出 RustDesk/第三方远程桌面界面；
- UI 显示状态与工具探针矛盾；
- 实际运行包的路径、版本或 SHA 与候选不一致；
- 同一错误码连续出现两次且变量未变化；
- 只能证明本机端口通，不能证明远端业务返回；
- 测试没有负向控制，无法证明它能抓住故障；
- 安装、卸载或写文件没有显式授权和回滚点。
