# 发布质量门禁

Vibekits 不再以“页面存在”或“按钮可点击”作为完成功能。每个功能必须登记成真实用户任务链，并同时具备自动测试、风险边界和可追溯证据。

## 验收层级

1. 领域层：输入边界、失败、取消、超时、并发和敏感信息不落盘。
2. 组件层：真实点击、页面切换、状态恢复、停止与错误提示。
3. 工具桥：Harness 能发现并调用同一个领域服务，权限和真实工具日志可核对。
4. 任务链：从用户目标开始，到可见结果、失败恢复和后续动作结束。
5. 发布包：Release 版本、哈希、自包含运行时、断网降级和进程退出。
6. 实际环境：ADB、串口、远程服务器、数据库和真实系统盘等必须保留实机证据；没有证据只能标记“待实机”，不能写“完成”。

机器清单位于 `tool/release_acceptance_manifest.json`。新增工具时必须同时新增任务链、测试和证据路径，否则清单测试失败。

## 执行

- 快速闭环：`powershell -File tool/run_release_acceptance.ps1 -Tier fast`
- 发布闭环：`powershell -File tool/run_release_acceptance.ps1 -Tier release`

每次执行会在 `build/acceptance` 生成 JSON、Markdown 和逐命令日志，记录退出码、耗时、Release 版本和 SHA-256。报告由命令结果生成，不允许手工把失败改成通过。

## 清理样板链

清理必须按“后台扫描 → 软件/系统占用解释 → 用户确认 → 回收站/安全删除 → 重新扫描 → 本次与累计释放量 → 报告 → Harness 可继续解释”验收。

“合理性”是可解释的启发式判断，不是删除授权：Windows 系统目录的常见逻辑量仅作参考；未知目录、日志和缓存按绝对大小、磁盘比例、来源、年龄和可再生性分级。任何受保护目录都不会因智能体判断而变成可删除。
