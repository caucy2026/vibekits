# Vibekits 实验与闭环路径

版本：0.1
更新日期：2026-08-16

## 1. 统一实验漏斗

每个需求按同一条路径推进，不以“界面出现入口”判定完成。

| 门 | 要回答的问题 | 必须产物 | 失败时处理 |
|---|---|---|---|
| E0 需求与预算 | 用户把什么交给程序，期望最少几步得到什么 | 需求 ID、默认动作、操作预算、危险边界 | 需求不清则不写入口 |
| E1 官方研究 | 可用的标准、上游、许可证和平台限制是什么 | 一手来源、固定版本/提交、许可证、哈希 | 来源或许可证不清则替换方案 |
| E2 失败夹具 | 当前实现在哪些真实输入上失败 | 最小失败文件/向量、预期错误、资源上限 | 先固化复现再开发 |
| E3 领域原型 | 不依赖 UI 能否正确、安全地完成任务 | 纯服务/API、单元测试、取消/释放协议 | 算法不稳不进入 UI |
| E4 体验原型 | 拖入后是否自动进入最佳结果，操作是否够少 | Widget 测试、窄窗测试、键盘流程、空/错/忙状态 | 超预算则重做信息架构 |
| E5 融合与系统入口 | 拖放、选择器、右键/Open With 是否走同一路由 | 路由测试、文件关联/UTI 测试、结果动作 | 孤立功能不得标记完成 |
| E6 边界与安全 | 大文件、损坏、取消、权限、竞态、敏感信息是否受控 | 边界测试、临时文件检查、脱敏检查 | 有数据破坏风险则停止发布 |
| E7 平台 Release | Debug 可用是否也能在目标 Release 真运行 | Windows/macOS 构建、真实夹具、实机记录 | 缺目标平台证据标记部分实现 |
| E8 交付 | 代码、文档、版本、来源和备份是否一致 | 状态/日志/验收、版本、提交、标签、双远端 | 工作树或文档不一致不推送 |

## 2. 体验实验方法

每个工作区至少跑以下任务：

1. **首次用户**：只给一个真实文件，不读说明，能否在 10 秒内看到正确结果。
2. **键盘用户**：打开、查找、执行、复制、保存能否用主流快捷键完成。
3. **窄窗口与缩放**：1024×700，100%/150%/200%，主按钮、错误和结果不溢出。
4. **错误恢复**：输入错误时保留输入和上次有效结果，错误可执行且不暴露堆栈给普通用户。
5. **反复操作**：连续切换文件/工具不残留上一任务状态，不要求重复选择同一输入。
6. **危险操作**：覆盖、删除、数据库写入、Git 写操作和系统配置变更都有预览或确认，可恢复时优先可恢复方式。

记录三项硬指标：拖入到结果的点击数、首个可用结果时间、用户必须理解的同时可见选项数。

## 3. 当前各项实验路径

| 工作项 | 失败基线/真实夹具 | 领域实验 | 体验实验 | 平台/安全出口 |
|---|---|---|---|---|
| 程序员计算器 | 负数、溢出、移位、除零、非法字面量 | Pratt/优先级解析，多位宽转换 | 输入即算，复制任一进制，窄窗不溢出 | Analyze + 单元/Widget + Release |
| SQLite | 空库、多表、BLOB、NULL、中文、10 万行、损坏库、锁定库 | 只读打开、分页、参数化查询、事务写入 | 拖入即显示表；查询一键运行；写入明确模式 | 默认只读、超时/行数限制、临时库测试 |
| 源码/Shell | 无后缀脚本、混合换行、超长行、未知编码、只读文件 | 内容/文件名路由、增量读取、原子保存 | 查找/编辑/保存与主流编辑器一致 | 运行脚本必须确认，参数不经 Shell 拼接 |
| SSH/SFTP | 错主机、拒绝端口、未知/变化主机密钥、大文件中断 | 系统 OpenSSH 能力探测、配置生成、传输/转发进程协议 | 连接资料最少字段，终端/文件/转发同一会话 | 不保存密码，保留主机密钥验证，可取消并清进程 |
| HTTP/API | 超时、重定向环、巨型响应、无效证书、敏感头 | 有界流式请求、响应摘要、脱敏历史 | URL+方法为主，Body/认证按需展开 | 不自动放宽 TLS，不记录令牌，限制响应大小 |
| Git/网络 | 非仓库、冲突、代理错误、DNS/TLS/SSH 失败 | 结构化 Git 调用和分层诊断 | 先解释状态，再给一个安全主操作 | 不做隐式 MITM/hosts 修改；变更可审计可恢复 |
| 图片/OCR | 官方样图、灰度/CMYK/透明/旋转、损坏、超大像素 | 统一 RGB 预处理、ONNX 真推理、结果框 | 拖入先预览，模型可用时自动准备 | 哈希固定模型、内存预算、Windows/macOS 真推理 |
| 压缩 | RAR5、分卷、ISO、ZST、穿越、炸弹、损坏、加密 | 统一列表/计划/暂存/冲突/取消合同 | 拖入即列出，安全摘要和解压为唯一主操作 | 全后端同安全限制，目标空间复核 |
| 清理 | 临时沙箱、旧插件、下载残留、占用/无权限、路径替换 | 扫描原因、不可变快照、回收站、匿名报告 | 先看清“清什么、为什么、多少”，默认只选低风险 | 不扫描/删除项目源码和个人下载；竞态再验证 |

## 4. 自动化证据层级

- L1：纯领域单元测试，覆盖正确和错误向量。
- L2：真实文件/进程/模型集成测试，证明不是模拟结果。
- L3：Widget 测试，覆盖拖入后的默认页、主操作、错误和窄窗。
- L4：平台 Release 构建与系统入口测试。
- L5：目标机人工任务、截图/录屏、性能和操作数记录。

状态规则：L1～L3 通过只能写“代码已实现”；目标平台缺 L4/L5 时必须写“部分实现/未验收”。

## 5. 本轮停止条件

本轮研发只有满足以下条件才进入备份：所有新增代码格式化和 Analyze 通过；全量测试通过；Windows Release 构建通过；需求总账、当前状态、开发日志和第三方来源已同步；研究临时目录和构建日志不进入提交；版本号更新；本地提交/标签和指定云端仓库同步完成。macOS 因当前 Windows 主机无法生成实机证据时，必须保留为明确未完成项，不能用 Windows 测试替代。
