# 全部工具的智能体闭环验收准则

## 闭环定义

一个功能只有同时通过下列层级，才能写成“智能体可用”：

1. `ToolSpec` 描述使用场景、禁用场景和 Harness 工具 ID。
2. 工具进入 Harness 完整目录；若当前不可安全执行，只能进入不可用目录并说明原因，不能暴露空壳。
3. 所有对模型公开的工具都存在本地处理器。
4. 处理器调用真实领域服务，返回结构化结果；失败、拒绝和取消状态彼此分离。
5. 默认写入对应模块的 Harness 工具日志；密码、Key 和正文按隐私策略脱敏。
6. 有代表性成功用例；涉及写入、设备、网络或进程的工具还需拒绝授权、错误参数、取消或恢复用例。
7. 外部硬件和服务必须单独标记真实环境门禁，不得用模拟通过冒充真机通过。

## APP 自检接口

Harness 可调用只读工具 `vibekits.system.capability_check`。

返回协议版本、定义工具数、公开可执行工具数、缺失处理器、不可用工具及原因、风险等级统计和检查时间。

发布硬门禁：`ready == true` 且 `missingHandlers` 必须为空。新增工具如果只登记 Schema、没有执行器，自动测试立即失败。

## 当前自动验收层

| 能力层 | 验收 |
|---|---|
| 官方 Harness 主链 | 本地兼容模型端点真实完成模型请求、Vibekits SHA-256 工具调用、原生授权操作和最终回复 |
| 工具目录 | 每个左侧工具至少有可执行适配器；所有公开工具逐项检查处理器 |
| 高频微工具 | 30/30 逐项通过 Harness 真调用并逐项写入成功日志 |
| 复杂工具 | ADB、SQLite/远程数据库、SSH/SFTP、HTTP、Git、Diff、文件、OCR、音频、资源、代理/虚拟机按领域专项调用 |
| UI/交互 | 五个一级入口、全部开发工具、设置、文档、拖入路由逐项计时和异常检查 |
| 生命周期 | 扫描/搜索/串口/资源探针具备后台、取消或销毁释放测试 |

## 真实环境门禁

以下能力有自动模拟或合同测试，但发布到相应环境前仍必须执行真实门禁：

- ADB 真机语义全链：提供 `VIBEKITS_LIVE_ADB_TARGET`。
- Mihomo 用户 Profile 与真实节点：提供脱敏 Profile 和 Release 路径。
- 内置 Mihomo/QEMU 启停与系统代理恢复：提供 `VIBEKITS_LIVE_RELEASE`。
- 真实系统盘只读扫描：显式启用 `VIBEKITS_REAL_SYSTEM_DRIVE`。
- macOS 签名、公证和多机型 GPU；真实串口硬件；外部 MySQL/MariaDB 服务矩阵。

环境门禁未执行时，报告必须写“环境待验”，不能写“全部真机通过”。
